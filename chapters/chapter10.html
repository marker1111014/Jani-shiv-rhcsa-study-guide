管理邏輯磁區 (LVM)

精通邏輯磁區管理 (LVM) 以實現彈性的儲存空間配置。學習建立與管理實體磁區 (PV)、磁區群組 (VG) 與邏輯磁區 (LV)， 並掌握動態擴充、縮減、建立快照及遷移儲存空間的技巧。

🎯 LVM 簡介

邏輯磁區管理程式 (Logical Volume Manager, LVM) 提供了高度彈性的磁碟管理機制。與傳統磁碟分割不同， LVM 允許您在不中斷服務的情況下調整磁區大小、建立快照，並在實體磁碟之間遷移資料。

LVM 架構

實體磁碟 (/dev/sdb, /dev/sdc)
    ↓
實體磁區 (PV) - pvcreate
    ↓
磁區群組 (VG) - vgcreate (儲存空間集區)
    ↓
邏輯磁區 (LV) - lvcreate (虛擬分割區)
    ↓
檔案系統 (mkfs, mount)

LVM 組成元件

元件 說明 範例
實體磁區 (PV) 供 LVM 使用的實體磁碟或分割區 /dev/sdb1, /dev/sdc
實體延伸區 (PE) 最小儲存配置單位（預設為 4MB） 4MB 區塊
磁區群組 (VG) 由多個 PV 彙整而成的儲存集區 vg_data, rhel
邏輯磁區 (LV) 從 VG 中建立的虛擬分割區 /dev/vg_data/lv_web
邏輯延伸區 (LE) 對應至 LV 的 PE 單位 與 PE 大小相同

LVM 的優勢

  • 彈性調整容量： 支援線上調整磁區大小（擴充 XFS/ext4、縮減 ext4）
  • 快照功能： 建立時間點副本，便於測試或災難復原
  • 等量分割 (Striping)： 將資料分散寫入多顆磁碟以提升效能
  • 鏡像 (Mirroring)： 跨實體磁區提供資料備援與容錯
  • 線上遷移： 在不停機的情況下於磁碟間搬移資料
📘 LVM 與傳統分割區比較

傳統分割區：容量固定、難以調整大小、彈性有限
LVM：可動態調整容量、支援快照、整合儲存集區、更易於管理

💽 實體磁區 (PV)

建立實體磁區

# 將分割區或整顆磁碟初始化為 PV
sudo pvcreate /dev/sdb1
sudo pvcreate /dev/sdc

# 一次初始化多個裝置
sudo pvcreate /dev/sdb1 /dev/sdc /dev/sdd1

# 輸出範例：
  Physical volume "/dev/sdb1" successfully created.

檢視實體磁區

# 列出所有 PV 摘要
sudo pvs

# 輸出範例：
  PV         VG     Fmt  Attr PSize  PFree
  /dev/sda2  rhel   lvm2 a--  19.00g    0 
  /dev/sdb1  vgdata lvm2 a--   5.00g 2.00g

# 顯示詳細資訊
sudo pvdisplay

# 顯示特定 PV 的詳細資訊
sudo pvdisplay /dev/sdb1

# 顯示 PE 與詳細資訊
sudo pvs -v
sudo pvscan

移除實體磁區

# 需先將 PV 從 VG 中移除（若有資料請先執行 pvmove 搬移）
sudo pvremove /dev/sdb1

# 輸出：
  Labels on physical volume "/dev/sdb1" successfully wiped.
💡 PV 最佳實務

建議使用整顆磁碟，或將分割區類型設為 Linux LVM（MBR 使用代碼 8e，GPT 請設定 lvm 旗標）。 建立 PV 前先用 parted 為分割區命名，能讓磁碟用途更加明確。

🗄️ 磁區群組 (VG)

建立磁區群組

# 從單一 PV 建立 VG
sudo vgcreate vg_data /dev/sdb1

# 從多個 PV 建立 VG
sudo vgcreate vg_data /dev/sdb1 /dev/sdc

# 自訂 PE 大小（預設為 4MB）
sudo vgcreate -s 8M vg_data /dev/sdb1

# 輸出：
  Volume group "vg_data" successfully created

檢視磁區群組

# 列出所有 VG
sudo vgs

# 輸出：
  VG      #PV #LV #SN Attr   VSize  VFree
  rhel      1   2   0 wz--n- 19.00g    0 
  vg_data   2   1   0 wz--n-  9.99g 7.00g

# 顯示詳細資訊
sudo vgdisplay

# 顯示特定 VG 資訊
sudo vgdisplay vg_data

# 顯示 VG 內包含的 PV 名稱
sudo vgs -o +pv_name

擴充磁區群組

# 將新的 PV 加入現有 VG
sudo vgextend vg_data /dev/sdd1

# 輸出：
  Volume group "vg_data" successfully extended

# 驗證結果
sudo vgs vg_data

縮減磁區群組

# 從 VG 移除 PV（該 PV 必須為空，或先使用 pvmove 搬移資料）
sudo vgreduce vg_data /dev/sdd1

# 移除遺失或故障的 PV
sudo vgreduce --removemissing vg_data

移除磁區群組

# 移除 VG（必須先刪除其下所有 LV）
sudo vgremove vg_data

# 輸出：
  Volume group "vg_data" successfully removed

重新命名磁區群組

# 重新命名 VG
sudo vgrename vg_data vg_backup

# 或透過裝置路徑指定
sudo vgrename /dev/vg_data vg_backup

📦 邏輯磁區 (LV)

建立邏輯磁區

# 建立 2GB 的 LV
sudo lvcreate -L 2G -n lv_web vg_data

# 使用 VG 內所有剩餘可用空間建立 LV
sudo lvcreate -l 100%FREE -n lv_backup vg_data

# 依指定 PE 數量建立 LV
sudo lvcreate -l 512 -n lv_logs vg_data

# 輸出：
  Logical volume "lv_web" created.

LV 命名路徑

# 存取 LV 的裝置路徑格式：
/dev/VG_NAME/LV_NAME
/dev/vg_data/lv_web

# 或透過 device mapper 路徑：
/dev/mapper/VG_NAME-LV_NAME
/dev/mapper/vg_data-lv_web

檢視邏輯磁區

# 列出所有 LV
sudo lvs

# 輸出：
  LV      VG      Attr       LSize  Pool Origin Data%
  lv_web  vg_data -wi-a-----  2.00g                   
  root    rhel    -wi-ao---- 17.00g                   
  swap    rhel    -wi-ao----  2.00g                   

# 顯示詳細資訊
sudo lvdisplay

# 顯示特定 LV 資訊
sudo lvdisplay /dev/vg_data/lv_web

# 顯示所有屬性與對應裝置
sudo lvs -a -o +devices

在 LV 上建立檔案系統

# 建立 XFS 檔案系統
sudo mkfs.xfs /dev/vg_data/lv_web

# 建立 ext4 檔案系統
sudo mkfs.ext4 /dev/vg_data/lv_logs

# 掛載使用
sudo mkdir /web
sudo mount /dev/vg_data/lv_web /web

# 驗證掛載結果
df -h /web

移除邏輯磁區

# 務必先卸載
sudo umount /web

# 移除 LV
sudo lvremove /dev/vg_data/lv_web

# 確認提示：
Do you really want to remove active logical volume vg_data/lv_web? [y/n]: y
  Logical volume "lv_web" successfully removed

操作步驟：完整 LVM 建置流程

  1. 建立並標記為 LVM 類型的分割區： 
    sudo parted /dev/sdb mkpart primary 1MiB 5GiB
sudo parted /dev/sdb set 1 lvm on
  2. 建立實體磁區 (PV)： 
    sudo pvcreate /dev/sdb1
  3. 建立磁區群組 (VG)： 
    sudo vgcreate vg_data /dev/sdb1
  4. 建立邏輯磁區 (LV，大小 2GB)： 
    sudo lvcreate -L 2G -n lv_web vg_data
  5. 建立檔案系統： 
    sudo mkfs.xfs /dev/vg_data/lv_web
  6. 設定永久掛載： 
    sudo mkdir /web
echo "/dev/vg_data/lv_web /web xfs defaults 0 2" | sudo tee -a /etc/fstab
sudo mount -a
  7. 驗證設定結果： 
    df -h /web
sudo lvs
sudo vgs

📈 擴充儲存空間

擴充邏輯磁區

# 增加指定容量
sudo lvextend -L +1G /dev/vg_data/lv_web

# 擴充至指定的總容量
sudo lvextend -L 5G /dev/vg_data/lv_web

# 使用所有剩餘可用空間進行擴充
sudo lvextend -l +100%FREE /dev/vg_data/lv_web

# 單一指令同時擴充 LV 與調整檔案系統大小
sudo lvextend -r -L +1G /dev/vg_data/lv_web

# 輸出：
  Size of logical volume vg_data/lv_web changed from 2.00 GiB to 3.00 GiB.
  Logical volume vg_data/lv_web successfully resized.

擴充檔案系統

# 擴充 LV 後，接著擴充檔案系統：

# XFS（必須處於已掛載狀態）
sudo xfs_growfs /web

# ext4（掛載或未掛載狀態皆可）
sudo resize2fs /dev/vg_data/lv_web

# 擴充後檢查檔案系統容量
df -h /web

擴充磁區群組

# 若 VG 空間不足，請新增更多 PV：

# 建立新的 PV
sudo pvcreate /dev/sdc1

# 擴充 VG
sudo vgextend vg_data /dev/sdc1

# 接著即可擴充 LV 與檔案系統
sudo lvextend -L +5G /dev/vg_data/lv_web
sudo xfs_growfs /web

操作步驟：擴充 LV 與檔案系統

  1. 檢查目前容量： 
    df -h /web
sudo lvs /dev/vg_data/lv_web
  2. 檢查 VG 剩餘可用空間： 
    sudo vgs vg_data
  3. 將 LV 擴充 2GB： 
    sudo lvextend -L +2G /dev/vg_data/lv_web
  4. 擴充檔案系統 (XFS)： 
    sudo xfs_growfs /web
  5. 驗證擴充結果： 
    df -h /web
sudo lvs
💡 快速擴充技巧

使用 lvextend -r 可在擴充 LV 後自動一併調整檔案系統大小。 此參數同時適用於 XFS 與 ext4：sudo lvextend -r -L +2G /dev/vg_data/lv_web

📉 縮減儲存空間

⚠️ 嚴重警告

XFS 無法縮減！ 僅有 ext4 支援縮小容量。縮減前務必先備份資料， 並先卸載檔案系統。若操作順序錯誤將導致嚴重資料遺失！

縮減 ext4 邏輯磁區

# 重要：務必先卸載！
sudo umount /backup

# 檢查檔案系統完整性
sudo e2fsck -f /dev/vg_data/lv_backup

# 先縮減檔案系統（縮減至 3GB）
sudo resize2fs /dev/vg_data/lv_backup 3G

# 再縮減 LV（縮減至 3GB）
sudo lvreduce -L 3G /dev/vg_data/lv_backup

# 警告提示：
  WARNING: Reducing active logical volume to 3.00 GiB.
  THIS MAY DESTROY YOUR DATA (filesystem etc.)
Do you really want to reduce vg_data/lv_backup? [y/n]: y

# 重新掛載
sudo mount /dev/vg_data/lv_backup /backup

# 驗證結果
df -h /backup
sudo lvs

安全縮減步驟

  1. 備份資料（極為重要！）
  2. 卸載檔案系統
  3. 檢查檔案系統完整性 (e2fsck -f)
  4. 先縮減檔案系統容量 (resize2fs)
  5. 再將 LV 縮減至相同或更大的容量
  6. 重新掛載並驗證

替代方案：使用 lvreduce 搭配 -r

# 同時縮減 LV 與檔案系統（僅限 ext4）
sudo umount /backup
sudo lvreduce -r -L 3G /dev/vg_data/lv_backup

# 此指令會自動依序執行：
# 1. 檢查檔案系統
# 2. 縮減檔案系統
# 3. 縮減 LV
📘 為何 XFS 無法縮減

XFS 的設計專注於高效能與擴展性，而不支援縮小容量。若您必須縮減 XFS 磁區， 只能採用：備份資料 → 刪除原有 LV → 建立較小的 LV → 還原資料。

📸 LVM 快照

快照可提供邏輯磁區在特定時間點的狀態複本，非常適合在系統變更前進行備份、測試或復原 (Rollback)。

建立快照

# 建立快照（配置原始 LV 容量的 20% 以記錄變更資料）
sudo lvcreate -L 1G -s -n lv_web_snap /dev/vg_data/lv_web

# 或使用百分比指定大小
sudo lvcreate -l 20%ORIGIN -s -n lv_web_snap /dev/vg_data/lv_web

# 輸出：
  Logical volume "lv_web_snap" created.

檢視快照

# 列出快照與原始磁區
sudo lvs

# 輸出會顯示快照及其 Origin 來源：
  LV           VG      Attr       LSize  Pool Origin Data%
  lv_web       vg_data owi-aos---  5.00g                   
  lv_web_snap  vg_data swi-a-s---  1.00g      lv_web 0.02

# 檢視快照詳細資訊
sudo lvdisplay /dev/vg_data/lv_web_snap

掛載快照

# 以唯讀模式掛載快照進行備份
sudo mkdir /snapshot
sudo mount -o ro /dev/vg_data/lv_web_snap /snapshot

# 從快照進行資料備份
sudo tar -czf /backup/web_backup.tar.gz -C /snapshot .

# 卸載快照
sudo umount /snapshot

從快照還原

# 卸載原始 LV
sudo umount /web

# 將快照合併回原始 LV（復原變更內容）
sudo lvconvert --merge /dev/vg_data/lv_web_snap

# 重新掛載（於重開機或重新啟用 LV 後）
sudo mount /dev/vg_data/lv_web /web

移除快照

# 移除快照（不影響原始 LV）
sudo lvremove /dev/vg_data/lv_web_snap

# 確認提示：
Do you really want to remove active logical volume vg_data/lv_web_snap? [y/n]: y

操作步驟：使用快照安全更新系統

  1. 在進行系統更新前建立快照： 
    sudo lvcreate -L 2G -s -n root_snap /dev/rhel/root
  2. 執行系統更新： 
    sudo dnf update -y
  3. 測試系統狀態。若發生問題，執行復原： 
    # 開機進入救援模式或單人模式
sudo umount /
sudo lvconvert --merge /dev/rhel/root_snap
sudo reboot
  4. 若更新成功無誤，移除快照以釋放空間： 
    sudo lvremove /dev/rhel/root_snap

快照最佳實務

  • 針對一般變更，建議將快照大小設為原始 LV 的 20-30%
  • 定期監控快照空間使用率（lvs 指令中的 Data% 欄位）
  • 使用完畢後請即時移除快照以釋放空間
  • 若快照空間寫滿，快照將會失效並被系統自動移除
  • 快照僅適用於短期備份與測試，不可作為長期儲存用途
⚠️ 快照空間注意事項

如果快照空間耗盡（Data% 達到 100%），快照將會失效並被自動刪除。 請持續使用 lvs 監控，必要時可即時擴充快照空間： sudo lvextend -L +500M /dev/vg_data/lv_web_snap

📝 練習題

第 1 題：建立 LVM 儲存空間的正確順序為何？

  • A) LV → VG → PV → 檔案系統
  • B) PV → VG → LV → 檔案系統
  • C) VG → PV → LV → 檔案系統
  • D) 檔案系統 → LV → VG → PV
解答：B) PV → VG → LV → 檔案系統
正確流程為：1) pvcreate（實體磁區）、2) vgcreate（磁區群組）、3) lvcreate（邏輯磁區）、4) mkfs（建立檔案系統）、5) mount（掛載使用）。 記憶口訣：實體磁碟 → 資源集區 → 虛擬分割區 → 格式化 → 掛載使用。

第 2 題：哪一種檔案系統僅支援擴充容量，而不支援縮減容量？

  • A) ext4
  • B) ext3
  • C) XFS
  • D) Btrfs
解答：C) XFS
XFS 僅支援線上擴充 (xfs_growfs)，無法進行縮減。若需要縮減容量功能請選擇 ext4。 若要「縮小」XFS，必須先備份資料 → 刪除磁區 → 建立較小的磁區 → 還原資料。

第 3 題：哪一個指令可以單一步驟同時擴充 LV 與檔案系統？

  • A) lvextend -L +2G /dev/vg/lv
  • B) lvextend -r -L +2G /dev/vg/lv
  • C) lvresize -L +2G /dev/vg/lv
  • D) vgextend -L +2G /dev/vg
解答：B) lvextend -r -L +2G /dev/vg/lv
-r（或 --resizefs）參數會在擴充 LV 後自動調整檔案系統大小。 若未加上 -r，則必須在執行 lvextend 後手動執行 xfs_growfs 或 resize2fs。

第 4 題：當 LVM 快照空間用盡時會發生什麼事？

  • A) 系統當機
  • B) 快照變為唯讀狀態
  • C) 快照會失效並被系統自動移除
  • D) 原始 LV 資料毀損
解答：C) 快照會失效並被系統自動移除
當快照空間寫滿時（Data% = 100%），快照將立即失效並由 LVM 自動移除，但不會影響原始 LV 的資料。 請使用 lvs 持續監控，並在需要時擴充快照：lvextend -L +500M /dev/vg/snap

第 5 題：如何在 'vg_app' 磁區群組中建立名為 'lv_data'、大小為 3GB 的邏輯磁區？

  • A) lvcreate -n lv_data -L 3G vg_app
  • B) lvcreate -L 3G -n lv_data vg_app
  • C) A 與 B 皆正確
  • D) vgcreate -L 3G lv_data vg_app
解答：C) A 與 B 皆正確
這兩個指令皆完全有效。參數的先後順序不影響執行結果：lvcreate -L SIZE -n NAME VG 或 lvcreate -n NAME -L SIZE VG 皆可， 但 VG 名稱必須放在最後。請留意 -l 是指定 PE 數量，-L 才是指定容量大小。

第 6 題：在縮減 ext4 邏輯磁區之前，必須先執行什麼操作？

  • A) 什麼都不用做，直接執行 lvreduce
  • B) 卸載、檢查檔案系統，並先縮減檔案系統容量
  • C) 建立快照
  • D) 擴充 VG
解答：B) 卸載、檢查檔案系統，並先縮減檔案系統容量
安全縮減流程為：1) 備份資料、2) 執行 umount 卸載、3) 執行 e2fsck -f 檢查、4) 使用 resize2fs 縮小檔案系統、5) 使用 lvreduce 縮小 LV 至相同或較大空間。 亦可直接使用 lvreduce -r 自動化完成步驟 3 至 5。切記絕對不可在縮減檔案系統前先縮減 LV，否則將造成資料毀損！
