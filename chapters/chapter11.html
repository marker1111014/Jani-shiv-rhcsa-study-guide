🎯 systemd 簡介

systemd 是 RHEL 9 的初始化系統 (init system) 與服務管理程式。它取代了傳統的 SysV init 系統， 提供平行啟動服務、相依性管理以及進階的日誌記錄功能。

systemd 特色功能

  • 平行啟動： 同時啟動多個服務以大幅加快開機速度
  • 服務相依性： 自動處理服務之間的相依關係
  • Socket 啟動機制 (Socket Activation)： 當收到連線請求時才隨需啟動服務
  • Targets： 將多個單元群組化，類似傳統的 Runlevel（例如 multi-user、graphical）
  • Journal 日誌記錄： 整合 journalctl 進行系統日誌管理
  • 資源控管： 可針對個別服務限制 CPU、記憶體與 I/O 使用量

systemd 核心元件

元件 說明
systemctl 控制 systemd 服務與系統狀態
journalctl 查詢 systemd journal 系統日誌
systemd-analyze 分析開機效能與服務啟動耗時
單元檔 (Unit Files) 服務與系統單元設定檔（.service、.target、.mount）

單元類型 (Unit Types)

# 常見單元類型：
.service    # 系統服務 (sshd, httpd)
.target     # 單元群組 (multi-user.target)
.mount      # 掛載點
.socket     # IPC 通訊插槽 (Socket)
.timer      # 排程任務計時器
.path       # 檔案或目錄監控
.device     # 硬體裝置

⚙️ 管理系統服務

基本服務操作指令

# 啟動服務
sudo systemctl start httpd

# 停止服務
sudo systemctl stop httpd

# 重新啟動服務
sudo systemctl restart httpd

# 重新載入設定檔（不中斷服務進行重啟）
sudo systemctl reload httpd

# 若服務正在執行則重啟，若已停止則不啟動
sudo systemctl try-restart httpd

# 重新載入設定檔；若該服務不支援 reload，則執行 restart
sudo systemctl reload-or-restart httpd

檢視服務狀態

# 檢查服務詳細狀態
systemctl status httpd

# 輸出範例：
● httpd.service - The Apache HTTP Server
     Loaded: loaded (/usr/lib/systemd/system/httpd.service; enabled; preset: disabled)
     Active: active (running) since Mon 2025-01-13 10:30:15 EST; 2h 15min ago
       Docs: man:httpd.service(8)
   Main PID: 1234 (httpd)
     Status: "Total requests: 150; Idle/Busy workers 100/0"
      Tasks: 213 (limit: 11123)
     Memory: 25.1M
        CPU: 3.456s
     CGroup: /system.slice/httpd.service
             ├─1234 /usr/sbin/httpd -DFOREGROUND
             └─1235 /usr/sbin/httpd -DFOREGROUND

# 快速檢查是否運行中（僅回傳 active/inactive）
systemctl is-active httpd

# 檢查是否設定開機自動啟動
systemctl is-enabled httpd

# 檢查是否處於失敗狀態
systemctl is-failed httpd

開機自動啟用 / 停用服務

# 設定開機自動啟動服務
sudo systemctl enable httpd
# 會在 /etc/systemd/system/multi-user.target.wants/ 建立符號連結

# 取消開機自動啟動
sudo systemctl disable httpd

# 設定開機自動啟動並立即啟動服務
sudo systemctl enable --now httpd

# 取消開機自動啟動並立即停止服務
sudo systemctl disable --now httpd

# 遮蔽服務 (Mask，徹底禁止啟動，包含手動啟動)
sudo systemctl mask httpd

# 解除服務遮蔽
sudo systemctl unmask httpd

列出服務清單

# 列出所有已載入的單元
systemctl list-units

# 列出所有執行中的服務
systemctl list-units --type=service

# 列出所有服務（包含未啟動或非運行中的服務）
systemctl list-units --type=service --all

# 列出所有設定為開機啟用的服務
systemctl list-unit-files --state=enabled

# 列出啟動失敗的服務
systemctl --failed

# 顯示服務相依性樹狀圖
systemctl list-dependencies httpd

檢視與編輯服務設定

# 顯示完整單元設定檔內容
systemctl cat httpd

# 編輯單元設定（建立覆寫檔 override）
sudo systemctl edit httpd
# 會建立設定檔：/etc/systemd/system/httpd.service.d/override.conf

# 編輯完整單元檔複本
sudo systemctl edit --full httpd

# 顯示該單元的所有屬性
systemctl show httpd

# 顯示特定屬性值
systemctl show httpd -p ActiveState

操作步驟：安裝並啟用 Apache 服務

  1. 安裝 Apache 網頁伺服器： 
    sudo dnf install -y httpd
  2. 立即啟動服務： 
    sudo systemctl start httpd
  3. 設定於開機時自動啟動： 
    sudo systemctl enable httpd
  4. 驗證服務狀態與啟用設定： 
    systemctl status httpd
systemctl is-enabled httpd
  5. 測試服務是否正常回應（需防火牆已放行）： 
    curl http://localhost
💡 Enable 與 Start 的差異

enable：設定服務在開機時自動啟動
start：立即啟動服務（但重開機後不會自動啟動）
enable --now：單一指令同時完成開機啟用與立即啟動

🎯 Systemd Targets

Target 是定義系統運作狀態的單元群組，其功能類似於傳統的 SysV Runlevel（執行層級）。

常見 Targets

Target Runlevel 說明
poweroff.target 0 關閉系統電源
rescue.target 1 單人救援模式（提供 root Shell）
multi-user.target 3 多使用者文字模式（無圖形介面）
graphical.target 5 多使用者圖形介面模式 (GUI)
reboot.target 6 重新啟動系統
emergency.target - 最小化 Shell 環境（比救援模式更精簡）

管理 Targets

# 顯示目前預設的開機 Target
systemctl get-default

# 設定開機預設 Target
sudo systemctl set-default multi-user.target
sudo systemctl set-default graphical.target

# 立即切換至指定的 Target
sudo systemctl isolate multi-user.target
sudo systemctl isolate graphical.target

# 列出可用的 Targets
systemctl list-units --type=target

# 顯示 Target 的相依性清單
systemctl list-dependencies graphical.target

系統電源與狀態指令

# 重新啟動系統
sudo systemctl reboot

# 關閉系統電源
sudo systemctl poweroff

# 停止系統運作 (Halt)
sudo systemctl halt

# 暫停系統（睡眠模式）
sudo systemctl suspend

# 系統休眠 (Hibernate)
sudo systemctl hibernate

# 進入救援模式
sudo systemctl rescue

# 進入緊急模式
sudo systemctl emergency
📘 Rescue 與 Emergency 模式比較

rescue.target：會掛載本機檔案系統、啟動基本服務，並要求輸入 root 密碼
emergency.target：僅將根檔案系統以唯讀模式掛載、不啟動任何服務，直接進入單人 Shell

🚀 開機流程

RHEL 9 開機順序

  1. UEFI/BIOS：硬體初始化、開機自我檢測 (POST)
  2. 開機載入程式 (GRUB2)：載入 Linux 核心與 initramfs
  3. 核心 (Kernel)：初始化硬體裝置並掛載根檔案系統
  4. systemd：系統第一個行程 (PID 1)，啟動各項系統服務
  5. 預設 Target：抵達 multi-user.target 或 graphical.target
  6. 登入畫面：系統啟動完成並可供登入

分析開機效能

# 顯示總開機耗時統計
systemd-analyze

# 輸出範例：
Startup finished in 1.234s (kernel) + 5.678s (initrd) + 15.432s (userspace) = 22.344s
graphical.target reached after 15.123s in userspace

# 顯示各服務啟動所花費的時間
systemd-analyze blame

# 輸出（耗時最長的服務排在最前面）：
5.234s NetworkManager-wait-online.service
2.123s kdump.service
1.456s firewalld.service

# 顯示關鍵路徑相依鏈（找出拖慢開機的瓶頸服務）
systemd-analyze critical-chain

# 產生開機過程時間軸視覺化圖表 (SVG)
systemd-analyze plot > boot.svg

GRUB2 開機選單

# GRUB2 設定檔路徑
/boot/grub2/grub.cfg        # 主要設定檔（請勿直接手動編輯）
/etc/default/grub           # 使用者自訂設定檔
/etc/grub.d/                # 設定產生腳本目錄

# 修改 GRUB 設定
sudo vi /etc/default/grub

# 設定範例：
GRUB_TIMEOUT=5
GRUB_CMDLINE_LINUX="rhgb quiet"

# 重新產生 GRUB 設定檔（BIOS 系統）
sudo grub2-mkconfig -o /boot/grub2/grub.cfg

# 重新產生 GRUB 設定檔（UEFI 系統）：
sudo grub2-mkconfig -o /boot/efi/EFI/redhat/grub.cfg

核心開機參數 (Kernel Command Line)

# 檢視目前開機所使用的核心參數
cat /proc/cmdline

# 常見核心開機參數：
rhgb               # Red Hat 圖形化開機畫面 (Splash screen)
quiet              # 隱藏大多數開機過程訊息
systemd.unit=      # 指定開機進入特定的 Target
rd.break           # 中斷開機流程並進入 initramfs Shell
init=/bin/bash     # 直接開機進入 bash（風險較高，需謹慎使用）
selinux=0          # 暫時停用 SELinux

🔧 開機問題疑難排解

開機進入救援模式 (Rescue Mode)

  1. 重新啟動系統
  2. 在 GRUB 開機選單按 e 鍵
  3. 找到以 linux 或 linux16 開頭的那一行
  4. 在該行末端加上：systemd.unit=rescue.target
  5. 按下 Ctrl+x 啟動系統
  6. 輸入 root 密碼登入

開機進入緊急模式 (Emergency Mode)

  1. 步驟與救援模式相同，但改為加上：systemd.unit=emergency.target
  2. 此時根檔案系統預設為唯讀掛載
  3. 手動將根目錄重新掛載為讀寫模式：mount -o remount,rw /

中斷進入 initramfs 階段

# 在 GRUB 編輯畫面中，於核心參數行末端加上：
rd.break

# 系統會在掛載真實根檔案系統之前提供一個 Shell
# 此時真實系統的根目錄位於 /sysroot（為唯讀狀態）

# 將 /sysroot 重新掛載為讀寫模式
mount -o remount,rw /sysroot

# 使用 chroot 切換至系統環境
chroot /sysroot

# 完成修改作業後，依序離開並重新開機：
exit
reboot -f

常見開機問題與解決方式

問題描述 解決方式
/etc/fstab 設定錯誤 開機進入緊急模式並修正 fstab 設定檔
忘記 root 密碼 利用 rd.break 中斷開機並重設密碼
開機時特定服務啟動失敗 暫時停用該服務並檢查系統日誌以排查錯誤
SELinux 阻擋系統開機 於核心啟動參數行加上 selinux=0 進行排查

🔑 重設 Root 密碼

操作步驟：重設 Root 密碼（RHCSA 考試必考重點！）

  1. 重新啟動系統
  2. 在 GRUB 開機選單畫面按下 e 鍵進入編輯模式
  3. 找到以 linux 開頭的那一行
  4. 在該行末端加上 rd.break： 
    linux ($root)/vmlinuz-... root=UUID=... rhgb quiet rd.break
  5. 按下 Ctrl+x 繼續開機
  6. 系統將會進入 switch_root:/# 提示字元
  7. 將 /sysroot 重新掛載為讀寫模式： 
    mount -o remount,rw /sysroot
  8. 切換根目錄 (chroot) 至系統環境： 
    chroot /sysroot
  9. 變更 root 使用者密碼： 
    passwd root
# 輸入兩次新密碼
  10. SELinux 關鍵步驟：設定於下次開機時自動重新標記檔案標籤： 
    touch /.autorelabel
  11. 離開 chroot 環境並強制重新開機： 
    exit
reboot -f
  12. 系統會自動執行檔案安全脈絡重新標記（可能需要幾分鐘），完成後即會正常開機
⚠️ 關鍵提醒：切勿遺忘 .autorelabel

如果您沒有建立 /.autorelabel 檔案，SELinux 將會阻擋您在變更密碼後登入系統！ 系統會在下次開機時自動重新標記檔案的安全脈絡。這是 RHCSA 考試中絕對不可遺漏的必要步驟！

替代方案：使用 init=/bin/bash 開機

# 在 GRUB 編輯畫面中，將 'rhgb quiet' 替換為：
init=/bin/bash

# 系統會直接開機進入 bash（不啟動 systemd）
# 此時根檔案系統為唯讀狀態

# 重新掛載為讀寫模式
mount -o remount,rw /

# 變更密碼
passwd root

# 建立 autorelabel 標記檔
touch /.autorelabel

# 將資料寫回磁碟並強制重開機
sync
reboot -f
⚠️ 安全性考量

能夠實體接觸主機就等同於取得 root 存取權限。請務必為 GRUB 設定保護密碼或啟用 BIOS/UEFI 密碼， 以防止未經授權的人員重設密碼。此外，亦可考慮採用全磁碟加密 (LUKS) 提升安全性。

📝 練習題

第 1 題：哪一個指令可以設定 httpd 服務在開機時自動啟動？

  • A) systemctl start httpd
  • B) systemctl enable httpd
  • C) systemctl activate httpd
  • D) systemctl boot httpd
解答：B) systemctl enable httpd
enable 會在對應 target 的 .wants 目錄中建立符號連結，使服務於開機時自動啟動。 start 僅會立即啟動服務（不會在重開機後維持啟動）。可使用 enable --now 同時設定開機啟用並立即啟動服務。

第 2 題：哪一個 Target 相當於傳統的 Runlevel 3（多使用者文字模式，無 GUI）？

  • A) graphical.target
  • B) multi-user.target
  • C) rescue.target
  • D) default.target
解答：B) multi-user.target
multi-user.target 等同於 Runlevel 3（文字介面模式）；graphical.target 為 Runlevel 5（圖形介面）； rescue.target 為 Runlevel 1（單人救援模式）。設定預設 Target 指令：systemctl set-default multi-user.target

第 3 題：使用 rd.break 重設 root 密碼時，最關鍵的步驟為何？

  • A) 執行 passwd root
  • B) 執行 mount -o remount,rw /sysroot
  • C) 執行 touch /.autorelabel
  • D) 執行 chroot /sysroot
解答：C) 執行 touch /.autorelabel
雖然所有步驟都不可或缺，但 touch /.autorelabel 在啟用 SELinux 的系統上極為關鍵。 若缺少此步驟，更改後的 /etc/shadow 安全脈絡標籤將不正確，導致系統阻擋登入。這也是考試中最常見的失分原因！

第 4 題：如何徹底阻止服務啟動（即使是手動啟動也不允許）？

  • A) systemctl disable httpd
  • B) systemctl stop httpd
  • C) systemctl mask httpd
  • D) systemctl isolate httpd
解答：C) systemctl mask httpd
mask 會將服務單元連結至 /dev/null，使其完全無法被啟動（包含手動執行 start）。 disable 僅取消開機自動啟動。若要解除遮蔽請使用 unmask，這常用於避免服務相互衝突。

第 5 題：哪一種模式會在不啟動系統服務的情況下提供最小化 Shell（根目錄為唯讀）？

  • A) rescue.target
  • B) emergency.target
  • C) multi-user.target
  • D) rd.break
解答：B) emergency.target
emergency.target 會將根檔案系統以唯讀模式掛載，僅提供最小化 Shell 且不啟動任何服務。 rescue.target 則會掛載所有本機檔案系統、啟動基本服務並要求輸入 root 密碼。 而 rd.break 則是在切換至真實根檔案系統前中斷並進入 initramfs Shell。

第 6 題：哪個指令可以顯示是哪些服務拖慢了開機速度？

  • A) systemctl --failed
  • B) systemd-analyze blame
  • C) journalctl -b
  • D) systemctl list-units
解答：B) systemd-analyze blame
systemd-analyze blame 會依服務啟動耗時由長到短列出清單。 systemd-analyze 顯示開機總耗時；systemd-analyze critical-chain 則可顯示造成開機阻塞的相依性關鍵路徑。
