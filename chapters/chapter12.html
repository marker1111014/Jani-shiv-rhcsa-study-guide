分析系統日誌

精通使用 journalctl 與 rsyslog 分析及管理系統日誌。學習查詢 systemd journal、設定持久性日誌儲存、 分析開機過程日誌，以及管理傳統的 syslog 文字日誌檔案。

🎯 系統日誌簡介

RHEL 9 使用兩套系統日誌架構：systemd-journald（二進位格式日誌）與 rsyslog（純文字檔案）。 兩者相互配合運作，為系統提供完整且詳盡的日誌記錄能力。

日誌系統架構

日誌系統 格式 儲存位置 查詢工具
systemd-journald 二進位 (Binary) /run/log/journal (揮發性) journalctl
rsyslog 純文字 (Text) /var/log/* less, grep, tail

常見日誌檔案 (rsyslog)

檔案路徑 記錄內容
/var/log/messages 一般系統訊息
/var/log/secure 身分驗證與授權安全日誌
/var/log/audit/audit.log SELinux 稽核事件記錄
/var/log/cron Cron 排程工作執行日誌
/var/log/boot.log 系統開機過程訊息
/var/log/maillog 郵件伺服器日誌

日誌優先層級 (Priority Levels)

# 由最高至最低嚴重層級排列：
0 emerg    # 系統已無法運作
1 alert    # 必須立即採取行動
2 crit     # 嚴重緊急狀況
3 err      # 錯誤狀況
4 warning  # 警告狀況
5 notice   # 正常但值得注意的事件
6 info     # 一般資訊性訊息
7 debug    # 除錯偵錯訊息

📜 journalctl - systemd Journal

基本 journalctl 指令

# 檢視所有 journal 日誌（最舊的排在最前面）
journalctl

# 反向檢視（最新的排在最前面）
journalctl -r

# 即時追蹤最新日誌（類似 tail -f）
journalctl -f

# 僅顯示核心 (Kernel) 訊息
journalctl -k
# 或
journalctl --dmesg

# 顯示最近 N 筆日誌項目
journalctl -n 50

# 不使用分頁器（一次輸出所有內容）
journalctl --no-pager

依時間條件篩選

# 顯示自上次開機以來的日誌
journalctl -b

# 顯示前一次開機的日誌
journalctl -b -1

# 列出所有有記錄的開機歷史清單
journalctl --list-boots

# 查詢特定起始時間之後的日誌
journalctl --since "2025-01-13 10:00:00"
journalctl --since "1 hour ago"
journalctl --since yesterday
journalctl --since today

# 查詢特定結束時間之前的日誌
journalctl --until "2025-01-13 12:00:00"

# 查詢指定時間區間內的日誌
journalctl --since "2025-01-13 09:00" --until "2025-01-13 17:00"

依服務 / 單元篩選

# 顯示特定服務的日誌
journalctl -u sshd
journalctl -u httpd.service

# 同時查詢多個單元
journalctl -u sshd -u httpd

# 顯示特定服務自本次開機以來的日誌
journalctl -u sshd -b

# 即時追蹤特定服務的日誌
journalctl -u httpd -f

依優先層級篩選

# 僅顯示錯誤及以上層級 (emerg, alert, crit, err)
journalctl -p err

# 顯示警告及以上層級
journalctl -p warning

# 指定特定層級代碼
journalctl -p 3  # err 層級

# 指定層級範圍
journalctl -p err -p warning

依行程 / 使用者篩選

# 依行程編號 (PID) 篩選
journalctl _PID=1234

# 依使用者 UID 篩選
journalctl _UID=1000

# 依執行檔名稱篩選
journalctl _COMM=sshd

# 依 systemd 單元篩選
journalctl _SYSTEMD_UNIT=httpd.service

輸出格式

# 詳細欄位輸出
journalctl -o verbose

# 簡短格式（傳統 syslog 風格，預設）
journalctl -o short

# JSON 格式
journalctl -o json

# 易讀縮排的 JSON 格式
journalctl -o json-pretty

# 匯出格式（適合用於備份或跨主機遷移）
journalctl -o export

# 僅顯示訊息內容本文
journalctl -o cat

組合多種篩選條件

# 查詢 sshd 自上次開機以來的錯誤層級日誌
journalctl -u sshd -b -p err

# 查詢 httpd 最近 20 筆錯誤日誌
journalctl -u httpd -p err -n 20

# 查詢今日的 SSH 驗證日誌，並顯示精確到微秒的時間戳記
journalctl -u sshd --since today -o short-precise

磁碟空間使用量

# 顯示 journal 佔用的磁碟空間
journalctl --disk-usage

# 輸出範例：
Archived and active journals take up 512.0M in the file system.

# 驗證 journal 檔案完整性
journalctl --verify

操作步驟：排查服務啟動失敗問題

  1. 檢查服務目前狀態： 
    systemctl status httpd
  2. 檢視該服務最近的日誌： 
    journalctl -u httpd -n 50
  3. 檢查自本次開機以來的錯誤層級日誌： 
    journalctl -u httpd -b -p err
  4. 在重啟服務的同時即時追蹤日誌輸出： 
    # 終端機 1：
journalctl -u httpd -f

# 終端機 2：
sudo systemctl restart httpd
  5. 檢視特定錯誤發生的精確時間戳記： 
    journalctl -u httpd --since "5 minutes ago" -o short-precise

💾 持久性 Journal 儲存

預設情況下，systemd journal 儲存在 /run/log/journal（重開機後即遺失）。 啟用持久性儲存後，系統便會在重新開機後保留所有歷史日誌。

啟用持久性 Journal

# 建立持久性 journal 儲存目錄
sudo mkdir -p /var/log/journal

# 設定正確的擁有權與權限
sudo chown root:systemd-journal /var/log/journal
sudo chmod 2755 /var/log/journal

# 重新啟動 journald 以套用新目錄
sudo systemctl restart systemd-journald

# 或者透過修改 /etc/systemd/journald.conf 設定檔啟用：
sudo vi /etc/systemd/journald.conf

[Journal]
Storage=persistent
SystemMaxUse=500M
SystemKeepFree=1G
MaxRetentionSec=1month

# 重新啟動 journald
sudo systemctl restart systemd-journald

Journal 設定參數

設定項目 說明
Storage=persistent 將日誌儲存於 /var/log/journal
Storage=volatile 將日誌儲存於 /run/log/journal（預設值）
SystemMaxUse= Journal 可使用的最大磁碟空間上限
MaxRetentionSec= Journal 日誌項目的最長保留時間

管理 Journal 容量大小

# 手動輪替 journal 檔案
sudo journalctl --rotate

# 依空間上限清理舊日誌（僅保留 500MB）
sudo journalctl --vacuum-size=500M

# 依保留時間清理舊日誌（僅保留最近 2 週）
sudo journalctl --vacuum-time=2weeks

# 依檔案數量清理舊日誌（僅保留 5 個檔案）
sudo journalctl --vacuum-files=5

# 清理後檢查剩餘空間使用量
journalctl --disk-usage
📘 Journal 儲存位置比較

/run/log/journal：揮發性（位於 RAM 記憶體中，重開機即清空）
/var/log/journal：持久性（寫入實體磁碟，重開機後依然保留）
只要 /var/log/journal 目錄存在，系統便會自動啟用持久性儲存。

📋 rsyslog - 傳統日誌系統

rsyslog 會接收來自 journald 的日誌事件，並將其寫入 /var/log/ 目錄下的純文字日誌檔中。

rsyslog 設定檔

# 主要設定檔
/etc/rsyslog.conf

# 額外擴充設定檔目錄
/etc/rsyslog.d/*.conf

# 設定規則語法格式範例：
facility.priority    action

# 規則範例：
*.info;mail.none;authpriv.none;cron.none    /var/log/messages
authpriv.*                                   /var/log/secure
mail.*                                       /var/log/maillog
cron.*                                       /var/log/cron

設備類別 (Facilities) 與優先層級 (Priorities)

# 設備類別 (Facilities)：
auth, authpriv  # 安全性與身分驗證
cron            # Cron 排程守護行程
daemon          # 系統背景服務 (Daemons)
kern            # 核心訊息
mail            # 郵件系統
user            # 使用者層級訊息
local0-local7   # 自訂應用程式專用

# 優先層級選取器 (Priority selectors)：
*          # 所有層級
none       # 不記錄任何層級
.priority  # 指定層級及以上所有層級
.=priority # 僅記錄完全符合該層級的訊息
.!priority # 排除該層級的訊息

檢視傳統文字日誌

# 檢視系統一般訊息日誌
sudo less /var/log/messages
sudo tail -f /var/log/messages

# 檢視身分驗證與安全日誌
sudo tail -f /var/log/secure

# 搜尋特定關鍵字樣式
sudo grep "Failed password" /var/log/secure

# 檢視最後 20 行日誌
sudo tail -20 /var/log/messages

# 同時即時追蹤多個日誌檔
sudo tail -f /var/log/messages /var/log/secure

自訂 rsyslog 規則

# 為 httpd 建立獨立的自訂日誌設定
sudo vi /etc/rsyslog.d/httpd.conf

# 新增規則：
if $programname == 'httpd' then /var/log/httpd-custom.log
& stop

# 重新啟動 rsyslog 服務
sudo systemctl restart rsyslog

# 使用 logger 測試驗證
logger -t httpd "Test message"
sudo tail /var/log/httpd-custom.log

遠端日誌傳送

# 設定用戶端將日誌傳送至遠端日誌伺服器
sudo vi /etc/rsyslog.conf

# 新增規則（使用 UDP 協定）：
*.* @192.168.1.100:514

# 或（使用 TCP 協定）：
*.* @@192.168.1.100:514

# 重新啟動 rsyslog
sudo systemctl restart rsyslog

🔄 日誌輪替 (Log Rotation)

logrotate 負責自動化管理日誌檔案的輪替與歸檔，以防止日誌檔持續膨脹而塞滿磁碟空間。

logrotate 設定檔

# 主要設定檔
/etc/logrotate.conf

# 各服務專屬的設定檔目錄
/etc/logrotate.d/

# 自訂應用程式的日誌輪替設定範例
sudo vi /etc/logrotate.d/myapp

/var/log/myapp/*.log {
    daily
    rotate 7
    compress
    delaycompress
    missingok
    notifempty
    create 0640 root root
    sharedscripts
    postrotate
        systemctl reload myapp > /dev/null 2>&1 || true
    endscript
}

logrotate 常用指令參數

參數 說明
daily/weekly/monthly 輪替週期（每日 / 每週 / 每月）
rotate N 保留最近 N 份已輪替的歷史日誌
compress 使用 gzip 壓縮已輪替的日誌檔案
delaycompress 延遲至下一次輪替時才執行壓縮
missingok 若日誌檔案遺失或不存在時不回報錯誤
notifempty 若日誌檔案為空則不執行輪替
create MODE OWNER GROUP 輪替後依指定權限與擁有者建立新的空日誌檔

手動執行日誌輪替

# 測試輪替設定（Dry run 模擬執行，不實際變更檔案）
sudo logrotate -d /etc/logrotate.d/myapp

# 強制立即執行輪替
sudo logrotate -f /etc/logrotate.d/myapp

# 依主設定檔執行所有日誌輪替
sudo logrotate /etc/logrotate.conf

# 檢視日誌輪替狀態記錄
cat /var/lib/logrotate/logrotate.status

📝 練習題

第 1 題：哪一個指令可以顯示自上次開機以來的系統日誌？

  • A) journalctl --boot
  • B) journalctl -b
  • C) A 與 B 皆可
  • D) journalctl --since boot
解答：C) A 與 B 皆可
journalctl -b 與 journalctl --boot 功能完全相同。 使用 -b -1 可查看前一次開機日誌，-b -2 則為更前一次。 使用 --list-boots 可列出所有可用的開機歷史紀錄。

第 2 題：如何啟用持久性 journal 日誌儲存？

  • A) 建立 /var/log/journal 目錄
  • B) 在 journald.conf 中設定 Storage=persistent
  • C) A 與 B 皆可
  • D) 編輯 /etc/fstab
解答：C) A 與 B 皆可
兩種方式皆有效：建立 /var/log/journal 目錄（系統會自動啟用）或在 /etc/systemd/journald.conf 中設定 Storage=persistent。 建立目錄的方法最為簡便。修改完成後切記重新啟動 systemd-journald 服務。

第 3 題：哪一個日誌檔案會記錄使用者身分驗證失敗的訊息？

  • A) /var/log/messages
  • B) /var/log/secure
  • C) /var/log/auth.log
  • D) /var/log/faillog
解答：B) /var/log/secure
在 RHEL 系統中，/var/log/secure 負責記錄身分驗證與授權相關日誌（如 SSH 登入、sudo 使用記錄等）。 可使用 grep "Failed password" /var/log/secure 找出失敗的登入嘗試，或使用 journalctl -u sshd 查詢。

第 4 題：哪一個指令可以像 "tail -f" 一樣即時追蹤最新的 journal 日誌？

  • A) journalctl -f
  • B) journalctl --follow
  • C) A 與 B 皆可
  • D) journalctl -tail
解答：C) A 與 B 皆可
journalctl -f 與 journalctl --follow 皆可即時追蹤日誌輸出。 亦可搭配 -u 追蹤特定服務：journalctl -u httpd -f。按下 Ctrl+C 即可停止追蹤。

第 5 題：如何將 journal 日誌的磁碟空間使用量限制在 500MB 以內？

  • A) journalctl --vacuum-size=500M
  • B) 在 journald.conf 中設定 SystemMaxUse=500M
  • C) A 與 B 皆可
  • D) logrotate -s 500M
解答：C) A 與 B 皆可
--vacuum-size 會立即清理舊日誌以符合容量限制；而在 /etc/systemd/journald.conf 中設定 SystemMaxUse 則可設定長期的空間上限。 也可使用 --vacuum-time=2weeks 依時間清理舊日誌，並透過 journalctl --disk-usage 檢查目前佔用空間。

第 6 題：哪一個優先層級參數只會顯示錯誤 (err) 及更嚴重的日誌訊息？

  • A) journalctl -p warning
  • B) journalctl -p err
  • C) journalctl -p crit
  • D) journalctl -p 3
解答：B 或 D（兩者皆正確）
-p err 會顯示錯誤及以上嚴重程度的訊息（emerg、alert、crit、err），而層級代碼 3 正好代表 err。 -p warning 會包含警告訊息（較寬鬆）；-p crit 則只顯示嚴重及更高層級（較嚴格）。 層級對照：0=emerg、1=alert、2=crit、3=err、4=warning、5=notice、6=info、7=debug。
