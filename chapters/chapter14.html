掛載網路儲存 (NFS & AutoFS)

精通使用 NFS 掛載網路檔案系統以及透過 AutoFS 實現自動掛載。學習如何設定 NFS 用戶端、建立開機永久掛載，並使用萬用字元對應（Wildcard Maps）實現隨需掛載。

📋 本章目錄

  • 網路儲存簡介
  • NFS 用戶端設定
  • AutoFS - 自動掛載
  • 直接對應 (Direct Maps)
  • 間接對應 (Indirect Maps)
  • 萬用字元對應 (Wildcard Maps)
  • 練習題

🎯 網路儲存簡介

網路檔案系統（Network File System, NFS）可透過網路共用目錄。AutoFS 則提供 NFS 共用目錄與本機檔案系統的自動、隨需（on-demand）掛載機制。

NFS 版本比較

版本 特色
NFSv3 傳統版本，支援 UDP/TCP，無加密機制
NFSv4 RHEL 9 預設版本，僅使用 TCP，支援 Kerberos 驗證
NFSv4.2 最新版本，支援伺服器端複製、稀疏檔案（Sparse files）

傳統 /etc/fstab 掛載 vs AutoFS

方式 優點 缺點
/etc/fstab 設定簡單，開機時自動掛載 永遠保持掛載狀態，若伺服器離線可能導致開機卡住
AutoFS 存取時才隨需掛載、閒置自動卸載、不影響開機速度 設定步驟較為複雜

必要軟體套件

# 安裝 NFS 公用程式（用戶端）
sudo dnf install -y nfs-utils

# 安裝 AutoFS
sudo dnf install -y autofs

# 驗證套件安裝
rpm -q nfs-utils autofs

📂 NFS 用戶端設定

探索 NFS 共用資源

# 顯示 NFS 伺服器匯出的共用目錄
showmount -e server.example.com

# 輸出範例：
Export list for server.example.com:
/shared     192.168.1.0/24
/home/users *
/data       client1.example.com

# 檢查 NFS 伺服器連線與 RPC 服務狀態
ping server.example.com
rpcinfo -p server.example.com

手動掛載 NFS

# 建立掛載點目錄
sudo mkdir -p /mnt/nfs

# 掛載 NFS 共用目錄（NFSv4）
sudo mount -t nfs4 server.example.com:/shared /mnt/nfs

# 指定使用 NFSv3 掛載
sudo mount -t nfs -o vers=3 server.example.com:/shared /mnt/nfs

# 驗證掛載狀態
df -h /mnt/nfs
mount | grep nfs

# 卸載
sudo umount /mnt/nfs

永久掛載 NFS（/etc/fstab）

# 編輯 /etc/fstab
sudo vi /etc/fstab

# 新增 NFS 掛載設定（NFSv4）
server.example.com:/shared  /mnt/nfs  nfs  defaults  0  0

# 搭配網路掛載選項
server.example.com:/shared  /mnt/nfs  nfs  defaults,_netdev  0  0

# 指定使用 NFSv3
server.example.com:/shared  /mnt/nfs  nfs  defaults,_netdev,vers=3  0  0

# 重新開機前先測試掛載
sudo mount -a

# 驗證掛載
df -h /mnt/nfs

常見 NFS 掛載選項

選項 說明
_netdev 等待網路就緒後再進行掛載（NFS 掛載極為關鍵！）
soft 伺服器連線逾時時直接回傳錯誤
hard 持續重試連線（預設值，資料安全性較高）
ro 唯讀（Read-only）
rw 可讀寫（Read-write）
vers=4 強制使用 NFSv4（預設）
sec=krb5 使用 Kerberos 身分驗證
⚠️ 務必使用 _netdev 選項

在 /etc/fstab 中設定 NFS 掛載時，請務必加上 _netdev 選項！ 若未加入此選項，當網路尚未就緒時系統可能會在開機階段卡住。此選項能確保系統等待網路啟動完成後再嘗試掛載 NFS。

操作步驟：永久掛載 NFS 共用目錄

  1. 查詢可用的共用目錄： 
    showmount -e server.example.com
  2. 建立掛載點目錄： 
    sudo mkdir -p /mnt/shared
  3. 測試手動掛載： 
    sudo mount -t nfs4 server.example.com:/shared /mnt/shared
df -h /mnt/shared
  4. 將設定寫入 /etc/fstab： 
    sudo vi /etc/fstab
server.example.com:/shared  /mnt/shared  nfs  defaults,_netdev  0  0
  5. 卸載並測試 fstab 設定： 
    sudo umount /mnt/shared
sudo mount -a
df -h /mnt/shared

🔄 AutoFS - 自動掛載

AutoFS 會在檔案系統被存取時自動進行掛載，並在閒置逾時後自動卸載（預設為 5 分鐘）。

AutoFS 設定檔

# 主要設定檔
/etc/auto.master        # 主對應檔（定義掛載點與對應檔）
/etc/auto.master.d/     # 額外的主對應設定檔目錄

# 對應檔（定義要掛載的遠端資源與選項）
/etc/auto.misc          # 預設的間接對應檔
/etc/auto.net           # 網路自動掛載腳本
/etc/auto.home          # 家目錄對應檔（範例）

AutoFS 服務管理

# 啟動 AutoFS 服務
sudo systemctl start autofs

# 設定開機自動啟動並立即啟動
sudo systemctl enable --now autofs

# 修改設定後重新啟動服務
sudo systemctl restart autofs

# 檢查服務狀態
systemctl status autofs

# 重新載入設定檔
sudo systemctl reload autofs

主對應檔（Master Map）格式

# /etc/auto.master 格式：
# 掛載點(mount-point)  對應檔(map-file)  [選項(options)]

/mnt/auto    /etc/auto.nfs    --timeout=60
/home        /etc/auto.home   --timeout=300

📍 AutoFS 直接對應 (Direct Maps)

直接對應（Direct Map）會在對應檔中直接指定精確的絕對掛載路徑。在主對應檔中使用 /- 作為掛載點。

操作步驟：設定直接對應（Direct Map）

  1. 建立對應檔： 
    sudo vi /etc/auto.direct

# 新增直接掛載項目（使用絕對路徑）
/mnt/data  -rw,soft  server.example.com:/exports/data
  2. 將對應檔加入主對應檔： 
    sudo vi /etc/auto.master

# 新增以下設定行：
/-  /etc/auto.direct
  3. 重新啟動 AutoFS 服務： 
    sudo systemctl restart autofs
  4. 存取目錄以觸發自動掛載： 
    ls /mnt/data
df -h /mnt/data
  5. 驗證自動掛載結果： 
    mount | grep autofs

直接對應檔格式

# /etc/auto.direct
# 掛載點(mount-point)  掛載選項(options)  遠端位置(location)

/mnt/project  -rw,soft  nfsserver:/exports/project
/backup       -ro       nfsserver:/backups
/share        -rw       192.168.1.100:/shared

📂 AutoFS 間接對應 (Indirect Maps)

間接對應（Indirect Map）會在指定的父目錄下建立子目錄作為掛載點，相較於直接對應更具彈性。

操作步驟：設定間接對應（Indirect Map）

  1. 建立對應檔： 
    sudo vi /etc/auto.shares

# 新增間接掛載項目（使用相對名稱，開頭不可加 /）
data     -rw,soft  server.example.com:/exports/data
backup   -ro       server.example.com:/exports/backup
docs     -rw       server.example.com:/exports/docs
  2. 將設定加入主對應檔： 
    sudo vi /etc/auto.master

# 新增設定行（指定父目錄）：
/mnt/remote  /etc/auto.shares  --timeout=60
  3. 重新啟動 AutoFS 服務： 
    sudo systemctl restart autofs
  4. 存取目錄進行測試： 
    ls /mnt/remote/data      # 掛載 server:/exports/data
ls /mnt/remote/backup    # 掛載 server:/exports/backup
ls /mnt/remote/docs      # 掛載 server:/exports/docs
  5. 檢查掛載狀態： 
    df -h | grep remote
mount | grep autofs

間接對應檔格式

# /etc/auto.shares
# 鍵值(key)  掛載選項(options)  遠端位置(location)

docs     -rw  nfsserver:/exports/documentation
home     -rw  nfsserver:/home/&
tools    -ro  nfsserver:/opt/tools
📘 注意：直接對應 vs 間接對應

直接對應（Direct）：在主對應檔使用 /-，對應檔內填寫絕對路徑
間接對應（Indirect）：在主對應檔指定父目錄，對應檔內填寫相對鍵值名稱
使用時機：當同一個父目錄下有多個相關掛載點時，建議優先使用間接對應

🎯 AutoFS 萬用字元對應 (Wildcard Maps)

萬用字元對應使用 * 來匹配任意鍵值，非常適合用於自動掛載使用者的家目錄。

家目錄自動掛載

# 建立家目錄的對應檔
sudo vi /etc/auto.home

# 萬用字元項目（& 會自動代入所存取的鍵值）
*  -rw,soft  nfsserver:/home/&amp;

# 加入主對應檔
sudo vi /etc/auto.master
/home  /etc/auto.home  --timeout=300

# 重新啟動 AutoFS
sudo systemctl restart autofs

# 存取使用者家目錄（存取時自動掛載）
cd /home/john    # 掛載 nfsserver:/home/john
cd /home/alice   # 掛載 nfsserver:/home/alice

萬用字元應用範例

# 多使用者共用目錄
sudo vi /etc/auto.users
*  -rw  nfsserver:/users/&amp;

# 各部門共用目錄
sudo vi /etc/auto.dept
*  -rw  fileserver:/departments/&amp;

# 存取方式：
ls /mnt/users/bob      # 掛載 /users/bob
ls /mnt/dept/sales     # 掛載 /departments/sales

搭配子目錄的進階萬用字元設定

# 多層級目錄結構
sudo vi /etc/auto.projects

*  -rw  projectserver:/projects/&amp;/current

# 產生的對應結構如下：
/mnt/projects/alpha  → projectserver:/projects/alpha/current
/mnt/projects/beta   → projectserver:/projects/beta/current

操作步驟：設定使用萬用字元的 AutoFS 家目錄掛載

  1. 建立包含萬用字元的對應檔： 
    sudo vi /etc/auto.home
*  -rw,soft,_netdev  server.example.com:/home/&amp;
  2. 將設定加入主對應檔： 
    sudo vi /etc/auto.master
/rhome  /etc/auto.home
  3. 重新啟動 AutoFS 服務： 
    sudo systemctl restart autofs
  4. 以不同使用者名稱進行測試： 
    ls /rhome/user1    # 自動掛載 server:/home/user1
ls /rhome/user2    # 自動掛載 server:/home/user2
  5. 驗證掛載結果： 
    df -h | grep rhome
mount | grep autofs

AutoFS 疑難排解

# 檢查 AutoFS 服務狀態
systemctl status autofs

# 檢視 AutoFS 日誌
journalctl -u autofs -n 50

# 以詳細除錯輸出模式進行前景測試
sudo automount -f -v

# 檢查主對應檔的有效設定
sudo cat /etc/auto.master | grep -v '^#'

# 驗證對應檔語法
sudo cat /etc/auto.home

# 檢查掛載點目錄狀態（存取前子目錄通常尚未建立）
ls -ld /mnt/auto

# 強制延遲卸載卡住的 AutoFS 掛載點
sudo umount -l /mnt/auto/*
💡 AutoFS 最佳實踐

• 不要手動建立 AutoFS 的掛載點目錄（AutoFS 會自動管理並建立）
• 多個相關共用目錄建議採用間接對應（Indirect Maps）
• 依需求設定適當的閒置逾時時間（預設 300 秒，可透過 --timeout= 調整）
• 每次修改設定後務必重新啟動 autofs 服務
• 若未觸發自動掛載，請查看日誌：journalctl -u autofs

📝 練習題

第 1 題：在 /etc/fstab 中設定 NFS 掛載時，哪一個選項最為關鍵？

  • A) rw
  • B) _netdev
  • C) defaults
  • D) soft
解答：B) _netdev
_netdev 會通知 systemd 等待網路就緒後再執行掛載。若缺少此選項， 當 NFS 伺服器無法連線時可能會導致系統開機卡住。標準寫法如下： server:/share /mnt nfs defaults,_netdev 0 0

第 2 題：AutoFS 主對應檔（Master Map）中，直接掛載（Direct Mounts）需使用哪個符號？

  • A) *
  • B) /-
  • C) /mnt
  • D) &
解答：B) /-
直接對應在 /etc/auto.master 中使用 /- 作為掛載點， 並在對應檔中使用絕對路徑。間接對應則是在主對應檔指定一個父目錄。 範例：/- /etc/auto.direct

第 3 題：在 AutoFS 萬用字元對應檔中，"&" 符號代表什麼意義？

  • A) 匹配所有檔案
  • B) 替換為所存取的鍵值（例如使用者名稱或目錄名稱）
  • C) 在背景執行程序
  • D) 選填參數
解答：B) 替換為所存取的鍵值
在 * -rw server:/home/& 設定中，& 會被自動替換為實際存取的鍵值名稱。 例如存取 /home/john 時會自動掛載 server:/home/john，非常適合用於家目錄管理。

第 4 題：編輯完成 AutoFS 對應檔後，必須執行什麼操作？

  • A) 重新開機
  • B) 執行 mount -a
  • C) 執行 systemctl restart autofs
  • D) 不需任何動作，變更會自動生效
解答：C) 執行 systemctl restart autofs
修改 AutoFS 設定檔後，務必重新啟動 autofs 服務： sudo systemctl restart autofs。雖然也可以使用 reload，但執行 restart 更為穩妥。 可使用 systemctl status autofs 確認服務狀態。

第 5 題：哪個指令可以查看 NFS 伺服器所匯出的共用目錄？

  • A) nfs-list server.example.com
  • B) showmount -e server.example.com
  • C) exportfs -v
  • D) mount | grep nfs
解答：B) showmount -e server.example.com
showmount -e 用於從用戶端查詢 NFS 伺服器匯出的共用清單； exportfs -v 則是在 NFS 伺服器端執行以檢視其匯出設定； mount | grep nfs 則用於檢視本機目前已掛載的 NFS 共用目錄。

第 6 題：間接對應設定為 "/shares /etc/auto.data"，其中的 "docs" 鍵值會掛載到哪個路徑？

  • A) /docs
  • B) /shares
  • C) /shares/docs
  • D) /etc/auto.data/docs
解答：C) /shares/docs
間接對應會在主對應檔指定的父目錄下建立子目錄作為掛載點。主對應檔指定 /shares 為父目錄， 而對應檔中定義了 "docs" 鍵值，因此實際掛載路徑為 /shares/docs。 若是直接對應，則會在對應檔中直接寫入完整的絕對路徑。
