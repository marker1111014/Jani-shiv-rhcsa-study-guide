執行容器 (Podman)

精通使用 Podman 進行容器管理。學習如何以無根（Rootless）使用者身分搜尋、拉取、執行與管理容器， 並設定永久儲存空間（Persistent Storage）及與 systemd 整合以實現開機自動啟動。

🎯 Podman 簡介

Podman 是一款無守護程式（Daemonless）的 OCI 標準容器引擎。它與 Docker 指令高度相容， 且預設支援以無根（Rootless）權限執行容器，大幅提升了系統安全性。

Podman vs Docker

特性 Podman Docker
守護程式 (Daemon) 不需背景守護程式 需執行 dockerd 背景程式
Root 權限 預設支援無根（Rootless）執行 預設需具備 root 權限
Systemd 原生整合 systemd 單元產生 需搭配額外工具設定
Pods 支援 原生支援 Pod 概念 需透過 Compose 或 Swarm

安裝 Podman

# 安裝 podman
sudo dnf install -y podman

# 安裝額外輔助工具
sudo dnf install -y podman-docker  # 提供 docker 指令相容性
sudo dnf install -y buildah         # 容器映像檔建置工具
sudo dnf install -y skopeo          # 映像檔檢視與搬移工具

# 驗證安裝結果
podman --version
podman info

映像檔倉庫（Registry）設定

# 檢視已設定的映像檔倉庫
cat /etc/containers/registries.conf

# 常見的公開映像檔倉庫
# registry.access.redhat.com (Red Hat 官方倉庫)
# docker.io (Docker Hub)
# quay.io (Red Hat Quay)

# 搜尋映像檔
podman search nginx
podman search --limit 5 httpd

# 搜尋指定倉庫中的映像檔
podman search quay.io/nginx
💡 提示：無根容器（Rootless Containers）

Podman 可由一般使用者直接執行而不需 root 權限。一般使用者的容器資料儲存於 ~/.local/share/containers，而 root 容器（sudo podman）則儲存於 /var/lib/containers，兩者完全隔離獨立！

💿 管理映像檔

容器映像檔（Container Images）是用來建立容器的唯讀範本。

拉取（Pull）映像檔

# 拉取最新版本映像檔
podman pull nginx
podman pull docker.io/library/nginx

# 拉取指定版本標籤（Tag）
podman pull nginx:1.24
podman pull registry.access.redhat.com/ubi9/ubi:latest

# 從特定倉庫拉取映像檔
podman pull quay.io/podman/hello

# 驗證已下載的映像檔
podman images

列出與檢視映像檔

# 列出所有本機映像檔
podman images

# 自訂輸出格式列出映像檔
podman images --format "{{.Repository}}:{{.Tag}}"

# 顯示映像檔詳細中繼資料
podman inspect nginx

# 顯示映像檔建置層（Layers）歷史紀錄
podman history nginx

# 顯示映像檔大小表格
podman images --format "table {{.Repository}}\t{{.Tag}}\t{{.Size}}"

移除映像檔

# 移除指定的映像檔
podman rmi nginx

# 依據映像檔 ID 移除
podman rmi 12345678

# 清除所有未使用的映像檔
podman image prune

# 移除本機所有映像檔（操作前請謹慎確認！）
podman rmi --all

標記（Tagging）映像檔

# 為映像檔建立新標籤
podman tag nginx:latest mynginx:v1

# 為私有倉庫建立標籤
podman tag nginx localhost:5000/mynginx:v1

# 列出所有映像檔與標籤
podman images
📘 注意：映像檔完整命名格式

完整格式：registry/namespace/repository:tag
範例：quay.io/podman/hello:latest
預設倉庫：docker.io
預設標籤：latest

🐳 執行容器

基本容器操作

# 執行容器（互動式終端機模式）
podman run -it ubi9 /bin/bash

# 執行容器（背景分離模式 Detached）
podman run -d nginx

# 指定自訂容器名稱
podman run -d --name webserver nginx

# 搭配連接埠對應執行容器
podman run -d -p 8080:80 --name web nginx

# 傳入環境變數執行容器
podman run -d -e MYSQL_ROOT_PASSWORD=secret mysql

# 執行完畢離開後自動刪除容器
podman run --rm -it ubi9 /bin/bash

管理執行中的容器

# 列出目前執行中的容器
podman ps

# 列出所有容器（包含已停止的容器）
podman ps -a

# 顯示容器詳細資訊
podman inspect webserver

# 檢視容器輸出日誌
podman logs webserver
podman logs -f webserver  # 即時追蹤日誌輸出

# 查看容器內執行的程序
podman top webserver

# 查看容器即時資源使用率
podman stats webserver

容器生命週期管理

# 停止容器
podman stop webserver

# 啟動已停止的容器
podman start webserver

# 重新啟動容器
podman restart webserver

# 強制終止容器（Kill）
podman kill webserver

# 暫停容器
podman pause webserver

# 恢復暫停中的容器
podman unpause webserver

# 移除容器
podman rm webserver

# 強制移除執行中的容器
podman rm -f webserver

在容器內執行指令

# 在執行中的容器內執行指定指令
podman exec webserver ls /usr/share/nginx/html

# 在執行中的容器內開啟互動式 Shell
podman exec -it webserver /bin/bash

# 以指定使用者身分執行指令
podman exec -u nginx webserver whoami

# 帶入環境變數執行指令
podman exec -e VAR=value webserver env

連接埠對應（Port Mapping）

參數格式 說明 範例
-p HOST:CONTAINER 將主機連接埠對應至容器內部連接埠 -p 8080:80
-p IP:HOST:CONTAINER 繫結至主機指定的 IP 位址 -p 127.0.0.1:8080:80
-p CONTAINER 隨機分配一個主機連接埠 -p 80
-P 公開並隨機對應映像檔暴露的所有連接埠 -P

操作步驟：執行 Nginx 網頁伺服器容器

  1. 拉取 nginx 映像檔： 
    podman pull nginx
  2. 啟動容器並設定連接埠對應： 
    podman run -d --name webserver -p 8080:80 nginx
  3. 驗證容器是否正常運作： 
    podman ps
  4. 檢查容器日誌： 
    podman logs webserver
  5. 測試網頁伺服器回應： 
    curl http://localhost:8080
  6. 停止並移除容器： 
    podman stop webserver
podman rm webserver

💾 永久儲存空間

預設情況下，容器內的資料屬於暫時性（Ephemeral），容器刪除後資料就會遺失。若需保留資料，請使用資料卷（Volumes）或繫結掛載（Bind Mounts）。

儲存卷類型

類型 說明 適用場景
繫結掛載 (Bind Mount) 將主機目錄直接掛載至容器內 開發測試、掛載設定檔與靜態網頁資料
資料卷 (Volume) 由 Podman 管理的儲存空間 資料庫儲存、永久化應用程式資料

繫結掛載 (Bind Mounts)

# 建立主機端目錄
mkdir -p ~/web-content

# 搭配繫結掛載執行容器
podman run -d --name web \
  -v ~/web-content:/usr/share/nginx/html:Z \
  -p 8080:80 nginx

# :Z 會自動設定專屬的 SELinux 脈絡標籤（在 RHEL 上極為重要！）
# 若未加上 :Z，SELinux 將會阻擋容器存取主機目錄

# 唯讀繫結掛載
podman run -d --name web \
  -v ~/web-content:/usr/share/nginx/html:ro,Z \
  nginx

# 同時掛載多個目錄
podman run -d --name web \
  -v ~/web-content:/usr/share/nginx/html:Z \
  -v ~/web-logs:/var/log/nginx:Z \
  nginx

具名資料卷 (Named Volumes)

# 建立具名資料卷
podman volume create mysql-data

# 列出所有資料卷
podman volume ls

# 檢視資料卷詳細資訊
podman volume inspect mysql-data

# 搭配具名資料卷執行容器
podman run -d --name db \
  -v mysql-data:/var/lib/mysql \
  -e MYSQL_ROOT_PASSWORD=secret \
  mysql

# 移除資料卷
podman volume rm mysql-data

# 清除所有未使用的資料卷
podman volume prune

資料卷的 SELinux 脈絡選項

選項 說明
:z 共用內容標籤（允許複數個容器共同存取同一個目錄）
:Z 私有內容標籤（僅限單一容器專屬存取）
⚠️ SELinux 與資料卷掛載

在啟用 SELinux Enforcing 模式的 RHEL 系統上，掛載主機目錄時請「務必」加上 :Z 或 :z！ 若未加上此標籤，容器將會因權限不足而無法讀取或寫入檔案。單一容器專用請用 :Z，多容器共用則用 :z。

操作步驟：設定永久化網站內容

  1. 建立網頁內容目錄與測試檔案： 
    mkdir -p ~/webdata
echo "&lt;h1&gt;Hello Podman&lt;/h1&gt;" > ~/webdata/index.html
  2. 搭配繫結掛載執行 nginx 容器： 
    podman run -d --name myweb \
  -v ~/webdata:/usr/share/nginx/html:Z \
  -p 8080:80 nginx
  3. 測試網頁存取： 
    curl http://localhost:8080
  4. 更新主機端檔案內容（容器內會即時反映變更）： 
    echo "&lt;h1&gt;Updated!&lt;/h1&gt;" > ~/webdata/index.html
curl http://localhost:8080
  5. 刪除容器（主機上的資料依然完整保留）： 
    podman rm -f myweb
ls ~/webdata  # 檔案依然存在！

⚙️ Systemd 整合

將容器與 systemd 服務整合，實現開機自動啟動並以系統服務的方式統一管理。

產生 Systemd 單元檔

# 先建立並執行容器
podman run -d --name webserver -p 8080:80 nginx

# 產生 systemd 單元檔
podman generate systemd --name webserver --files --new

# 這會建立檔案：container-webserver.service

# 移動至使用者的 systemd 服務目錄
mkdir -p ~/.config/systemd/user
mv container-webserver.service ~/.config/systemd/user/

# 重新載入使用者 systemd 設定
systemctl --user daemon-reload

# 設定登入時自動啟用
systemctl --user enable container-webserver.service

# 啟動服務
systemctl --user start container-webserver.service

# 檢查服務狀態
systemctl --user status container-webserver.service

常用產生參數選項

選項 說明
--new 每次啟動服務時建立新容器（而非重複使用舊容器）
--files 將單元檔內容輸出成檔案（而非僅印在標準輸出）
--name 使用容器名稱而非容器 ID 作為識別
--restart-policy 設定重新啟動策略（always、on-failure、no）

啟用使用者常駐（Linger）模式（Rootless）

# 允許使用者的容器在未登入的情況下也能於開機時自動啟動
sudo loginctl enable-linger $(whoami)

# 檢查 Linger 啟用狀態
loginctl show-user $(whoami) | grep Linger

# 現在即使使用者尚未登入，容器也會在系統開機時自動啟動

系統級容器 vs 使用者級容器

比較項目 系統級 (Root) 使用者級 (Rootless)
執行指令 sudo podman podman
Systemd 指令 systemctl (root) systemctl --user
單元檔路徑 /etc/systemd/system/ ~/.config/systemd/user/
連接埠限制 可使用 1-1024 特權連接埠 必須使用 1024 以上的連接埠

操作步驟：將容器設定為開機自動啟動的 Systemd 服務

  1. 建立並測試容器： 
    podman run -d --name myapp -p 8080:80 nginx
  2. 產生 systemd 單元檔： 
    cd ~
podman generate systemd --name myapp --files --new
  3. 停止並移除原本手動建立的容器： 
    podman stop myapp
podman rm myapp
  4. 安裝 systemd 單元檔： 
    mkdir -p ~/.config/systemd/user
mv container-myapp.service ~/.config/systemd/user/
systemctl --user daemon-reload
  5. 啟用 Linger（確保開機即可啟動）： 
    sudo loginctl enable-linger $(whoami)
  6. 啟用並立即啟動服務： 
    systemctl --user enable --now container-myapp.service
  7. 驗證服務運作狀態： 
    systemctl --user status container-myapp.service
curl http://localhost:8080
  8. 測試重開機後的持久性： 
    sudo reboot
# 重新開機後檢查狀態
systemctl --user status container-myapp.service

📝 練習題

第 1 題：如何讓容器在背景執行？

  • A) podman run -b nginx
  • B) podman run -d nginx
  • C) podman run --background nginx
  • D) podman start nginx
解答：B) podman run -d nginx
-d（detached）參數會讓容器在背景執行並回傳容器 ID。 可使用 podman ps 查看執行中的容器。-it 則是用於啟動前景互動式終端機。

第 2 題：在繫結掛載（Bind Mount）時，哪個 SELinux 選項最為關鍵？

  • A) -v /host:/container
  • B) -v /host:/container:Z
  • C) -v /host:/container:selinux
  • D) -v /host:/container:secure
解答：B) -v /host:/container:Z
:Z 會為單一容器設定專屬的 SELinux 脈絡標籤；若未加上，SELinux 將會阻擋容器存取。 若多個容器需要共用同一目錄，則使用小寫的 :z。這在啟用 SELinux Enforcing 的 RHEL 系統上極為關鍵！

第 3 題：如何將主機連接埠 8080 對應至容器連接埠 80？

  • A) -p 80:8080
  • B) -p 8080:80
  • C) --port 8080:80
  • D) --expose 8080:80
解答：B) -p 8080:80
對應格式為 -p HOST:CONTAINER。透過 http://host:8080 連線時， 流量會被轉發至容器內的 80 埠。請注意，Rootless 使用者在主機端只能繫結 1024 以上的連接埠。

第 4 題：哪個指令可以產生容器的 systemd 單元檔？

  • A) podman systemd --name myapp --files
  • B) podman generate systemd --name myapp --files --new
  • C) podman create-service myapp
  • D) systemctl generate myapp
解答：B)
podman generate systemd --name myapp --files --new。 --new 表示每次啟動服務時都會建立全新容器，--files 則會輸出為設定檔。 產生後將檔案移至 ~/.config/systemd/user/ 並執行 systemctl --user daemon-reload。

第 5 題：如何設定無根（Rootless）容器於系統開機時自動啟動？

  • A) systemctl --user enable container-name
  • B) sudo loginctl enable-linger $USER
  • C) podman enable container-name
  • D) A 與 B 皆需執行
解答：D) A 與 B 皆需執行
兩個步驟缺一不可：必須先執行 systemctl --user enable container-name 啟用服務， 「並且」執行 sudo loginctl enable-linger $USER 允許使用者服務在未登入時執行。 若未啟用 linger，容器只有在該使用者登入系統時才會啟動。

第 6 題：無根（Rootless）容器的映像檔儲存在哪個路徑？

  • A) /var/lib/containers
  • B) ~/.local/share/containers
  • C) ~/podman/images
  • D) /home/containers
解答：B) ~/.local/share/containers
無根（一般使用者）容器資料儲存在 ~/.local/share/containers， 而 root 容器則儲存在 /var/lib/containers。兩者完全分開管理， 一般使用者與 root 可以各自擁有同名的映像檔而互不衝突。
