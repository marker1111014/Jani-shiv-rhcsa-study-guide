🧪 實戰模擬情境

情境 1：建立受限存取權限的使用者帳號

任務需求：建立使用者「developer」，須符合以下條件：

  • 家目錄為 /home/developer
  • 預設 Shell 為 /bin/bash
  • 屬於「devteam」附屬群組
  • 密碼每 60 天過期
  • 僅具備使用 sudo 重新啟動 httpd 服務的權限
# 建立群組
sudo groupadd devteam

# 建立使用者
sudo useradd -m -s /bin/bash -G devteam developer

# 設定密碼
sudo passwd developer

# 設定密碼過期天數
sudo chage -M 60 developer

# 設定 sudo 權限
sudo visudo
# 新增以下設定行：
developer ALL=(ALL) /usr/bin/systemctl restart httpd

# 驗證設定
id developer
sudo -l -U developer

情境 2：設定永久儲存空間

任務需求：為 /data 建立一個 2GB 的邏輯磁區：

  • 使用磁碟 /dev/sdb
  • 磁區群組名稱：vg_data
  • 邏輯磁區名稱：lv_data
  • 檔案系統格式：XFS
  • 永久掛載於 /data
# 建立實體磁區
sudo pvcreate /dev/sdb

# 建立磁區群組
sudo vgcreate vg_data /dev/sdb

# 建立邏輯磁區
sudo lvcreate -n lv_data -L 2G vg_data

# 建立檔案系統
sudo mkfs.xfs /dev/vg_data/lv_data

# 建立掛載點目錄
sudo mkdir /data

# 寫入 /etc/fstab
echo '/dev/vg_data/lv_data /data xfs defaults 0 0' | sudo tee -a /etc/fstab

# 進行掛載
sudo mount -a

# 驗證結果
df -h /data
lsblk

情境 3：設定具備防火牆限制的網頁伺服器

任務需求：架設 httpd 服務並設定僅允許來自 192.168.1.0/24 網段的連線存取：

# 安裝 httpd
sudo dnf install -y httpd

# 啟用並立即啟動服務
sudo systemctl enable --now httpd

# 建立測試網頁
echo "&lt;h1&gt;Test Page&lt;/h1&gt;" | sudo tee /var/www/html/index.html

# 確認 SELinux 脈絡（必要時執行）
sudo restorecon -Rv /var/www/html

# 防火牆 - 僅允許特定子網路存取 HTTP
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="192.168.1.0/24" service name="http" accept'
sudo firewall-cmd --reload

# 驗證設定
curl http://localhost
sudo firewall-cmd --list-all

情境 4：設定容器於開機時自動啟動

任務需求：執行 nginx 容器並設定其透過 systemd 在開機時自動啟動：

# 拉取映像檔
podman pull nginx

# 執行容器
podman run -d --name webserver -p 8080:80 nginx

# 測試存取
curl http://localhost:8080

# 產生 systemd 單元檔
podman generate systemd --name webserver --files --new

# 停止並移除原本的容器
podman stop webserver
podman rm webserver

# 安裝 systemd 服務檔
mkdir -p ~/.config/systemd/user
mv container-webserver.service ~/.config/systemd/user/

# 重新載入 systemd
systemctl --user daemon-reload

# 啟用 linger 常駐模式
sudo loginctl enable-linger $USER

# 啟用並立即啟動服務
systemctl --user enable --now container-webserver.service

# 驗證結果
systemctl --user status container-webserver.service
curl http://localhost:8080

情境 5：排除 SELinux 存取拒絕錯誤

任務需求：Apache 無法存取 /web/index.html 檔案：

# 檢查 SELinux 運作模式
getenforce

# 檢查檔案的 SELinux 脈絡
ls -Z /web/index.html

# 查詢拒絕紀錄
sudo ausearch -m AVC -ts recent
sudo journalctl -t setroubleshoot

# 修正永久安全脈絡並套用
sudo semanage fcontext -a -t httpd_sys_content_t "/web(/.*)?"
sudo restorecon -Rv /web

# 驗證修正結果
ls -Z /web
curl http://localhost/index.html

# 替代方式：使用疑難排解分析工具
sudo sealert -a /var/log/audit/audit.log

🔧 疑難排解指南

開機問題

問題狀況 解決方案
忘記 root 密碼 開機時進入 rd.break，執行 mount -o remount,rw /sysroot、chroot /sysroot、passwd，並建立 touch /.autorelabel
/etc/fstab 設定錯誤 開機進入 emergency.target，修正 /etc/fstab，執行 systemctl daemon-reload 與 mount -a
SELinux 導致無法開機 於 GRUB 核心參數列加上 selinux=0（暫時停用）或 enforcing=0（寬容模式）

網路問題

問題狀況 檢查指令 修復方式
沒有 IP 位址 ip addr, nmcli con show nmcli con up connection
無法 ping 通預設閘道 ip route nmcli con mod con ipv4.gateway x.x.x.x
DNS 解析失效 cat /etc/resolv.conf nmcli con mod con ipv4.dns "8.8.8.8"
連接埠遭阻擋 firewall-cmd --list-all firewall-cmd --add-port=X/tcp --permanent

儲存空間問題

問題狀況 解決方案
磁碟空間已滿 df -h, du -sh /*, lvextend -r -L +5G /dev/vg/lv
掛載失敗 使用 blkid 確認 UUID、檢查 /etc/fstab 語法、執行 mount -a 測試
存取遭拒 (Permission denied) 檢查 ls -ld、chmod、chown、getfacl、ls -Z 與 restorecon

服務問題

# 服務無法啟動
systemctl status service.service
journalctl -u service.service -n 50
journalctl -xe

# 服務未設定開機自動啟動
systemctl is-enabled service
systemctl enable service

# 連接埠已被其他程序佔用
ss -tulpn | grep :80
kill -9 PID

💡 考試技巧與策略

⏱️ 時間管理策略

考試時間：3 小時（180 分鐘）
應考策略：
• 先快速瀏覽所有題目（5-10 分鐘）
• 先完成簡單題型建立信心（30 分鐘）
• 接著處理中等難度題目（60 分鐘）
• 集中精力攻克複雜情境題（60 分鐘）
• 最後全面檢查並驗證所有設定（20-30 分鐘）
• 千萬別在單一題目卡關！先標記跳過，之後再回頭處理

開始作答前

  • ✅ 仔細閱讀題目說明與每一項限制條件
  • ✅ 記錄題目提供的伺服器主機名稱與 IP 位址
  • ✅ 確認所有考試機器的網路連線暢通
  • ✅ 確認 sudo / root 管理員權限可正常使用
  • ✅ 確認 SELinux 處於 Enforcing 模式（切勿關閉它！）

作答過程中

  • ✅ 善用 man 手冊查詢語法（man -k keyword）
  • ✅ 參考系統範例設定檔：/usr/share/doc/
  • ✅ 每完成一項任務立即驗證（systemctl status、mount -a 等）
  • ✅ 確保所有設定皆為永久生效（/etc/fstab、systemctl enable）
  • ✅ 針對重要任務測試重新開機後設定是否依然有效
  • ✅ 修改任何 systemd 單元檔後務必執行 systemctl daemon-reload
  • ✅ 修改防火牆永久規則後務必執行 firewall-cmd --reload
  • ✅ 在 SELinux 環境掛載容器資料卷時別忘了加上 :Z

應避免的常見錯誤

常見錯誤 預防方式
忘記加上 --permanent 設定防火牆 養成先加 --permanent 再執行 --reload 的習慣
忘記設定服務開機自動啟動 統一使用 systemctl enable --now
/etc/fstab 打字錯誤導致無法開機 重開機前務必先執行 mount -a 驗證
設定了錯誤的 SELinux 安全脈絡 使用 semanage fcontext 搭配 restorecon，不要只用 chcon
NFS 掛載漏掉 _netdev 選項 凡是在 fstab 設定網路掛載一律加上 _netdev
容器資料卷掛載忘記加 :Z 在啟用 SELinux 的系統上執行繫結掛載務必加上 :Z

# 使用者帳號
id username
sudo -l -U username

# SELinux
getenforce  # 應為 Enforcing
ls -Z /path
ps -Z | grep service

# 容器服務
podman ps
systemctl --user status container-*
loginctl show-user $USER | grep Linger
⚠️ 務必確認重開機後仍維持生效

以下設定「必須」在系統重新開機後依然正常運作：
• 系統服務：已執行 systemctl enable
• 磁碟掛載：/etc/fstab 內容與選項完全正確
• 網路設定：nmcli 組態預設即會永久保存
• 防火牆規則：必須搭配 --permanent 參數
• 容器服務：完成 systemd 單元檔設定並啟用 loginctl enable-linger
• AutoFS：已執行 systemctl enable autofs

如果考試時間充裕，強烈建議在交卷前親自執行一次重開機來驗證所有關鍵設定！

第 1 題：使用 useradd 建立使用者帳號後，通常還需要進行什麼設定才能登入？

  • A) 不需任何設定即可直接使用
  • B) 使用 passwd 設定密碼
  • C) 使用 -m 建立家目錄
  • D) 需要同時執行 B 並定義 Shell
解答：B) 使用 passwd 設定密碼
使用者必須先設定密碼才能正常登入。家目錄則視需求而定（可用 -m 建立）， 預設 Shell 會讀取自 /etc/default/useradd（通常為 /bin/bash）。 標準做法：useradd -m user; passwd user

第 2 題：如何讓 LVM 邏輯磁區在系統開機時自動永久掛載？

  • A) 加入設定至 /etc/fstab
  • B) 執行 systemctl enable lvm
  • C) 在開機時執行 vgchange -ay
  • D) 不需任何操作，系統會自動掛載
解答：A) 加入設定至 /etc/fstab
LVM 邏輯磁區在開機時會自動啟用，但「掛載」動作仍必須透過 /etc/fstab 設定檔完成。 例如：/dev/vg/lv /mnt xfs defaults 0 0。重新開機前別忘了先用 mount -a 測試！

第 3 題：使用 semanage fcontext 設定完永久 SELinux 安全脈絡後，下一步應該做什麼？

  • A) 重新啟動系統
  • B) 執行 restorecon -Rv /path
  • C) 先執行 setenforce 0 再執行 setenforce 1
  • D) 不需任何操作，設定會自動套用
解答：B) 執行 restorecon -Rv /path
semanage fcontext 僅負責將規則寫入永久原則資料庫，必須再執行 restorecon 才會真正將標籤套用到檔案上。完整流程如下：
semanage fcontext -a -t type "/path(/.*)?"
restorecon -Rv /path

第 4 題：為容器掛載主機端永久儲存目錄時，需要加上什麼標籤參數？

  • A) -v /host:/container
  • B) -v /host:/container:Z
  • C) --mount /host:/container
  • D) --storage /host:/container
解答：B) -v /host:/container:Z
在 RHEL 上，:Z 會為目錄設定正確的 SELinux 脈絡標籤，否則容器將無法存取其中的檔案。 範例：podman run -d -v ~/data:/data:Z nginx。 多容器共用時使用 :z，單一容器專用時使用 :Z。

第 5 題：如何擴充 LVM 邏輯磁區上的 XFS 檔案系統容量？

  • A) lvextend -L +5G /dev/vg/lv; xfs_growfs /mnt
  • B) lvextend -r -L +5G /dev/vg/lv
  • C) lvextend -L +5G /dev/vg/lv; resize2fs /dev/vg/lv
  • D) A 與 B 皆可
解答：D) A 與 B 皆可
方法 1：lvextend -L +5G /dev/vg/lv; xfs_growfs /mnt
方法 2：lvextend -r -L +5G /dev/vg/lv（自動一併調整檔案系統大小）
注意：ext4 使用 resize2fs，而 XFS 則使用 xfs_growfs。

第 6 題：設定無根（Rootless）容器在開機時自動啟動，哪些步驟最為關鍵？

  • A) systemctl --user enable container-name
  • B) loginctl enable-linger $USER
  • C) podman generate systemd
  • D) 以上皆是
解答：D) 以上皆是
所有步驟皆不可或缺：產生 systemd 單元檔、移動至 ~/.config/systemd/user/、 啟用服務，以及啟用 linger 常駐模式。若未啟用 linger，使用者服務只會在登入後執行。 loginctl enable-linger $USER 是考場上最容易被遺忘的關鍵步驟！
