控制檔案存取權限

精通 Linux 檔案權限與擁有權設定。學習使用 chmod、chown、umask 以及存取控制清單（ACLs）， 保護檔案安全並實作細粒度的存取控制原則。

📋 本章目錄

  • 簡介

  • 練習題

🎯 簡介

檔案權限是 Linux 安全性的核心基礎。每個檔案與目錄都有所屬的擁有者、群組以及一組權限， 用以決定誰可以讀取、寫入或執行該項目。了解並妥善管理這些權限，對於維持系統安全性與正確的存取控制至關重要。

在本章中，您將學會：

  • 使用符號表示法與八進位表示法解讀並修改檔案權限
  • 使用 chown 與 chgrp 變更檔案與目錄的擁有權
  • 在進階情境中套用特殊權限（SUID、SGID、Sticky Bit）
  • 使用 umask 設定預設權限
  • 透過存取控制清單（ACLs）實作細粒度的存取控制
  • 排除與權限相關的常見問題
📘 注意

在 RHEL 系統上，檔案權限會與 SELinux 協同運作。兩者皆必須正確設定，才能確保完整的存取控制正常生效。

🔒 檔案權限

認識權限類型

Linux 使用三種權限類型，並套用至三種不同的使用者類別：

權限 符號 八進位 對檔案的作用 對目錄的作用
讀取（Read） r 4 檢視檔案內容 列出目錄內容
寫入（Write） w 2 修改檔案內容 在目錄中建立／刪除檔案
執行（Execute） x 1 將檔案作為程式執行 進入目錄（cd）

解讀權限字串

當您執行 ls -l 時，將會看到如下的權限資訊：

-rwxr-xr--. 1 student developers 1234 Nov 14 10:30 script.sh
│││││││││││
│││││││││└└─ 其他使用者權限 (r--)
││││││└┴┴─── 群組權限 (r-x)
│││└┴┴───── 擁有者權限 (rwx)
│└───────── 檔案類型指示符
└────────── 具備 SELinux 安全脈絡（句點）

檔案類型指示符

  • - 一般檔案（Regular file）
  • d 目錄（Directory）
  • l 符號連結（Symbolic link）
  • c 字元裝置（Character device）
  • b 區塊裝置（Block device）
  • s 通訊端（Socket）
  • p 具名管線（Named pipe，FIFO）

chmod - 變更權限模式（Change Mode）

符號表示法

使用英文字母與運算子來修改權限：

# 為擁有者（user）新增執行權限
chmod u+x file.sh

# 移除群組的寫入權限
chmod g-w file.txt

# 精確設定其他使用者的權限
chmod o=r file.txt

# 為所有類別（擁有者、群組、其他人）新增讀取權限
chmod a+r file.txt

# 一次套用多項權限變更
chmod u+x,g-w,o-r file.sh

# 遞迴變更目錄內所有項目的權限
chmod -R u+w directory/

符號表示法語法：

  • 對象（Who）： u（使用者／擁有者）、g（群組）、o（其他人）、a（全部）
  • 運算子（Operator）： +（新增）、-（移除）、=（精確設定）
  • 權限（Permission）： r（讀取）、w（寫入）、x（執行）

八進位（數字）表示法

使用三位數的數字，每位數依序代表擁有者、群組與其他使用者：

# 常見權限設定組合
chmod 755 script.sh    # rwxr-xr-x（擁有者：完整權限；群組／其他人：讀取+執行）
chmod 644 file.txt     # rw-r--r--（擁有者：讀取+寫入；其他人：唯讀）
chmod 600 secret.txt   # rw-------（擁有者：讀取+寫入；其他人：無權限）
chmod 777 public/      # rwxrwxrwx（所有人皆具備完整權限 - 極度危險！）
chmod 700 private/     # rwx------（擁有者：完整存取權限；其他人：無權限）
chmod 640 config.conf  # rw-r-----（擁有者：讀取+寫入；群組：唯讀；其他人：無權限）

計算八進位數值

# 各項權限對應的數值：
# r (讀取)    = 4
# w (寫入)    = 2
# x (執行)    = 1

# 將每個使用者類別的權限數值相加：
# rwx = 4+2+1 = 7
# rw- = 4+2+0 = 6
# r-x = 4+0+1 = 5
# r-- = 4+0+0 = 4
# -wx = 0+2+1 = 3
# -w- = 0+2+0 = 2
# --x = 0+0+1 = 1
# --- = 0+0+0 = 0
💡 提示

進行漸進式微調時適合使用符號表示法（chmod g+w）；當需要一次性設定完整權限組合時，則適合使用八進位表示法（chmod 644）。

常見權限情境

八進位 符號表示法 使用情境
755 rwxr-xr-x 可執行腳本、一般目錄
644 rw-r--r-- 一般檔案、純文字檔案
600 rw------- 私密檔案、SSH 私鑰
700 rwx------ 私密腳本、.ssh 目錄
775 rwxrwxr-x 團隊共用目錄

👤 檔案擁有權

每個檔案與目錄都具備兩種擁有者身份：

  • 使用者（擁有者，Owner）：擁有該檔案的使用者帳號
  • 群組（Group）：擁有該檔案的群組

chown - 變更擁有者

# 僅變更擁有者
sudo chown john file.txt

# 同時變更擁有者與群組
sudo chown john:developers file.txt

# 僅變更群組（使用冒號開頭）
sudo chown :developers file.txt

# 遞迴變更目錄內所有項目的擁有權
sudo chown -R john:developers directory/

# 參照範本檔案設定擁有權
sudo chown --reference=template.txt newfile.txt

# 顯示詳細輸出
sudo chown -v john file.txt

# 僅當目前擁有者符合指定條件時才變更為新擁有者
sudo chown --from=alice:users john:developers file.txt
⚠️ 警告

只有 root 能夠變更檔案的擁有者。一般使用者無法將自己的檔案轉讓給其他使用者，這是為了防止安全性風險與規避磁碟配額（Quota）限制。

chgrp - 變更群組

# 變更群組
sudo chgrp developers file.txt

# 遞迴變更群組
sudo chgrp -R developers project/

# 顯示詳細輸出
sudo chgrp -v developers *.txt

# 參照範本檔案設定群組
sudo chgrp --reference=template.txt newfile.txt

操作步驟：設定共用專案目錄

  1. 建立專案目錄： 
    sudo mkdir /shared/projects
  2. 為團隊建立群組： 
    sudo groupadd developers
  3. 將使用者加入該群組： 
    sudo usermod -aG developers alice
sudo usermod -aG developers bob
sudo usermod -aG developers charlie
  4. 設定目錄的群組擁有權： 
    sudo chgrp developers /shared/projects
  5. 設定適當權限（含 SGID 位元）： 
    sudo chmod 2775 /shared/projects
  6. 驗證設定結果： 
    ls -ld /shared/projects
# 應顯示為：drwxrwsr-x. 2 root developers ...

⭐ 特殊權限

除了基本的讀取、寫入與執行權限之外，Linux 還支援三種特殊權限位元：

1. SUID（Set User ID）- 位元值 4

當設定在可執行檔上時，該程式會以檔案擁有者的權限執行，而非執行該程式的使用者權限。

# 使用符號表示法設定 SUID
sudo chmod u+s /usr/local/bin/program

# 使用八進位表示法設定 SUID（前綴數字為 4）
sudo chmod 4755 /usr/local/bin/program

# 範例：passwd 指令使用了 SUID
ls -l /usr/bin/passwd
-rwsr-xr-x. 1 root root 27856 /usr/bin/passwd
#   ↑ 注意這裡顯示 's' 而非 'x'

常見應用情境：

  • passwd - 允許一般使用者變更自己的密碼（因修改 /etc/shadow 需要 root 權限）
  • ping - 需要 root 權限才能建立原始網路通訊端（Raw Socket）
  • sudo - 以 root 身分執行指令
⚠️ 安全警告

如果擁有者為 root 的執行檔設定了 SUID，一旦該程式存在漏洞，就會造成嚴重的安全風險。請定期稽核系統中的 SUID 檔案：

sudo find / -perm -4000 -type f -ls 2>/dev/null

2. SGID（Set Group ID）- 位元值 2

在可執行檔上：程序會以該檔案所屬群組的權限執行。

在目錄上：在該目錄中新建立的檔案，會自動繼承此目錄的群組擁有權（而非建立者的主要群組）。

# 在目錄上設定 SGID（最常見的用法）
sudo chmod g+s /shared/projects
sudo chmod 2775 /shared/projects

# 在可執行檔上設定 SGID
sudo chmod g+s /usr/local/bin/tool

# 驗證目錄上的 SGID 設定
ls -ld /shared/projects
drwxrwsr-x. 2 root developers 4096 /shared/projects
#      ↑ 注意群組執行權限位置上的 's'

為什麼要在目錄上使用 SGID：

  • 確保共用目錄中的所有檔案都具有一致的群組擁有權
  • 讓團隊成員協作時不會遇到權限不足的問題
  • 新建立的檔案會自動歸屬於專案群組

3. 黏滯位元（Sticky Bit）- 位元值 1

當設定在目錄上時，只有檔案擁有者、目錄擁有者或 root 才能刪除或重新命名該目錄內的檔案。

# 使用符號表示法設定 Sticky Bit
sudo chmod o+t /shared/public

# 使用八進位表示法設定 Sticky Bit（前綴數字為 1）
sudo chmod 1777 /shared/public

# 範例：/tmp 目錄使用了 Sticky Bit
ls -ld /tmp
drwxrwxrwt. 15 root root 4096 /tmp
#        ↑ 注意其他使用者執行權限位置上的 't'

常見應用情境：

  • /tmp - 所有使用者皆可建立檔案，但無法刪除他人的檔案
  • /var/tmp - 與 /tmp 具備相同的保護機制
  • 不允許使用者刪除彼此檔案的共用上傳目錄

特殊權限總結

權限 符號表示法 八進位 顯示方式 效果
SUID u+s 4 擁有者執行欄位顯示 s 或 S 以檔案擁有者身分執行
SGID g+s 2 群組執行欄位顯示 s 或 S 以檔案群組身分執行／繼承目錄群組
Sticky o+t 1 其他人執行欄位顯示 t 或 T 限制刪除與重新命名權限
📘 注意：大寫與小寫的差異

小寫（s、t）：已設定特殊權限，且原本的執行權限（x）也已開啟
大寫（S、T）：已設定特殊權限，但原本的執行權限（x）並未開啟

-rwSr--r--  # 已設定 SUID，但擁有者沒有執行權限（不常見）
drwxrwsrwx  # 已設定 SGID 且具備執行權限（正常情況）

🎭 使用 umask 設定預設權限

umask（使用者建立檔案模式遮罩）決定新建立的檔案與目錄預設會擁有哪些權限。 它的運作方式是從系統預設的最大權限中扣除（遮罩）對應的權限位元。

umask 運作原理

# 系統預設的最大權限：
# 檔案：       666 (rw-rw-rw-)  - 預設不包含執行權限
# 目錄：       777 (rwxrwxrwx)  - 完整權限

# 當 umask 為 0022 時：
# 檔案：       666 - 022 = 644 (rw-r--r--)
# 目錄：       777 - 022 = 755 (rwxr-xr-x)

檢視與設定 umask

# 檢視目前的 umask（八進位）
umask
0022

# 檢視目前的 umask（符號表示法，顯示將賦予的權限）
umask -S
u=rwx,g=rx,o=rx

# 暫時設定 umask（僅在目前工作階段生效）
umask 0027

# 使用符號表示法設定 umask
umask u=rwx,g=rx,o=

常見 umask 數值

umask 新建檔案權限 新建目錄權限 使用情境
0022 644 (rw-r--r--) 755 (rwxr-xr-x) 多數使用者的預設設定
0002 664 (rw-rw-r--) 775 (rwxrwxr-x) 群組協作開發
0077 600 (rw-------) 700 (rwx------) 最高隱私保護
0027 640 (rw-r-----) 750 (rwxr-x---) 安全的群組共享

讓 umask 設定永久生效

若要讓 umask 設定永久保留，請將其加入 Shell 的設定檔中：

# 針對個別使用者（加入 ~/.bashrc 或 ~/.bash_profile）
echo "umask 0027" >> ~/.bashrc

# 針對系統所有使用者（加入 /etc/bashrc 或 /etc/profile）
sudo vi /etc/bashrc
# 加入：umask 0027

# 重新載入設定檔
source ~/.bashrc
💡 提示

為了提升安全性，root 使用者通常會配置比一般使用者更嚴格的 umask（如 0022 或 0027）。

🎯 存取控制清單（ACLs）

存取控制清單（Access Control Lists，ACLs）提供超越傳統「擁有者／群組／其他人」權限模型的細粒度存取控制。 透過 ACL，您無需變更檔案的擁有者或擁有群組，即可直接賦予特定使用者或群組專屬權限。

何時使用 ACL

  • 需要賦予特定使用者存取權限，但不想將他們加入群組
  • 多個不同群組需要對同一個檔案擁有不同層級的存取權限
  • 超越「擁有者／群組／其他人」模型所能處理的複雜權限情境
  • 暫時授權給特定使用者存取資源

檢視 ACL - getfacl

# 檢視檔案的 ACL 設定
getfacl file.txt

# 輸出範例：
# file: file.txt
# owner: student
# group: developers
user::rw-              # 擁有者權限
user:john:r--          # 特定使用者 'john' 具備讀取權限
user:alice:rw-         # 特定使用者 'alice' 具備讀寫權限
group::r--             # 擁有群組權限
group:managers:r--     # 特定群組 'managers' 具備讀取權限
mask::rw-              # 最大有效權限遮罩
other::---             # 其他使用者權限

# 遞迴檢視目錄及其內容的 ACL
getfacl -R /project

# 透過 ls -la 識別設有 ACL 的檔案
ls -la
-rw-r--r--+ 1 student developers 1234 Nov 14 10:30 file.txt
#        ↑ 加號 (+) 表示此檔案已設定 ACL

設定 ACL - setfacl

賦予權限

# 賦予使用者 'john' 讀取權限
setfacl -m u:john:r file.txt

# 賦予使用者 'alice' 讀寫權限
setfacl -m u:alice:rw file.txt

# 賦予群組 'managers' 對目錄的讀取與執行權限
setfacl -m g:managers:rx /project

# 一次套用多筆 ACL 設定
setfacl -m u:john:rw,u:jane:r,g:team:rx file.txt

# 遞迴套用 ACL 至目錄與所有子項目
setfacl -R -m u:john:rx /project

移除權限

# 移除特定使用者的 ACL
setfacl -x u:john file.txt

# 移除特定群組的 ACL
setfacl -x g:managers file.txt

# 移除所有 ACL（還原為基本權限）
setfacl -b file.txt

# 遞迴移除所有 ACL
setfacl -R -b /project

預設 ACL（Default ACLs）

預設 ACL 套用於目錄上，並會自動被該目錄內新建的檔案與子目錄繼承：

# 為目錄中新建的檔案設定預設 ACL
setfacl -d -m g:developers:rwx /project

# 為特定使用者設定預設 ACL
setfacl -d -m u:john:rx /project

# 檢視預設 ACL
getfacl /project
# 輸出中將包含類似項目：default:user:john:r-x

# 同時設定目前的存取權限與預設 ACL
setfacl -m d:g:developers:rwx,g:developers:rwx /project

ACL 遮罩（Mask）

遮罩（Mask）定義了具名使用者與具名群組所能達到的最大有效權限：

# 設定遮罩以限制最大有效權限
setfacl -m m::rx file.txt

# 即使某個使用者在自己的 ACL 項目中擁有 rwx，
# 遮罩仍會將其有效權限限制在 r-x 以內

# 檢視實際有效權限
getfacl file.txt
user:john:rwx      #effective:r-x
#         ↑ ACL     ↑ 受遮罩限制

# 重新計算／調整遮罩權限
setfacl -m m::rwx file.txt

複製與備份 ACL

# 將 ACL 從一個檔案複製到另一個檔案
getfacl file1.txt | setfacl --set-file=- file2.txt

# 將目錄的 ACL 備份至檔案
getfacl -R /project > project_acls.txt

# 從備份檔案還原 ACL
setfacl --restore=project_acls.txt

# 複製檔案時一併保留 ACL
cp -a --preserve=all source.txt dest.txt
# 或
cp --preserve=mode,ownership,timestamps,xattr source.txt dest.txt

操作步驟：為專案目錄實作 ACL

  1. 建立專案目錄： 
    sudo mkdir /project/webapp
sudo chown root:developers /project/webapp
sudo chmod 750 /project/webapp
  2. 新增特定使用者的存取權限： 
    # 賦予經理讀取與執行權限
sudo setfacl -m u:manager:rx /project/webapp

# 賦予稽核員唯讀權限
sudo setfacl -m u:auditor:r /project/webapp
  3. 新增特定群組的存取權限： 
    # 賦予 QA 團隊讀取與執行權限
sudo setfacl -m g:qa_team:rx /project/webapp
  4. 為新建檔案設定預設 ACL： 
    # 開發人員對新建立的檔案擁有完整權限
sudo setfacl -d -m g:developers:rwx /project/webapp

# 經理對新建立的檔案擁有讀取與執行權限
sudo setfacl -d -m u:manager:rx /project/webapp
  5. 驗證設定結果： 
    getfacl /project/webapp

# 預期輸出將同時顯示目前的 ACL 與預設 ACL
  6. 建立新檔案測試繼承效果： 
    sudo -u developer touch /project/webapp/test.txt
getfacl /project/webapp/test.txt
# 應顯示從上層目錄繼承而來的 ACL

常見情境的 ACL 範例

# 情境 1：賦予約聘人員為期 1 個月的暫時存取權限
setfacl -m u:contractor:rx /data
# (專案結束後移除：setfacl -x u:contractor /data)

# 情境 2：多個團隊需要不同層級的存取權限
setfacl -m g:dev_team:rwx,g:qa_team:rx,g:managers:r /project

# 情境 3：共用目錄中所有人皆可寫入，但無法刪除他人的檔案
chmod 1777 /shared/dropbox
setfacl -m d:u::rwx,d:g::rwx,d:o::rwx /shared/dropbox

# 情境 4：讓特定使用者可讀取應用程式日誌
setfacl -m u:alice:r,u:bob:r /var/log/application.log
⚠️ 重要注意事項
  • ACL 是以延伸屬性（Extended Attributes）的形式儲存，請確認檔案系統支援該功能（多數現代檔案系統皆預設支援）
  • 備份工具必須支援保留 ACL（例如使用 tar --acls 或 rsync -A）
  • ls -l 輸出中的 + 符號表示該項目已套用 ACL
  • ACL 是與 SELinux 搭配疊加運作，而非取代 SELinux

📝 練習題

第 1 題：chmod 755 會設定什麼樣的權限？

  • A) rwxr-xr-x（擁有者：完整權限，群組：r-x，其他人：r-x）
  • B) rw-r--r--（擁有者：rw，群組：r，其他人：r）
  • C) rwxrwxrwx（所有人皆有完整存取權限）
  • D) r-xr-xr-x（所有人皆為讀取+執行）
解答：A) rwxr-xr-x
7=rwx (4+2+1)，5=r-x (4+0+1)，5=r-x (4+0+1)。擁有者擁有完整控制權（讀取、寫入、執行），而群組與其他使用者僅可讀取與執行，無法寫入。

第 2 題：在目錄上設定黏滯位元（Sticky Bit）有什麼作用？

  • A) 讓檔案變成唯讀
  • B) 只有檔案擁有者可以刪除自己的檔案
  • C) 防止目錄被刪除
  • D) 讓目錄中的所有檔案變成可執行
解答：B) 只有檔案擁有者可以刪除自己的檔案
即使使用者對該目錄擁有寫入權限，Sticky Bit 也能防止使用者刪除或重新命名不屬於自己的檔案。這正是 /tmp 目錄使用 Sticky Bit（1777）的原因。

第 3 題：如何使用 ACL 賦予使用者 'john' 對檔案的讀取權限？

  • A) chmod u+r:john file.txt
  • B) setfacl -m u:john:r file.txt
  • C) chown john:r file.txt
  • D) acl john read file.txt
解答：B) setfacl -m u:john:r file.txt
搭配 -m（修改，modify）選項的 setfacl 是設定 ACL 權限的正確指令。其語法為：setfacl -m u:username:permissions file

第 4 題：umask 0027 的效果是什麼？

  • A) 新建立的檔案：640，新建立的目錄：750
  • B) 新建立的檔案：644，新建立的目錄：755
  • C) 新建立的檔案：600，新建立的目錄：700
  • D) 新建立的檔案：666，新建立的目錄：777
解答：A) 新建立的檔案：640，新建立的目錄：750
使用 umask 0027 時：新建檔案權限為 666-027=640 (rw-r-----)，新建目錄則為 777-027=750 (rwxr-x---)。這能在維持良好安全性的同時，允許同群組成員進行讀取。

第 5 題：在目錄上設定 SGID 有什麼作用？

  • A) 讓目錄變成可執行
  • B) 新建立的檔案會繼承該目錄的群組擁有權
  • C) 只有 root 可以存取該目錄
  • D) 加密目錄中的所有檔案
解答：B) 新建立的檔案會繼承該目錄的群組擁有權
在目錄上設定 SGID 可確保新建立的檔案以該目錄的群組作為擁有群組，而非採用建立者的主要群組。這對於需要團隊成員保持一致群組擁有權的共用專案目錄至關重要（chmod 2775 /shared/project）。
