管理 SELinux 安全性

🛡️ SELinux 簡介

SELinux（Security-Enhanced Linux）是由美國國家安全局（NSA）開發的強制存取控制（MAC）安全系統。 不同於傳統基於檔案權限的自主存取控制（DAC），SELinux 會強制執行安全原則，即使是使用者或 root 也無法任意覆寫繞過。

為什麼使用 SELinux？

  • 縱深防禦（Defense in Depth）： 在傳統權限之外提供額外的安全防護層
  • 最小權限原則（Least Privilege）： 程序僅以執行所需的最小權限運作
  • 損害隔離（Containment）： 遭入侵的程序會被限制在其所屬的安全脈絡中
  • 法規合規（Compliance）： 許多資安標準（如 PCI-DSS、HIPAA 等）的必要規範

SELinux 架構

SELinux 基於「萬物皆有標籤」的原則運作：

  • 主體（Subjects）： 程序（標記有安全脈絡）
  • 客體（Objects）： 檔案、目錄、連接埠、裝置（同樣標記有安全脈絡）
  • 原則（Policy）： 定義哪些主體可以存取哪些客體的規則
📘 注意：SELinux 與傳統權限比較

傳統權限： 只要你是檔案擁有者或 root，就可以存取該檔案
SELinux： 即使是 root 也必須遵守 SELinux 安全原則的規則

核心概念

術語 說明
安全脈絡（Context） 檔案或程序上的安全標籤（user:role:type:level）
類型（Type） 安全脈絡中最重要的部分；定義誰可以存取什麼
布林值（Boolean） 用於啟用或停用特定原則功能的開關
原則（Policy） 規則集合（RHEL 預設使用「targeted」原則）

⚙️ SELinux 模式

SELinux 可在以下三種模式下運作：

模式 行為 適用情境
Enforcing（強制） SELinux 強制執行原則；會記錄並阻擋違規存取 正式環境系統（預設）
Permissive（寬容） SELinux 僅記錄拒絕事件但仍允許存取 疑難排解、測試原則
Disabled（停用） 完全關閉 SELinux 不建議使用（需重新開機生效）

檢查 SELinux 狀態

# 檢查目前的 SELinux 狀態
getenforce
Enforcing

# 檢視詳細狀態資訊
sestatus
SELinux status:                 enabled
SELinuxfs mount:                /sys/fs/selinux
SELinux root directory:         /etc/selinux
Loaded policy name:             targeted
Current mode:                   enforcing
Mode from config file:          enforcing
Policy MLS status:              enabled
Policy deny_unknown status:     allowed
Memory protection checking:     actual (secure)
Max kernel policy version:      33

切換 SELinux 模式

暫時變更（執行階段，重新開機後失效）

# 切換為 permissive 模式（暫時）
sudo setenforce 0
# 或
sudo setenforce Permissive

# 切換為 enforcing 模式（暫時）
sudo setenforce 1
# 或
sudo setenforce Enforcing

# 驗證變更結果
getenforce

永久變更（重新開機後依然有效）

# 編輯 SELinux 設定檔
sudo vi /etc/selinux/config

# 設定 SELINUX 變數：
SELINUX=enforcing    # 可設為 enforcing、permissive 或 disabled

# 設定檔範例：
# This file controls the state of SELinux on the system.
# SELINUX= can take one of these three values:
#     enforcing - SELinux security policy is enforced.
#     permissive - SELinux prints warnings instead of enforcing.
#     disabled - No SELinux policy is loaded.
SELINUX=enforcing
# SELINUXTYPE= can take one of these values:
#     targeted - Targeted processes are protected,
#     minimum - Modification of targeted policy. Only selected processes are protected.
#     mls - Multi Level Security protection.
SELINUXTYPE=targeted

# 重新開機以套用變更（切換至 disabled 模式時必須重開機）
sudo reboot
⚠️ 警告：從 Disabled 切換至 Enforcing

在原先停用 SELinux 的系統上重新啟用時，必須為所有檔案重新標記安全脈絡。 這會在重新開機時自動執行，但可能需要花費相當長的時間：

# 強制在下次開機時重新標記所有檔案
sudo touch /.autorelabel
sudo reboot

# 系統將在開機時重新標記所有檔案（可能需要 5-30 分鐘）

個別網域寬容模式（Per-Domain Permissive Mode）

你可以將特定網域設為寬容模式，同時讓整個系統維持在強制（enforcing）模式：

# 將 httpd_t 網域設為寬容模式（用於排解網頁伺服器問題）
sudo semanage permissive -a httpd_t

# 列出所有設為寬容模式的網域
sudo semanage permissive -l

# 移除寬容模式設定
sudo semanage permissive -d httpd_t

🏷️ SELinux 安全脈絡

每個檔案、程序與連接埠都有一個 SELinux 安全脈絡（標籤）。安全脈絡的格式為：
user:role:type:level

安全脈絡組成要素

組成要素 說明 範例
User（使用者） SELinux 使用者（非 Linux 系統使用者） system_u, unconfined_u
Role（角色） 角色型存取控制（RBAC） object_r, system_r
Type（類型） 最重要的部分；用於原則規則判斷 httpd_sys_content_t, user_home_t
Level（安全等級） MLS/MCS 安全等級 s0, s0-s0:c0.c1023

檢視安全脈絡

# 使用 ls -Z 檢視檔案安全脈絡
ls -Z /var/www/html/
-rw-r--r--. root root unconfined_u:object_r:httpd_sys_content_t:s0 index.html

# 使用 ps -Z 檢視程序安全脈絡
ps -eZ | grep httpd
system_u:system_r:httpd_t:s0    1234 ?        00:00:01 httpd

# 檢視目前程序的安全脈絡
id -Z
unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023

# 檢視連接埠安全脈絡
sudo semanage port -l | grep http
http_cache_port_t              tcp      8080, 8118, 8123, 10001-10010
http_port_t                    tcp      80, 81, 443, 488, 8008, 8009, 8443, 9000

變更檔案安全脈絡

暫時變更安全脈絡（chcon）

使用 chcon 進行暫時性變更，但檔案系統重新標記時將會被重置：

# 僅變更類型（Type）
sudo chcon -t httpd_sys_content_t /var/www/html/index.html

# 變更完整安全脈絡
sudo chcon -u system_u -r object_r -t httpd_sys_content_t /var/www/html/index.html

# 複製參考檔案的安全脈絡
sudo chcon --reference=/var/www/html/template.html /var/www/html/newfile.html

# 遞迴變更目錄內所有檔案的安全脈絡
sudo chcon -R -t httpd_sys_content_t /var/www/html/
⚠️ 警告：chcon 與 semanage fcontext 的差異

chcon： 暫時性變更，檔案系統重新標記後就會遺失
semanage fcontext： 永久性變更，重新標記後依然保留（建議使用）

永久變更安全脈絡（semanage fcontext）

使用 semanage fcontext 進行永久性設定：

# 新增檔案脈絡規則
sudo semanage fcontext -a -t httpd_sys_content_t "/web/html(/.*)?"

# 套用新的安全脈絡（restorecon）
sudo restorecon -Rv /web/html/

# 驗證安全脈絡
ls -Zd /web/html/

# 列出所有自訂檔案脈絡規則
sudo semanage fcontext -l -C

# 修改現有規則
sudo semanage fcontext -m -t httpd_sys_rw_content_t "/web/uploads(/.*)?"

# 刪除自訂規則
sudo semanage fcontext -d "/web/html(/.*)?"

還原預設安全脈絡

# 還原單一檔案的安全脈絡
sudo restorecon -v /var/www/html/index.html

# 遞迴還原整個目錄的安全脈絡
sudo restorecon -Rv /var/www/html/

# 預覽將會變更的項目（不實際修改）
sudo restorecon -Rvn /var/www/html/

# 還原整個檔案系統的安全脈絡（啟用 SELinux 後非常實用）
sudo restorecon -Rv /

# 強制重置為預設值（忽略目前的安全脈絡）
sudo restorecon -Fv /path/to/file

操作步驟：設定自訂網頁目錄

  1. 建立自訂網頁目錄： 
    sudo mkdir -p /custom/website
  2. 建立測試檔案： 
    sudo echo "Hello from custom location" > /custom/website/index.html
  3. 檢查目前的安全脈絡（此時為錯誤的預設類型）： 
    ls -Zd /custom/website
drwxr-xr-x. root root unconfined_u:object_r:default_t:s0 /custom/website
  4. 新增永久安全脈絡規則： 
    sudo semanage fcontext -a -t httpd_sys_content_t "/custom/website(/.*)?"
  5. 套用安全脈絡： 
    sudo restorecon -Rv /custom/website
  6. 驗證變更結果： 
    ls -Zd /custom/website
drwxr-xr-x. root root unconfined_u:object_r:httpd_sys_content_t:s0 /custom/website
  7. 設定 Apache 使用該目錄： 
    sudo vi /etc/httpd/conf.d/custom.conf
# 新增 DocumentRoot /custom/website

常見服務的 SELinux 類型

服務 內容安全類型 程序類型
Apache (httpd) httpd_sys_content_t httpd_t
SSH (sshd) ssh_home_t sshd_t
FTP (vsftpd) public_content_t ftpd_t
Samba (smbd) samba_share_t smbd_t

🔘 SELinux 布林值

SELinux 布林值（Booleans）是一種開關機制，可啟用或停用 SELinux 原則中的特定功能， 而無需重新編譯原則檔案，為調整原則行為提供了極大的彈性。

操作布林值

# 列出所有布林值
sudo getsebool -a

# 列出布林值與詳細說明
sudo semanage boolean -l

# 檢查特定布林值狀態
getsebool httpd_can_network_connect
httpd_can_network_connect --> off

# 搜尋相關的布林值
sudo getsebool -a | grep httpd
httpd_anon_write --> off
httpd_builtin_scripting --> on
httpd_can_connect_ftp --> off
httpd_can_connect_ldap --> off
httpd_can_network_connect --> off
httpd_can_network_connect_db --> off
httpd_can_sendmail --> off
httpd_enable_cgi --> on
httpd_enable_homedirs --> off
httpd_use_nfs --> off
httpd_use_cifs --> off

設定布林值

# 暫時設定布林值（僅在本次執行階段有效）
sudo setsebool httpd_can_network_connect on

# 永久設定布林值（重新開機後依然有效）
sudo setsebool -P httpd_can_network_connect on

# 關閉布林值
sudo setsebool -P httpd_enable_homedirs off

# 一次設定多個布林值
sudo setsebool -P httpd_can_network_connect=on httpd_can_network_connect_db=on
💡 提示：務必加上 -P 參數

在實務操作中，請務必使用 setsebool -P 讓變更永久生效。 未加 -P 的暫時性變更會在重新開機後遺失，容易造成後續維運上的困擾。

常見 SELinux 布林值

布林值 用途
httpd_can_network_connect 允許 httpd 發起對外網路連線（如反向代理、API 呼叫）
httpd_can_network_connect_db 允許 httpd 連線至資料庫伺服器
httpd_enable_homedirs 允許 httpd 存取使用者的家目錄
httpd_use_nfs 允許 httpd 存取掛載於 NFS 上的檔案
ftpd_anon_write 允許匿名 FTP 使用者上傳檔案
samba_enable_home_dirs 允許 Samba 分享使用者家目錄

尋找適用的布林值

# 依服務名稱搜尋
sudo getsebool -a | grep httpd
sudo getsebool -a | grep ftp
sudo getsebool -a | grep nfs

# 取得布林值說明
sudo semanage boolean -l | grep httpd_can_network_connect

# 查閱特定服務的 SELinux 線上手冊（man page）
man httpd_selinux
man ftpd_selinux
man samba_selinux

🔧 SELinux 疑難排解

當應用程式因 SELinux 而無法正常運作時，請依照以下系統化步驟進行排查：

步驟 1：確認是否為 SELinux 造成的問題

# 暫時將 SELinux 設為 permissive 模式
sudo setenforce 0

# 測試應用程式現在是否能正常運作
# 如果可以正常運作，表示確實是 SELinux 阻擋了存取
# 如果依然失敗，則問題出在其他地方

# 測試完成後切記恢復為 enforcing 模式
sudo setenforce 1

步驟 2：檢查 AVC 存取拒絕記錄

SELinux 會將存取拒絕事件記錄為 AVC（Access Vector Cache）訊息：

# 檢視稽核日誌中最近的拒絕記錄
sudo ausearch -m AVC -ts recent

# 檢視最近 10 分鐘內的拒絕記錄並轉換為易讀格式
sudo ausearch -m AVC -ts recent -i

# 搜尋今天特定服務的拒絕記錄
sudo ausearch -m AVC -c httpd -ts today

# 即時監看稽核日誌
sudo tail -f /var/log/audit/audit.log | grep AVC

步驟 3：使用 sealert 進行分析

sealert 工具可提供人類易讀的詳細分析與修復建議：

# 若尚未安裝，先安裝 setroubleshoot 工具套件
sudo dnf install setroubleshoot-server

# 分析稽核日誌中的所有拒絕記錄
sudo sealert -a /var/log/audit/audit.log

# 依 Alert ID 分析特定拒絕事件
sudo sealert -l <alert-id>

# 輸出範例：
SELinux is preventing httpd from name_connect access on the tcp_socket port 8080.

***** Plugin catchall_boolean (47.5 confidence) suggests *******************

If you want to allow httpd to can network connect
Then you must tell SELinux about this by enabling the 'httpd_can_network_connect' boolean.

Do
setsebool -P httpd_can_network_connect 1

***** Plugin catchall (6.38 confidence) suggests **************************

If you believe that httpd should be allowed name_connect access on the port 8080 tcp_socket by default.
Then you should report this as a bug.
You can generate a local policy module to allow this access.

Do
# ausearch -c 'httpd' --raw | audit2allow -M my-httpd
# semodule -X 300 -i my-httpd.pp

步驟 4：常見解決方案

方案 1：修正檔案安全脈絡

# 還原預設安全脈絡
sudo restorecon -Rv /var/www/html/

# 或設定自訂安全脈絡
sudo semanage fcontext -a -t httpd_sys_content_t "/custom/path(/.*)?"
sudo restorecon -Rv /custom/path/

方案 2：啟用布林值

# 啟用所需的布林值
sudo setsebool -P httpd_can_network_connect on

方案 3：新增連接埠標籤

# 允許 httpd 繫結至自訂連接埠
sudo semanage port -a -t http_port_t -p tcp 8080

方案 4：建立自訂原則模組

當上述方法皆不適用時，再建立自訂原則模組：

# 從稽核日誌產生原則模組
sudo ausearch -m AVC -ts recent | audit2allow -M mypolicy

# 檢視產生的原則內容
cat mypolicy.te

# 安裝原則模組
sudo semodule -i mypolicy.pp

# 列出已安裝的模組
sudo semodule -l | grep mypolicy

# 視需要移除模組
sudo semodule -r mypolicy
⚠️ 警告：自訂原則為最後手段

自訂原則模組應作為最後的手段。若未經妥善審查，可能會產生安全漏洞。 請務必優先嘗試修改檔案安全脈絡、調整布林值或設定連接埠標記。

疑難排解工作流程

  1. 辨識問題： 服務啟動失敗、應用程式無法存取檔案等。
  2. 確認是否為 SELinux 導致： 檢查執行 setenforce 0 後問題是否解決。
  3. 尋找 AVC 拒絕記錄： 執行 ausearch -m AVC -ts recent。
  4. 使用 sealert 分析： 執行 sealert -a /var/log/audit/audit.log。
  5. 套用建議的修正方案： 調整布林值、安全脈絡、連接埠標籤或原則。
  6. 測試解決方案： 驗證應用程式是否已能正常運作。
  7. 重新啟用強制模式： 執行 setenforce 1。

實用的疑難排解指令

# 檢查哪個程序被拒絕存取
sudo ausearch -m AVC -c httpd -ts recent

# 尋找特定檔案的所有存取拒絕記錄
sudo ausearch -m AVC -f /var/www/html/index.html

# 根據最近的拒絕記錄產生允許規則（不直接建立模組檔）
sudo ausearch -m AVC -ts recent | audit2allow

# 檢查是否有相關的布林值可解決問題
sudo getsebool -a | grep httpd

# 驗證檔案是否具有正確的安全脈絡
matchpathcon /var/www/html/index.html
ls -Z /var/www/html/index.html

🔌 連接埠標記

SELinux 會控管服務可以繫結（bind）使用哪些網路連接埠。每個連接埠都會標記一個安全類型， 唯有具備對應類型的程序才能使用這些連接埠。

檢視連接埠標籤

# 列出所有連接埠標籤
sudo semanage port -l

# 搜尋特定服務的連接埠
sudo semanage port -l | grep http
http_cache_port_t              tcp      8080, 8118, 8123, 10001-10010
http_port_t                    tcp      80, 81, 443, 488, 8008, 8009, 8443, 9000

# 檢查特定連接埠是否已標記
sudo semanage port -l | grep 8080

新增連接埠標籤

# 允許 httpd 繫結至連接埠 8080
sudo semanage port -a -t http_port_t -p tcp 8080

# 允許 httpd 繫結至連接埠範圍
sudo semanage port -a -t http_port_t -p tcp 8080-8090

# 新增 UDP 連接埠標籤
sudo semanage port -a -t dns_port_t -p udp 5353

修改連接埠標籤

# 變更連接埠類型
sudo semanage port -m -t http_cache_port_t -p tcp 8080

# 僅列出自訂的連接埠定義
sudo semanage port -l -C

移除連接埠標籤

# 移除自訂連接埠標籤
sudo semanage port -d -t http_port_t -p tcp 8080

# 移除連接埠範圍標籤
sudo semanage port -d -t http_port_t -p tcp 8080-8090

操作步驟：設定 Apache 使用自訂連接埠

  1. 編輯 Apache 設定檔： 
    sudo vi /etc/httpd/conf/httpd.conf
# 修改為：Listen 8888
  2. 嘗試啟動 Apache： 
    sudo systemctl start httpd
# 在 SELinux enforcing 模式下會因「Permission denied」而失敗
  3. 檢查稽核日誌： 
    sudo ausearch -m AVC -c httpd -ts recent
# 顯示 tcp_socket port 8888 的 name_bind 遭到拒絕
  4. 新增連接埠標籤： 
    sudo semanage port -a -t http_port_t -p tcp 8888
  5. 成功啟動 Apache： 
    sudo systemctl start httpd
sudo systemctl status httpd
  6. 驗證服務運作狀態： 
    sudo ss -tlnp | grep 8888
curl http://localhost:8888

📝 練習題

第 1 題：如何永久將 SELinux 變更為寬容（permissive）模式？

  • A) setenforce 0
  • B) 編輯 /etc/selinux/config，設定 SELINUX=permissive 並重新開機
  • C) systemctl disable selinux
  • D) chmod 000 /sys/fs/selinux
解答：B) 編輯 /etc/selinux/config，設定 SELINUX=permissive 並重新開機
setenforce 0 僅為暫時變更（重新開機後即失效）。永久變更必須編輯 /etc/selinux/config， 將 SELINUX=permissive 設定妥當後重新開機。

第 2 題：哪個指令可以永久設定檔案的 SELinux 安全脈絡？

  • A) chcon -t httpd_sys_content_t /var/www/html/file.html
  • B) semanage fcontext -a -t httpd_sys_content_t "/path(/.*)?" && restorecon -Rv /path
  • C) chmod --context httpd_sys_content_t file.html
  • D) setfacl -m t:httpd_sys_content_t file.html
解答：B) semanage fcontext -a -t httpd_sys_content_t "/path(/.*)?" && restorecon -Rv /path
semanage fcontext 會在 SELinux 原則資料庫中建立永久規則，再由 restorecon 套用該規則。 chcon 所做的只是暫時變更，當檔案系統重新標記時就會遺失。

第 3 題：如何永久允許 httpd 連線至網路資料庫？

  • A) setsebool httpd_can_network_connect_db on
  • B) setsebool -P httpd_can_network_connect_db on
  • C) semanage boolean -a httpd_can_network_connect_db
  • D) getenforce -s httpd_can_network_connect_db
解答：B) setsebool -P httpd_can_network_connect_db on
-P 參數可讓布林值的變更在重新開機後依然生效。若未加上 -P， 變更僅為暫時性，重開機後就會還原。

第 4 題：哪個工具能針對 SELinux 拒絕存取事件提供人類易讀的說明與建議？

  • A) ausearch
  • B) sealert
  • C) seinfo
  • D) getenforce
解答：B) sealert
sealert 會分析稽核日誌，並提供詳細、易讀的 SELinux 拒絕原因說明及建議解決方案。 用法：sealert -a /var/log/audit/audit.log。

第 5 題：如何允許 Apache 繫結並監聽 TCP 連接埠 8080？

  • A) firewall-cmd --add-port=8080/tcp
  • B) semanage port -a -t http_port_t -p tcp 8080
  • C) setsebool -P httpd_port_8080 on
  • D) chcon -t http_port_t 8080
解答：B) semanage port -a -t http_port_t -p tcp 8080
semanage port 可新增連接埠標籤，允許 httpd（使用 http_port_t 類型）繫結至指定的連接埠。 這與防火牆設定屬於不同層面的控管。
