調校系統效能

掌握系統效能監控與調校技巧。學習使用效能分析工具、管理程序優先權， 並設定 tuned 設定檔（Profile）以達到最佳的系統運作效能。

  • 簡介

  • 程序管理與優先權

🎯 簡介

系統效能調校包含監控資源使用狀況、調整程序優先權，以及套用效能設定檔，使系統針對特定工作負載發揮最佳表現。 RHEL 提供了強大的工具來監控 CPU、記憶體、磁碟與網路使用率，並內建 tuned 背景服務以實現自動化效能調校。

在本章中，你將學會：

  • 使用 top、ps、uptime 等工具監控系統效能
  • 使用 nice 與 renice 調整程序優先權
  • 針對不同的工作負載類型管理 tuned 設定檔
  • 識別系統效能瓶頸
  • 針對特定使用情境（桌面環境、伺服器、虛擬機器等）最佳化系統設定
📘 注意

效能調校的核心在於為你的特定工作負載找到最佳平衡點。 沒有一套設定能適用於所有情境。

📊 效能監控工具

top - 即時程序檢視器

top 指令可提供系統執行中程序的動態即時檢視畫面：

# 啟動 top
top

# 輸出範例：
top - 14:23:15 up  3:42,  2 users,  load average: 0.52, 0.58, 0.59
Tasks: 234 total,   1 running, 233 sleeping,   0 stopped,   0 zombie
%Cpu(s):  5.3 us,  2.1 sy,  0.0 ni, 92.2 id,  0.3 wa,  0.0 hi,  0.1 si,  0.0 st
MiB Mem :   3947.8 total,    234.5 free,   2456.7 used,   1256.6 buff/cache
MiB Swap:   2048.0 total,   2048.0 free,      0.0 used.   1234.3 avail Mem

  PID USER      PR  NI    VIRT    RES    SHR S  %CPU  %MEM     TIME+ COMMAND
 1234 student   20   0 1234567  89012   3456 S   2.3   2.2   0:45.67 firefox
 5678 root      20   0  123456  12345   6789 S   1.0   0.3   1:23.45 httpd

了解 top 輸出欄位

欄位 說明
load average 過去 1、5 與 15 分鐘的平均負載（等待 CPU 處理的程序數）
us (user) 執行使用者空間程序所佔用的時間百分比
sy (system) 執行核心空間（kernel space）作業所佔用的時間百分比
id (idle) CPU 閒置時間百分比
wa (I/O wait) CPU 等待 I/O 作業（例如磁碟讀寫）完成的時間百分比
PR 優先權（數值越小代表優先權越高）
NI Nice 值（範圍為 -20 至 19）
VIRT 使用的虛擬記憶體總量
RES 常駐記憶體（實際佔用的實體 RAM）

top 互動式操作指令

# 在 top 執行期間可使用的快速鍵：
k       # 終止程序（輸入 PID）
r       # 重新調整程序 Nice 值（變更優先權）
M       # 依記憶體使用量排序
P       # 依 CPU 使用率排序（預設）
1       # 切換顯示個別 CPU 核心的負載
h       # 顯示說明畫面
q       # 離開 top

# 搭配特定選項啟動 top
top -u student      # 僅顯示 student 使用者的程序
top -d 5            # 每 5 秒更新一次畫面（預設為 3 秒）
top -n 3            # 更新 3 次後自動結束
top -b > top.log    # 以批次模式執行以便寫入日誌檔

uptime - 系統負載

# 檢查系統開機運行時間與平均負載
uptime
14:23:15 up 3:42, 2 users, load average: 0.52, 0.58, 0.59

# 如何解讀平均負載（load average）：
# - 三個數字分別代表過去 1、5 與 15 分鐘的平均值
# - 在 4 核心系統上：負載 4.0 代表達到 100% 滿載
# - 若負載大於 CPU 核心數，代表系統已處於過載狀態

free - 記憶體使用量

# 顯示記憶體使用狀態
free

# 以人類易讀格式顯示
free -h
              total        used        free      shared  buff/cache   available
Mem:          3.9Gi       2.4Gi       234Mi       156Mi       1.2Gi       1.2Gi
Swap:         2.0Gi          0B       2.0Gi

# 關鍵欄位說明：
# available：預估可用於啟動新應用程式的實際可用記憶體
# buff/cache：用於緩衝與快取的記憶體（系統需要時可隨時回收）

ps - 程序狀態

# 檢視所有程序的完整詳細資訊
ps aux

# 以樹狀結構檢視程序階層關係
ps auxf

# 檢視特定使用者的程序
ps -u student

# 自訂輸出欄位並依 CPU 使用率排序取前 10 筆
ps -eo pid,ppid,cmd,%mem,%cpu --sort=-%cpu | head -10

# 搜尋特定程序
ps aux | grep httpd

vmstat - 虛擬記憶體統計資訊

# 顯示系統統計資訊
vmstat

# 每 2 秒更新一次，共顯示 5 次
vmstat 2 5

# 輸出範例：
procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----

 1  0      0 234567  12345 678901    0    0   123   456  789 1234  5  2 92  1  0

⚙️ 程序管理與優先權

Linux 使用優先權機制來決定哪些程序能獲得 CPU 運算時間。了解並調整程序優先權是效能調校的關鍵能力。

優先權（Priority）與 Nice 值

每個程序都有兩個相關數值：

  • 優先權（Priority, PR）： 核心實際用來排程的優先權數值（由系統計算產生）
  • Nice 值（NI）： 可由使用者控制並用來影響優先權的數值
Nice 值 優先權 誰可設定
-20（最高優先權） 獲得最多 CPU 時間 僅限 Root
0（預設值） 一般優先權 所有使用者
19（最低優先權） 獲得最少 CPU 時間 所有使用者
📘 注意：了解「Nice」的意義

「nice」這個詞源自對其他使用者「友善（nice）」的概念。Nice 值越高， 代表該程序越願意禮讓 CPU 資源，因此其使用的 CPU 優先權就越低。

🎚️ Nice 與 Renice 指令

nice - 以指定優先權啟動程序

使用 nice 以指定的 Nice 值啟動新的程序：

# 以預設 Nice 值（0）啟動程序
./my_program

# 以 Nice 值 10 啟動程序（較低優先權）
nice -n 10 ./my_program

# 以 Nice 值 -10 啟動程序（較高優先權，需要 root 權限）
sudo nice -n -10 ./important_program

# 在背景以低優先權啟動程序
nice -n 15 ./backup_script.sh &

# 檢查程序的 Nice 值
ps -o pid,ni,cmd -p $(pgrep my_program)

renice - 變更執行中程序的優先權

使用 renice 變更已正在執行之程序的優先權：

# 依 PID 調整 Nice 值
renice -n 5 -p 1234

# 調整特定使用者所有程序的 Nice 值（需要 root 權限）
sudo renice -n 10 -u student

# 調整特定群組內所有程序的 Nice 值
sudo renice -n 5 -g developers

# 降低耗費大量 CPU 資源程序的優先權（將資源讓給其他程序）
renice -n 19 -p $(pgrep heavy_computation)

# 提高優先權（需要 root 權限）
sudo renice -n -5 -p 1234

# 驗證變更結果
ps -o pid,ni,cmd -p 1234

實務範例

# 以最低優先權執行備份，避免拖慢系統回應
nice -n 19 tar -czf /backups/home.tar.gz /home &

# 以略高的優先權執行資料庫維護工作
sudo nice -n -5 /usr/bin/mysql_optimize

# 降低某位使用者失控程序的優先權
sudo renice -n 15 -p $(pgrep -u problematic_user)

# 以低優先權啟動編譯任務
nice -n 10 make -j4
💡 提示：最佳實務
  • 批次作業與備份任務建議使用較高的 nice 值（nice 10-19）
  • 非必要切勿使用 nice -20
  • 一般使用者只能調高 nice 值（降低優先權）
  • 唯有 root 才能調低 nice 值（提高優先權）

🔧 Tuned 設定檔

tuned 是一個系統監控背景服務，會根據不同的工作負載類型自動調整系統參數以最佳化效能。 它針對常見的應用情境提供了多種預先設定好的設定檔（Profile）。

安裝與啟動 Tuned

# 安裝 tuned（通常系統已預先安裝）
sudo dnf install tuned

# 啟動並設定開機自動啟用 tuned 服務
sudo systemctl start tuned
sudo systemctl enable tuned

# 檢查 tuned 服務狀態
sudo systemctl status tuned

使用 Tuned 設定檔

# 列出所有可用的設定檔
tuned-adm list

# 輸出範例：
Available profiles:
- balanced
- desktop
- latency-performance
- network-latency
- network-throughput
- powersave
- throughput-performance
- virtual-guest
- virtual-host
Current active profile: balanced

# 檢查目前啟用的設定檔
tuned-adm active

# 取得系統推薦的設定檔
tuned-adm recommend

# 切換至不同的設定檔
sudo tuned-adm profile throughput-performance

# 切換至專為虛擬機器客體機最佳化的設定檔
sudo tuned-adm profile virtual-guest

# 關閉 tuned 調校（不建議）
sudo tuned-adm off

常見 Tuned 設定檔

設定檔（Profile） 適用情境 最佳化重點
balanced 預設選項，適合一般均衡用途 在效能與省電之間取得平衡
throughput-performance 伺服器、需要最大吞吐量 最大化效能表現，不啟用省電機制
latency-performance 低延遲需求的系統 以較高耗電為代價將延遲降至最低
virtual-guest 虛擬機器（Guest） 針對虛擬機器內部環境最佳化
virtual-host 虛擬化主機（Hypervisor） 針對執行大量虛擬機器的實體主機最佳化
desktop 桌上型電腦 / 筆記型電腦 介面反應靈敏，並兼顧適度省電
powersave 依賴電池供電的裝置 最大化節省電力消耗

驗證 Tuned 設定檔

# 檢查目前啟用中的設定檔
tuned-adm active
Current active profile: throughput-performance

# 驗證設定檔是否已正確套用
tuned-adm verify
Verification succeeded, current system settings match the preset profile.

# 如果驗證失敗，代表手動修改的設定與設定檔衝突
# 重新套用設定檔：
sudo tuned-adm profile throughput-performance

操作步驟：最佳化資料庫伺服器

  1. 檢查目前的設定檔： 
    tuned-adm active
  2. 查看系統推薦的設定檔： 
    tuned-adm recommend
  3. 套用 throughput-performance 設定檔： 
    sudo tuned-adm profile throughput-performance
  4. 驗證設定是否生效： 
    tuned-adm active
tuned-adm verify
  5. 持續監控資料庫效能的改善情形

📝 練習題

第 1 題：在 4 核心系統上，平均負載（load average）為 4.0 代表什麼意思？

  • A) 系統處於閒置狀態
  • B) 系統的 CPU 使用率已達 100%
  • C) 系統嚴重過載
  • D) 系統目前僅有 4 個程序在執行
解答：B) 系統的 CPU 使用率已達 100%
平均負載代表等待或正在使用 CPU 的程序數量。在 4 核心系統上，負載為 4.0 表示所有核心都已充分使用（100% 滿載）。 當負載大於核心數時才表示系統過載。

第 2 題：哪個 Nice 值會賦予程序「最高」的優先權？

  • A) 19
  • B) 0
  • C) -20
  • D) 10
解答：C) -20
Nice 值的範圍從 -20（最高優先權）到 19（最低優先權）。只有 root 可以設定負數的 Nice 值。 Nice 值越低，優先權越高。

第 3 題：如何變更一個正在執行中的程序之優先權？

  • A) nice -n 10 -p 1234
  • B) renice -n 10 -p 1234
  • C) 執行 top 後按下 'r'
  • D) B 與 C 皆可
解答：D) B 與 C 皆可
renice 用於變更執行中程序的優先權，你也可以在 top 畫面中使用互動式指令 r。 nice 只能用於啟動新程序，無法變更已執行中的程序。

第 4 題：哪一個 tuned 設定檔最適合用於虛擬機器客體機（VM Guest）？

  • A) balanced
  • B) throughput-performance
  • C) virtual-guest
  • D) virtual-host
解答：C) virtual-guest
virtual-guest 設定檔是專為虛擬機器客體機所最佳化的配置； virtual-host 則是給虛擬化主機（Hypervisor）使用。套用指令：sudo tuned-adm profile virtual-guest。

第 5 題：哪個指令可以顯示目前啟用中的 tuned 設定檔？

  • A) tuned-adm status
  • B) tuned-adm active
  • C) systemctl status tuned
  • D) tuned-adm list
解答：B) tuned-adm active
tuned-adm active 會顯示目前運作中的設定檔；tuned-adm list 會列出所有可用的設定檔； tuned-adm recommend 則會建議最適合目前系統的設定檔。
