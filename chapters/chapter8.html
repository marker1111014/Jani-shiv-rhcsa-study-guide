管理軟體套件

掌握使用 DNF/YUM 管理軟體套件的技巧。學習安裝、更新與移除套件、管理套件庫（Repository）、 操作套件群組，以及在 RHEL 9 上處理 AppStream 模組串流（Module Streams）。

📋 本章目錄

  • 簡介

  • 管理套件庫
  • 套件群組

🎯 簡介

套件管理是 Red Hat 系統管理員的核心技能。RHEL 使用 RPM（Red Hat Package Manager）格式的軟體套件， 並透過 DNF（Dandified YUM，即 YUM 的後繼者）來進行管理。DNF 負責處理套件相依性解析、套件庫管理以及交易紀錄追蹤。

核心概念

  • RPM 套件： 預先編譯完成的軟體封裝檔（.rpm 檔案）
  • 套件庫（Repository）： 包含眾多套件及其中繼資料（Metadata）的集中儲存庫
  • DNF/YUM： 高階套件管理工具（可自動處理套件相依性）
  • rpm： 低階套件管理工具（不會自動解析相依性）
  • AppStream： RHEL 9 套件庫，提供同一軟體的多種版本供選擇
  • BaseOS： 提供作業系統核心基礎套件的套件庫
📘 注意：DNF 與 YUM 比較

在 RHEL 9 上，yum 實際上是指向 dnf 的符號連結，兩個指令的運作方式完全相同。 DNF 擁有更快的執行速度、更高的效能以及更優異的相依性解析能力。

RHEL 9 套件庫架構

套件庫 內容
BaseOS 核心作業系統套件（kernel、systemd、bash）
AppStream 應用程式、程式語言、資料庫（支援多版本切換）
Extras 額外的輔助工具與公用程式

📦 DNF/YUM 基礎操作

安裝套件

# 安裝單一套件
sudo dnf install httpd

# 一次安裝多個套件
sudo dnf install httpd mariadb-server php

# 自動確認安裝（不顯示詢問提示）
sudo dnf install -y nginx

# 安裝指定版本的套件
sudo dnf install httpd-2.4.51

# 僅下載套件而不進行安裝
sudo dnf download httpd

# 安裝本機已下載的 RPM 檔並自動解析相依性
sudo dnf install ./httpd-2.4.51-7.el9.x86_64.rpm

# 重新安裝套件
sudo dnf reinstall httpd

更新套件

# 檢查可用的套件更新
sudo dnf check-update

# 更新所有已安裝套件
sudo dnf update

# 更新指定套件
sudo dnf update httpd

# 僅安裝安全性更新修補程式
sudo dnf update --security

# 更新所有套件但排除核心（kernel）套件
sudo dnf update --exclude=kernel*

# 僅下載更新而不進行安裝
sudo dnf update --downloadonly

移除套件

# 移除指定套件
sudo dnf remove httpd

# 移除套件並一併清理不再使用的相依套件
sudo dnf autoremove httpd

# 清理系統中所有不再需要的相依套件
sudo dnf autoremove

# 移除舊版核心（只保留最新的 3 個版本）
sudo dnf remove --oldinstallonly --setopt installonly_limit=3

搜尋與查詢

# 搜尋套件
dnf search nginx
dnf search web server

# 查詢哪個套件提供特定的檔案或指令
dnf provides /usr/sbin/httpd
dnf provides */semanage

# 顯示套件詳細資訊
dnf info httpd

# 列出所有套件（含已安裝與可安裝）
dnf list all

# 列出所有已安裝的套件
dnf list installed

# 列出所有可安裝的套件
dnf list available

# 列出最近新增至套件庫的套件
dnf list recent

# 列出套件群組
dnf group list

# 檢查特定套件是否已安裝
dnf list installed httpd

套件資訊

# 顯示套件詳細資訊
dnf info httpd

# 顯示該套件所依賴的套件
dnf repoquery --requires httpd

# 顯示有哪些套件依賴此套件
dnf repoquery --whatrequires httpd

# 列出套件內包含的所有檔案
dnf repoquery -l httpd

# 顯示套件的變更日誌（Changelog）
dnf changelog httpd

DNF 交易紀錄

# 顯示 DNF 操作交易歷史紀錄
sudo dnf history

# 顯示特定交易編號的詳細資訊
sudo dnf history info 5

# 復原（Undo）特定交易的操作
sudo dnf history undo 5

# 重做（Redo）特定交易的操作
sudo dnf history redo 5

# 回復（Rollback）至特定交易編號當時的狀態
sudo dnf history rollback 10

# 列出所有交易編號清單
sudo dnf history list

清理快取

# 清理所有快取資料
sudo dnf clean all

# 僅清理中繼資料（Metadata）快取
sudo dnf clean metadata

# 僅清理已下載的套件快取
sudo dnf clean packages

# 移除重複安裝的套件
sudo dnf remove --duplicates

# 檢查 RPM 資料庫是否有潛在問題
sudo dnf check
💡 提示：實用技巧
  • 使用 dnf whatprovides（或 dnf provides）找出哪個套件提供特定指令
  • 在自動化腳本中加上 -y 參數以略過確認提示
  • 善用 dnf history 追蹤並在必要時復原套件變更
  • dnf repoquery 指令非常適合用來深入查詢套件細節

🗄️ 管理套件庫

檢視套件庫

# 列出所有已啟用的套件庫
dnf repolist

# 列出所有套件庫（包含已啟用與已停用）
dnf repolist all

# 顯示所有套件庫的詳細資訊
dnf repoinfo

# 顯示特定套件庫的詳細資訊
dnf repoinfo baseos

套件庫設定檔

套件庫設定檔儲存於以下路徑：

  • /etc/yum.repos.d/*.repo - 各別套件庫定義檔
  • /etc/dnf/dnf.conf - DNF 全域主要設定檔

套件庫設定檔格式

# 範例：/etc/yum.repos.d/example.repo
[repository-id]
name=Repository Name
baseurl=https://repo.example.com/rhel9/
# 或使用
metalink=https://mirrors.example.com/metalink?repo=rhel9
# 或使用
mirrorlist=https://mirrors.example.com/mirrorlist?repo=rhel9
enabled=1
gpgcheck=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-example

常見套件庫操作

# 單次指令暫時啟用特定套件庫
sudo dnf install httpd --enablerepo=extras

# 單次指令暫時停用特定套件庫
sudo dnf install httpd --disablerepo=appstream

# 永久啟用套件庫
sudo dnf config-manager --set-enabled extras

# 永久停用套件庫
sudo dnf config-manager --set-disabled extras

# 新增套件庫設定檔
sudo dnf config-manager --add-repo https://example.com/repo/rhel9.repo

# 若找不到 config-manager 指令，請先安裝 dnf-plugins-core
sudo dnf install dnf-plugins-core

操作步驟：新增 EPEL 套件庫

  1. 安裝 EPEL 發行版本設定套件： 
    sudo dnf install https://dl.fedoraproject.org/pub/epel/epel-release-latest-9.noarch.rpm
  2. 驗證套件庫已成功啟用： 
    dnf repolist | grep epel
  3. 搜尋 EPEL 提供的套件： 
    dnf search htop
  4. 從 EPEL 安裝套件： 
    sudo dnf install htop

建立本機套件庫

# 安裝建立套件庫所需的工具
sudo dnf install createrepo

# 建立存放套件的目錄
sudo mkdir -p /var/local-repo

# 複製 RPM 檔案至該目錄
sudo cp *.rpm /var/local-repo/

# 產生套件庫中繼資料
sudo createrepo /var/local-repo/

# 建立套件庫設定檔
sudo vi /etc/yum.repos.d/local.repo

[local]
name=Local Repository
baseurl=file:///var/local-repo
enabled=1
gpgcheck=0

# 清理快取並驗證套件庫
sudo dnf clean all
sudo dnf repolist

套件庫優先權

# 安裝優先權外掛（若需要）
sudo dnf install dnf-plugin-priorities

# 在 .repo 檔案中設定優先權（數字越小代表優先權越高）
[high-priority-repo]
name=High Priority Repo
baseurl=https://repo.example.com/
enabled=1
priority=1

[normal-repo]
name=Normal Repo
baseurl=https://other.example.com/
enabled=1
priority=10

GPG 金鑰管理

# 匯入 GPG 公鑰
sudo rpm --import https://example.com/RPM-GPG-KEY

# 列出已匯入的 GPG 金鑰
rpm -q gpg-pubkey --qf '%{name}-%{version}-%{release} --> %{summary}\n'

# 驗證 RPM 套件簽章
rpm --checksig package.rpm

# 略過 GPG 簽章檢查直接安裝套件（不建議使用）
sudo dnf install --nogpgcheck package.rpm

📚 套件群組

套件群組（Package Groups）是將多個相關聯的套件打包在一起的集合，方便一次完整安裝。

操作套件群組

# 列出所有套件群組
dnf group list

# 列出所有套件群組（包含隱藏群組）
dnf group list --hidden

# 顯示特定套件群組的詳細資訊與包含套件
dnf group info "Development Tools"

# 安裝套件群組
sudo dnf group install "Development Tools"

# 安裝套件群組並一併安裝選用套件
sudo dnf group install --with-optional "Server with GUI"

# 移除套件群組
sudo dnf group remove "Development Tools"

# 更新套件群組
sudo dnf group update "System Tools"

# 將群組標記為已安裝（不實際安裝套件）
sudo dnf group mark install "Development Tools"

常見套件群組

群組名稱 用途
Development Tools 編譯器、make、gcc、git 等開發工具
System Tools 系統管理工具集合
Server with GUI 含圖形化桌面環境的伺服器套件
Workstation 桌面工作站應用程式
Virtualization Host KVM、libvirt、QEMU 虛擬化主機套件

環境群組

# 列出環境群組及其 ID
dnf group list --ids

# 顯示環境群組詳細資訊
dnf group info "Server with GUI"

# 安裝環境群組
sudo dnf install @"Server with GUI"

# 將預設開機目標切換為圖形化介面
sudo systemctl set-default graphical.target

🔧 AppStream 模組

AppStream 透過模組串流（Module Streams）在單一套件庫中提供同款軟體的多個版本。 這讓你能夠自由選擇特定版本的應用程式（例如 Python 3.9 或 3.11、PostgreSQL 13 或 15）。

模組概念

  • 模組（Module）： 一組相關套件的集合（例如 postgresql）
  • 串流（Stream）： 該模組的特定版本線（例如 13、15）
  • 設定檔（Profile）： 針對特定使用情境安裝的套件子集合（例如 server、client）

檢視模組

# 列出所有可用模組
dnf module list

# 列出特定模組的可用串流
dnf module list postgresql

# 顯示模組詳細資訊
dnf module info postgresql

# 顯示特定串流的詳細資訊
dnf module info postgresql:15

# 列出目前已安裝的模組
dnf module list --installed

啟用與安裝模組

# 僅啟用模組串流（尚未安裝套件）
sudo dnf module enable postgresql:15

# 安裝已啟用串流的預設 Profile
sudo dnf module install postgresql:15

# 安裝指定的 Profile
sudo dnf module install postgresql:15/server

# 以單一指令同時啟用並安裝指定模組串流與 Profile
sudo dnf install @postgresql:15/server

# 一次安裝多個 Profile
sudo dnf module install postgresql:15/{server,client}

切換模組串流

# 檢查目前的模組串流狀態
dnf module list postgresql

# 重置模組狀態
sudo dnf module reset postgresql

# 切換至不同的串流並同步套件版本
sudo dnf module enable postgresql:13
sudo dnf distro-sync

# 另一種做法：先移除舊串流套件、重置模組，再安裝新串流
sudo dnf module remove postgresql:15
sudo dnf module reset postgresql
sudo dnf module install postgresql:13

模組管理

# 停用模組
sudo dnf module disable postgresql

# 移除已安裝的模組
sudo dnf module remove postgresql:15

# 重置模組狀態
sudo dnf module reset postgresql

# 顯示模組串流包含的 Profile 內容
dnf module info --profile postgresql:15

操作步驟：安裝 Python 3.11 模組

  1. 列出可用的 Python 版本： 
    dnf module list python3*
  2. 檢視 Python 3.11 模組詳細資訊： 
    dnf module info python39:3.11
  3. 啟用 Python 3.11 串流： 
    sudo dnf module enable python39:3.11
  4. 安裝 Python 3.11： 
    sudo dnf install python3
  5. 驗證安裝版本： 
    python3 --version

常見模組

模組 常見串流版本
postgresql 13, 15
python39 3.9, 3.11
nodejs 16, 18, 20
ruby 3.0, 3.1
⚠️ 警告：模組串流限制

同一個模組在同一時間只能啟用一個串流（Stream）。若要切換版本串流， 必須先重置（reset）或停用目前的串流。

⚙️ RPM 指令

rpm 是底層的套件管理工具，它不會自動處理套件之間的相依性。

查詢套件

# 列出系統中所有已安裝的套件
rpm -qa

# 查詢特定套件是否已安裝
rpm -q httpd

# 顯示已安裝套件的詳細資訊
rpm -qi httpd

# 列出套件安裝的所有檔案
rpm -ql httpd

# 列出套件的文件檔案
rpm -qd httpd

# 列出套件的設定檔
rpm -qc httpd

# 顯示套件的相依性需求
rpm -qR httpd

# 查詢某個檔案屬於哪一個已安裝套件
rpm -qf /usr/sbin/httpd

# 查詢尚未安裝的本機 RPM 檔案資訊
rpm -qip package.rpm
rpm -qlp package.rpm

使用 RPM 安裝與移除

# 安裝 RPM 套件（不自動解析相依性）
sudo rpm -ivh package.rpm
# i = 安裝 (install), v = 顯示詳細過程 (verbose), h = 顯示進度符號 (hash marks)

# 升級套件
sudo rpm -Uvh package.rpm
# U = 升級 (upgrade，若尚未安裝則直接安裝)

# 更新（僅在系統已安裝該套件時才進行升級）
sudo rpm -Fvh package.rpm

# 移除套件
sudo rpm -e httpd

# 強制移除（忽略相依性檢查——非常危險！）
sudo rpm -e --nodeps httpd

# 安裝套件但不執行內含的安裝腳本
sudo rpm -ivh --noscripts package.rpm

驗證套件

# 驗證系統中所有已安裝套件的檔案完整性
sudo rpm -Va

# 驗證特定套件的檔案
sudo rpm -V httpd

# 驗證特定檔案所屬套件的完整性
sudo rpm -Vf /usr/sbin/httpd

# 驗證結果代碼說明：
# S = 檔案大小不同
# M = 權限模式或檔案類型不同
# 5 = MD5 雜湊值不同
# D = 裝置主次編號不同
# L = 符號連結路徑不同
# U = 擁有者不同
# G = 群組擁有者不同
# T = 修改時間 (mTime) 不同
# P = 權能 (Capabilities) 不同

解壓縮 RPM 內容

# 在不安裝的情況下解壓縮 RPM 檔案內容
rpm2cpio package.rpm | cpio -idmv

# 僅解壓縮 RPM 內的特定檔案
rpm2cpio package.rpm | cpio -idmv ./usr/bin/command
💡 提示：RPM 與 DNF 比較

使用 DNF 的時機： 安裝、更新或移除套件（可自動解析與處理相依性）
使用 RPM 的時機： 查詢已安裝套件、驗證檔案完整性或執行底層套件操作

📝 練習題

第 1 題：哪個指令能安裝 httpd 並自動處理其所有相依套件？

  • A) rpm -ivh httpd
  • B) dnf install httpd
  • C) yum search httpd
  • D) rpm -Uvh httpd
解答：B) dnf install httpd
DNF（與 YUM）會自動解析並安裝所有必要的相依套件。RPM 指令（如 rpm -ivh） 不會自動處理相依性，若缺少相依套件將會安裝失敗。

第 2 題：如何查詢哪一個套件提供了 /usr/sbin/semanage 指令？

  • A) dnf search semanage
  • B) dnf provides /usr/sbin/semanage
  • C) rpm -qf /usr/sbin/semanage
  • D) dnf info semanage
解答：B) dnf provides /usr/sbin/semanage
dnf provides（或 dnf whatprovides）可用來搜尋哪個套件提供指定的檔案，即使尚未安裝也能查到。 rpm -qf 僅在該套件已經安裝於系統時才有效。你也可以使用 dnf provides */semanage。

第 3 題：從 PostgreSQL 13 切換至 PostgreSQL 15 的正確步驟為何？

  • A) dnf install postgresql:15
  • B) dnf module reset postgresql && dnf module install postgresql:15
  • C) dnf update postgresql
  • D) dnf module enable postgresql:15
解答：B) dnf module reset postgresql && dnf module install postgresql:15
切換模組串流時，必須先重置（reset）目前的模組串流，接著再安裝新的串流。 或者先執行 dnf module remove postgresql:13，再重置後安裝 postgresql:15。

第 4 題：如何列出 httpd 套件在系統中安裝的所有檔案？

  • A) dnf list httpd
  • B) rpm -ql httpd
  • C) dnf info httpd
  • D) rpm -qa httpd
解答：B) rpm -ql httpd
rpm -ql（query list）會列出該套件所包含的所有檔案。你也可以使用 dnf repoquery -l httpd。 rpm -qa 則是列出所有已安裝的套件名稱，而非檔案清單。

第 5 題：「dnf group install "Development Tools"」這個指令會做什麼？

  • A) 僅安裝套件群組的中繼資料
  • B) 安裝 gcc、make、git 與其他開發相關套件
  • C) 僅列出可用的開發工具
  • D) 僅建立一個空的開發環境設定
解答：B) 安裝 gcc、make、git 與其他開發相關套件
套件群組將相關聯的套件打包在一起。「Development Tools」包含編譯器（gcc）、 建置工具（make）、版本控制工具（git）及軟體開發所需的函式庫。
