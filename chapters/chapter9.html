管理基礎儲存裝置

精通磁碟分割、檔案系統建立與儲存空間掛載。學習 MBR 與 GPT 分割架構、建立 ext4 與 XFS 檔案系統、 設定 Swap 空間，並透過 /etc/fstab 設定開機自動永久掛載。

🎯 簡介

儲存管理是 Linux 系統管理的基礎。您必須了解如何分割磁碟、建立檔案系統，以及掛載儲存空間使其可供存取。 RHEL 同時支援 MBR（傳統）與 GPT（現代）兩種磁碟分割架構。

儲存層級架構

  1. 實體磁碟： /dev/sda, /dev/vda, /dev/nvme0n1
  2. 分割區： /dev/sda1, /dev/vda2, /dev/nvme0n1p1
  3. 檔案系統： ext4, XFS, Btrfs
  4. 掛載點： /, /home, /data

裝置命名規則

裝置類型 命名模式 範例
SATA/SAS 磁碟 /dev/sd[a-z] /dev/sda, /dev/sdb
虛擬磁碟 (KVM) /dev/vd[a-z] /dev/vda, /dev/vdb
NVMe SSD /dev/nvme[0-9]n[0-9] /dev/nvme0n1, /dev/nvme1n1
MBR 分割區 /dev/sda[1-4] /dev/sda1, /dev/sda2
GPT/NVMe 分割區 /dev/nvme0n1p[1-128] /dev/nvme0n1p1
📘 MBR 與 GPT 比較

MBR：傳統架構，最大支援 2TB 磁碟，最多 4 個主分割區
GPT：現代架構，支援超過 2TB 的磁碟，最多可達 128 個分割區，可靠性更高

🔧 磁碟分割

檢視磁碟資訊

# 列出所有區塊裝置
lsblk

# 輸出範例：
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sda      8:0    0   20G  0 disk 
├─sda1   8:1    0    1G  0 part /boot
└─sda2   8:2    0   19G  0 part 
  ├─rhel-root 253:0 0 17G 0 lvm  /
  └─rhel-swap 253:1 0  2G 0 lvm  [SWAP]
sdb      8:16   0   10G  0 disk 

# 顯示檔案系統資訊
lsblk -f

# 列出分割表
sudo fdisk -l

# 顯示磁碟空間使用量
df -h

# 顯示分割區 UUID 與檔案系統類型
sudo blkid

使用 fdisk 進行分割 (MBR)

使用 fdisk 管理 MBR 分割表（適用於 2TB 以下的磁碟）：

# 啟動 fdisk
sudo fdisk /dev/sdb

# fdisk 內部常用指令：
m     # 顯示說明
p     # 顯示分割表
n     # 新增分割區
d     # 刪除分割區
t     # 變更分割區類型
l     # 列出支援的分割區類型
w     # 寫入變更並離開
q     # 不儲存並直接離開

# 範例：建立新分割區
Command: n
Partition type: p (primary)
Partition number: 1
First sector: (press Enter for default)
Last sector: +2G (create 2GB partition)

# 將分割區類型設為 Linux LVM（代碼 8e）
Command: t
Partition number: 1
Hex code: 8e

# 寫入變更
Command: w

使用 parted 進行分割 (GPT)

使用 parted 管理 GPT 分割表（現代架構，支援大於 2TB 的磁碟）：

# 以互動模式啟動 parted
sudo parted /dev/sdb

# 建立 GPT 分割表
(parted) mklabel gpt

# 建立分割區
(parted) mkpart primary 1MiB 2GiB

# 為分割區命名
(parted) name 1 data

# 設定分割區旗標
(parted) set 1 lvm on

# 顯示分割表
(parted) print

# 離開
(parted) quit

# 非互動模式（單行指令）
sudo parted /dev/sdb mklabel gpt
sudo parted /dev/sdb mkpart primary 1MiB 2GiB
sudo parted /dev/sdb name 1 data
sudo parted /dev/sdb set 1 lvm on

更新核心分割表

# 通知核心分割表已變更
sudo partprobe /dev/sdb

# 若 partprobe 失敗時的替代指令
sudo partx -u /dev/sdb

# 驗證變更結果
lsblk /dev/sdb

操作步驟：新增一個 5GB 資料分割區

  1. 識別可用的磁碟： 
    lsblk
# 假設 /dev/sdb 可供使用
  2. 建立 GPT 分割表： 
    sudo parted /dev/sdb mklabel gpt
  3. 建立 5GB 分割區： 
    sudo parted /dev/sdb mkpart primary 1MiB 5GiB
  4. 通知核心更新分割表： 
    sudo partprobe /dev/sdb
  5. 驗證分割區是否建立成功： 
    lsblk /dev/sdb
sudo parted /dev/sdb print

刪除分割區

# 使用 parted 刪除
sudo parted /dev/sdb rm 1

# 使用 fdisk 刪除
sudo fdisk /dev/sdb
Command: d
Partition number: 1
Command: w

💾 檔案系統

RHEL 9 主要使用 XFS（系統預設）與 ext4 檔案系統。

檔案系統比較

特性 XFS ext4
單一檔案最大容量 8 EiB 16 TiB
檔案系統最大容量 8 EiB 1 EiB
是否支援縮減 否 是
RHEL 9 預設值 是 否

建立檔案系統

# 建立 XFS 檔案系統（RHEL 預設）
sudo mkfs.xfs /dev/sdb1

# 建立 ext4 檔案系統
sudo mkfs.ext4 /dev/sdb1

# 建立時一併指定標籤 (Label)
sudo mkfs.xfs -L "data" /dev/sdb1
sudo mkfs.ext4 -L "backup" /dev/sdb2

# 強制建立（覆寫既有檔案系統）
sudo mkfs.xfs -f /dev/sdb1

# 建立時指定進階參數
sudo mkfs.ext4 -b 4096 -i 8192 /dev/sdb1
# -b 指定區塊大小 (block size)
# -i 指定每個 inode 分配的位元組數

檔案系統標籤 (Label)

# 設定或變更 XFS 標籤
sudo xfs_admin -L "newlabel" /dev/sdb1

# 設定或變更 ext4 標籤
sudo e2label /dev/sdb1 "newlabel"

# 檢視標籤資訊
lsblk -f
sudo blkid

檢查與修復檔案系統

# 修復 XFS 檔案系統
sudo xfs_repair /dev/sdb1

# 檢查 ext4 檔案系統
sudo fsck.ext4 /dev/sdb1
# 或
sudo e2fsck /dev/sdb1

# 強制檢查
sudo e2fsck -f /dev/sdb1

# 自動修復
sudo e2fsck -p /dev/sdb1

# 全自動回答 yes 進行修復
sudo e2fsck -y /dev/sdb1
⚠️ 檔案系統檢查注意事項

切勿對已掛載的檔案系統執行 fsck 或 xfs_repair！務必先卸載再進行檢查，否則會導致檔案系統嚴重損毀。 檢查前請先執行 umount /dev/sdb1。

擴充檔案系統

# 擴充 XFS（必須處於已掛載狀態）
sudo xfs_growfs /mount/point

# 擴充 ext4（掛載或未掛載狀態皆可）
sudo resize2fs /dev/sdb1

# 擴充至指定大小
sudo resize2fs /dev/sdb1 10G

📂 掛載檔案系統

手動掛載

# 建立掛載點目錄
sudo mkdir /data

# 掛載檔案系統
sudo mount /dev/sdb1 /data

# 搭配掛載選項
sudo mount -o ro /dev/sdb1 /data        # 唯讀模式
sudo mount -o noexec /dev/sdb1 /data    # 禁止執行二進位檔
sudo mount -o nosuid /dev/sdb1 /data    # 忽略 SUID 權限

# 依標籤 (LABEL) 掛載
sudo mount LABEL=data /data

# 依 UUID 掛載
sudo mount UUID=xxx-xxx-xxx /data

# 驗證掛載狀態
mount | grep sdb1
df -h /data

卸載檔案系統

# 依裝置名稱卸載
sudo umount /dev/sdb1

# 依掛載點路徑卸載
sudo umount /data

# 強制卸載（若裝置正忙線中）
sudo umount -f /data

# 延遲卸載 (Lazy unmount，立即中斷連結並於無人使用時清理)
sudo umount -l /data

# 檢查哪些程序正在使用該掛載點
sudo lsof /data
sudo fuser -mv /data

常見掛載選項

選項 說明
defaults 等同 rw, suid, dev, exec, auto, nouser, async
ro 唯讀 (Read-only)
rw 讀寫 (Read-write)
noexec 不允許執行二進位執行檔
nosuid 忽略 SUID 與 SGID 特殊權限位元
noauto 開機時不自動掛載
_netdev 網路裝置（等待網路連線就緒後再掛載）

💱 Swap 空間

當實體記憶體 (RAM) 用滿時會使用 Swap 空間。Swap 可以是獨立分割區或一般檔案。

建立 Swap 分割區

# 建立分割區（MBR 請使用類型 82，GPT 請使用 'linux-swap'）
sudo parted /dev/sdb mkpart primary linux-swap 5GiB 7GiB

# 格式化為 Swap 空間
sudo mkswap /dev/sdb2

# 設定標籤
sudo mkswap -L swap1 /dev/sdb2

# 啟用 Swap
sudo swapon /dev/sdb2

# 驗證 Swap 狀態
swapon --show
free -h

建立 Swap 檔案

# 建立 2GB 的 Swap 檔案
sudo dd if=/dev/zero of=/swapfile bs=1M count=2048
# 或使用較快的 fallocate 指令
sudo fallocate -l 2G /swapfile

# 設定安全權限（僅限 root 讀寫）
sudo chmod 600 /swapfile

# 格式化為 Swap 空間
sudo mkswap /swapfile

# 啟用 Swap 檔案
sudo swapon /swapfile

# 驗證
swapon --show

管理 Swap 空間

# 檢視 Swap 使用情形
swapon --show
free -h
cat /proc/swaps

# 停用指定 Swap
sudo swapoff /dev/sdb2
sudo swapoff /swapfile

# 停用所有 Swap
sudo swapoff -a

# 啟用 /etc/fstab 中定義的所有 Swap
sudo swapon -a

# 檢查 Swap 優先權
swapon --show

Swap 優先權

# 啟用時指定優先權（數字越大，優先權越高）
sudo swapon -p 10 /dev/sdb2

# 在 /etc/fstab 中的設定方式：
/dev/sdb2  none  swap  pri=10  0 0
💡 Swap 容量建議

RAM ≤ 2GB： 2 倍 RAM
RAM 2-8GB： 與 RAM 相同容量
RAM >8GB： 至少 4GB，或 0.5 倍 RAM
若需支援休眠 (Hibernation)： RAM 容量 + 0.5GB

📝 永久掛載 (/etc/fstab)

/etc/fstab 設定檔用於定義系統開機時要自動掛載的檔案系統。

fstab 格式

# /etc/fstab
# <裝置>      <掛載點>       <類型>  <選項>     <dump>  <pass>

UUID=xxx-xxx   /data         xfs     defaults   0       2
LABEL=backup   /backup       ext4    defaults   0       2
/dev/sdb3      /mnt/extra    xfs     noauto     0       0
/swapfile      none          swap    sw         0       0

欄位說明

欄位 說明
Device（裝置） UUID、LABEL 或 /dev/sdX（建議使用 UUID）
Mount Point（掛載點） 要掛載的目錄路徑（Swap 請填 'none'）
Type（類型） xfs、ext4、swap、nfs 等檔案系統類型
Options（選項） defaults、ro、noexec 等掛載選項
Dump 0=不備份，1=備份（現代系統通常設為 0）
Pass 0=不執行 fsck，1=根檔案系統，2=其他檔案系統

取得 UUID

# 顯示所有裝置的 UUID
sudo blkid

# 顯示特定裝置的資訊
sudo blkid /dev/sdb1

# 輸出範例：
/dev/sdb1: UUID="xxx-xxx-xxx" TYPE="xfs"

# 或使用 lsblk
lsblk -f

操作步驟：設定永久掛載

  1. 取得裝置的 UUID： 
    sudo blkid /dev/sdb1
UUID="a1b2c3d4-e5f6-..."
  2. 建立掛載點目錄： 
    sudo mkdir /data
  3. 編輯 /etc/fstab： 
    sudo vi /etc/fstab

# 新增設定行：
UUID=a1b2c3d4-e5f6-...  /data  xfs  defaults  0  2
  4. 測試 fstab 設定（無需重開機）： 
    sudo mount -a
  5. 驗證是否掛載成功： 
    df -h /data
mount | grep /data
  6. 驗證 fstab 語法是否正確： 
    sudo findmnt --verify
⚠️ 重要提醒：重開機前務必測試

重開機前請務必使用 mount -a 測試 /etc/fstab 設定！ 錯誤的 fstab 設定會導致系統無法正常開機。若不幸發生此問題，請開機進入救援模式並修正 fstab 檔案。

systemd 掛載單元 (Mount Units)

針對複雜的掛載需求，可以使用替代 fstab 的方式：

# 建立掛載單元檔：/etc/systemd/system/data.mount
[Unit]
Description=Data Partition

[Mount]
What=/dev/sdb1
Where=/data
Type=xfs
Options=defaults

[Install]
WantedBy=multi-user.target

# 重新載入 systemd 並啟用掛載單元
sudo systemctl daemon-reload
sudo systemctl enable --now data.mount

📝 練習題

第 1 題：哪一種分割架構支援大於 2TB 的磁碟？

  • A) MBR
  • B) GPT
  • C) LVM
  • D) 延伸分割區
解答：B) GPT
GPT (GUID Partition Table) 支援大於 2TB 的磁碟，且最多可建立 128 個分割區。MBR 則限制最大 2TB 磁碟及 4 個主分割區。建立 GPT 分割區請使用 parted。

第 2 題：哪個指令可以在 /dev/sdb1 上建立 XFS 檔案系統？

  • A) mkfs -t xfs /dev/sdb1
  • B) mkfs.xfs /dev/sdb1
  • C) A 與 B 皆可
  • D) xfs_create /dev/sdb1
解答：C) A 與 B 皆可
這兩個指令都能建立 XFS 檔案系統。mkfs.xfs 是直接呼叫專用工具，而 mkfs -t xfs 則是通用格式。若要建立 ext4 則可使用 mkfs.ext4 或 mkfs -t ext4。

第 3 題：/etc/fstab 中的哪一個欄位決定開機時的 fsck 檢查順序？

  • A) 第 4 欄 (options)
  • B) 第 5 欄 (dump)
  • C) 第 6 欄 (pass)
  • D) 第 3 欄 (type)
解答：C) 第 6 欄 (pass)
pass 欄位的設定意義為：0=不執行 fsck，1=根檔案系統（優先檢查），2=其他檔案系統（於根檔案系統之後檢查）。根目錄應設為 1，其他檔案系統設為 2，Swap 則設為 0。

第 4 題：在 /etc/fstab 中識別儲存裝置時，建議優先使用哪種方式？

  • A) 裝置名稱 (/dev/sdb1)
  • B) UUID
  • C) 標籤 (Label)
  • D) B 與 C 皆可
解答：D) B 與 C 皆可
UUID 與 LABEL 皆優於傳統裝置名稱，因為裝置名稱可能會因硬體變動而改變（例如新增磁碟後 /dev/sdb 變成 /dev/sdc）。其中又以 UUID 最為可靠。

第 5 題：如何在不重開機的情況下測試 /etc/fstab 設定？

  • A) mount -a
  • B) systemctl restart fstab
  • C) fstab --test
  • D) mount --check
解答：A) mount -a
mount -a 會嘗試掛載 /etc/fstab 中所有設定的檔案系統，讓您在無需重開機的情況下測試設定是否正確。編輯完 fstab 後務必執行此指令檢查錯誤，亦可搭配 findmnt --verify 驗證語法。
