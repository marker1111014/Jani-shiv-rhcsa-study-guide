設定網路連線

精通使用 NetworkManager 與 nmcli 進行網路組態設定。學習如何設定 IP 位址、 管理網路連線、設定主機名稱，並進行網路疑難排解。

🎯 網路設定簡介

RHEL 9 使用 NetworkManager 管理所有的網路組態設定。主要的命令列管理工具有 nmcli（NetworkManager Command Line Interface）。

NetworkManager 核心元件

元件 說明
Device（裝置） 網路介面卡（例如 eth0、ens33、wlan0）
Connection（連線） 網路組態設定檔
nmcli 命令列管理工具
nmtui 文字介面（TUI）工具

設定檔位置

# 連線設定檔（由 NetworkManager 管理）
/etc/NetworkManager/system-connections/

# 傳統網路腳本（在 RHEL 9 中已棄用）
/etc/sysconfig/network-scripts/

# 主機名稱
/etc/hostname

# DNS 解析
/etc/resolv.conf  # 由 NetworkManager 管理
/etc/hosts        # 靜態主機名稱對應

基本網路資訊查詢

# 顯示 IP 位址
ip addr show
ip a

# 顯示路由表
ip route show
ip r

# 顯示指定網路介面
ip addr show ens33

# 傳統指令（仍可使用）
ifconfig  # 可能需要安裝 net-tools 套件
route -n

🔧 nmcli - NetworkManager 命令列工具

檢視網路狀態

# 顯示所有網路裝置
nmcli device status
nmcli dev status

# 輸出範例：
DEVICE  TYPE      STATE      CONNECTION
ens33   ethernet  connected  ens33
lo      loopback  unmanaged  --

# 顯示所有連線設定
nmcli connection show
nmcli con show

# 輸出範例：
NAME   UUID                                  TYPE      DEVICE
ens33  abc123-def4-5678-9abc-def012345678   ethernet  ens33

# 顯示連線詳細資訊
nmcli con show ens33

# 顯示裝置詳細資訊
nmcli dev show ens33

管理連線

# 啟用連線
nmcli con up ens33

# 停用連線
nmcli con down ens33

# 重新載入連線設定
nmcli con reload

# 刪除連線
nmcli con delete ens33

# 重新命名連線
nmcli con modify ens33 connection.id "LAN"

連線類型

# 乙太網路連線
nmcli con add type ethernet con-name eth0 ifname eth0

# Wi-Fi 連線
nmcli dev wifi connect "SSID" password "password"

# 列出可用的 Wi-Fi 網路
nmcli dev wifi list

# Team/Bond（進階設定）
nmcli con add type team con-name team0 ifname team0
nmcli con add type bridge con-name br0 ifname br0

🌐 IP 組態設定

靜態 IP 設定

# 建立使用靜態 IP 的新連線
nmcli con add \
  con-name static-ens33 \
  ifname ens33 \
  type ethernet \
  ipv4.addresses 192.168.1.100/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.dns "8.8.8.8 8.8.4.4" \
  ipv4.method manual

# 啟用該連線
nmcli con up static-ens33

# 驗證設定
ip addr show ens33

修改現有連線

# 變更為靜態 IP
nmcli con mod ens33 \
  ipv4.addresses 192.168.1.100/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.dns "8.8.8.8 8.8.4.4" \
  ipv4.method manual

# 新增第二個 IP 位址
nmcli con mod ens33 +ipv4.addresses 192.168.1.101/24

# 移除 IP 位址
nmcli con mod ens33 -ipv4.addresses 192.168.1.101/24

# 套用變更
nmcli con up ens33

DHCP 設定

# 建立 DHCP 連線
nmcli con add \
  con-name dhcp-ens33 \
  ifname ens33 \
  type ethernet \
  ipv4.method auto

# 將現有連線變更為 DHCP
nmcli con mod ens33 ipv4.method auto

# 清除靜態設定
nmcli con mod ens33 \
  ipv4.addresses "" \
  ipv4.gateway "" \
  ipv4.dns ""

# 套用設定
nmcli con up ens33

IPv6 設定

# 靜態 IPv6
nmcli con mod ens33 \
  ipv6.addresses 2001:db8::1/64 \
  ipv6.gateway 2001:db8::ffff \
  ipv6.method manual

# 自動取得（SLAAC）
nmcli con mod ens33 ipv6.method auto

# 停用 IPv6
nmcli con mod ens33 ipv6.method disabled

# 套用設定
nmcli con up ens33

操作步驟：設定靜態 IP 位址

  1. 檢查目前的組態設定： 
    nmcli con show
ip addr show
  2. 修改連線設定以使用靜態 IP： 
    sudo nmcli con mod ens33 \
  ipv4.addresses 192.168.1.100/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.dns "8.8.8.8 8.8.4.4" \
  ipv4.method manual
  3. 啟用連線以套用變更： 
    sudo nmcli con up ens33
  4. 驗證網路組態： 
    ip addr show ens33
ip route show
cat /etc/resolv.conf
  5. 測試網路連線能力： 
    ping -c 4 8.8.8.8
ping -c 4 google.com

常用 nmcli 設定選項

設定項目 說明
ipv4.method auto（DHCP）、manual（靜態）、disabled（停用）
ipv4.addresses IP 位址與子網路遮罩長度（如 192.168.1.100/24）
ipv4.gateway 預設閘道 IP 位址
ipv4.dns DNS 伺服器（多筆以空白分隔）
connection.autoconnect yes/no（開機時是否自動啟用連線）

🏷️ 主機名稱管理

設定主機名稱

# 設定主機名稱（永久生效）
sudo hostnamectl set-hostname server1.example.com

# 檢視主機名稱詳細資訊
hostnamectl

# 輸出範例：
 Static hostname: server1.example.com
       Icon name: computer-vm
         Chassis: vm
      Machine ID: abc123...
         Boot ID: def456...
  Virtualization: kvm
Operating System: Red Hat Enterprise Linux 9.0 (Plow)
     CPE OS Name: cpe:/o:redhat:enterprise_linux:9::baseos
          Kernel: Linux 5.14.0-70.el9.x86_64
    Architecture: x86-64

# 僅檢視主機名稱
hostname
hostnamectl hostname

主機名稱類型

# 靜態主機名稱（永久）
sudo hostnamectl set-hostname server1.example.com

# 易讀主機名稱（Pretty hostname，描述性名稱）
sudo hostnamectl set-hostname "Web Server 1" --pretty

# 暫時性主機名稱（重開機後失效）
sudo hostnamectl set-hostname temp-name --transient

# 檢視所有類型的主機名稱
hostnamectl status

手動設定主機名稱

# 編輯主機名稱設定檔
sudo vi /etc/hostname
server1.example.com

# 或使用 nmcli 設定
sudo nmcli general hostname server1.example.com

# 更新 /etc/hosts 以進行本機解析
sudo vi /etc/hosts
127.0.0.1   localhost localhost.localdomain
192.168.1.100   server1.example.com server1
💡 提示：主機名稱最佳實踐

靜態主機名稱建議使用 FQDN（完整網域名稱）：server1.example.com
更新 /etc/hosts 加入主機名稱以供本機解析
避免使用特殊字元，僅使用英文字母、數字、連字號（-）與點號（.）

🔍 DNS 設定

使用 nmcli 設定 DNS

# 設定 DNS 伺服器
sudo nmcli con mod ens33 ipv4.dns "8.8.8.8 8.8.4.4"

# 新增額外的 DNS 伺服器
sudo nmcli con mod ens33 +ipv4.dns 1.1.1.1

# 設定 DNS 搜尋網域
sudo nmcli con mod ens33 ipv4.dns-search "example.com lab.local"

# 忽略自動取得的 DNS（僅使用手動設定）
sudo nmcli con mod ens33 ipv4.ignore-auto-dns yes

# 套用變更
sudo nmcli con up ens33

# 驗證設定
cat /etc/resolv.conf

/etc/resolv.conf

# 檢視 DNS 設定（由 NetworkManager 管理）
cat /etc/resolv.conf

# 輸出範例：
# Generated by NetworkManager
nameserver 8.8.8.8
nameserver 8.8.4.4
search example.com lab.local

/etc/hosts

# 靜態主機名稱與 IP 位址對應
sudo vi /etc/hosts

127.0.0.1   localhost localhost.localdomain
::1         localhost localhost.localdomain
192.168.1.10   server1.example.com server1
192.168.1.20   server2.example.com server2

# 測試主機名稱解析
getent hosts server1
ping server1

名稱解析順序

# 設定解析順序的檔案
/etc/nsswitch.conf

# 預設設定行：
hosts: files dns myhostname

# files = 優先查詢 /etc/hosts
# dns = 其次查詢 DNS 伺服器
# myhostname = systemd 本機主機名稱解析

測試 DNS 解析

# 測試網域名稱解析
nslookup google.com
dig google.com
host google.com

# 指定特定的 DNS 伺服器查詢
nslookup google.com 8.8.8.8
dig @8.8.8.8 google.com

# 反向 DNS 查詢
nslookup 8.8.8.8
dig -x 8.8.8.8

# 檢查目前使用的 DNS 伺服器
systemd-resolve --status

🔧 網路疑難排解

連線能力測試

# Ping 預設閘道
ping -c 4 192.168.1.1

# Ping 外部 IP
ping -c 4 8.8.8.8

# Ping 主機名稱（同時測試 DNS）
ping -c 4 google.com

# 路由追蹤
traceroute google.com
tracepath google.com

# 檢查正在監聽的連接埠
ss -tulpn
netstat -tulpn  # 傳統指令

網路介面疑難排解

# 檢查介面連線狀態
ip link show ens33

# 啟用網路介面
sudo ip link set ens33 up

# 停用網路介面
sudo ip link set ens33 down

# 檢查網卡驅動程式與硬體資訊
ethtool ens33

# 檢視連線狀態
nmcli con show ens33

# 重新啟動 NetworkManager
sudo systemctl restart NetworkManager

路由疑難排解

# 顯示路由表
ip route show

# 顯示前往特定目標的路由
ip route get 8.8.8.8

# 新增暫時性路由
sudo ip route add 10.0.0.0/8 via 192.168.1.1

# 刪除路由
sudo ip route del 10.0.0.0/8

# 使用 nmcli 新增永久路由
sudo nmcli con mod ens33 +ipv4.routes "10.0.0.0/8 192.168.1.1"

常見網路問題

問題狀況 檢查項目
沒有取得 IP 位址 檢查 DHCP 服務、確認 ipv4.method 設定、重新啟用連線
無法 ping 通預設閘道 檢查實體網路線、ip link 介面狀態、防火牆規則
無法 ping 通外部 IP 檢查預設閘道、路由表、防火牆設定
無法解析網域名稱 檢查 /etc/resolv.conf、DNS 伺服器設定、/etc/hosts

診斷指令

# 顯示 Socket 統計資訊
ss -tuln  # 監聽中的 TCP/UDP 連接埠
ss -ta    # 所有 TCP 連線

# 網路介面統計資訊
ip -s link show ens33  # 介面封包統計資訊

# ARP 表（位址解析快取）
ip neigh show

# 檢查 NetworkManager 服務狀態
systemctl status NetworkManager

# 檢視 NetworkManager 日誌
journalctl -u NetworkManager -n 50

操作步驟：網路疑難排解工作流程

  1. 檢查網路介面狀態： 
    ip link show
nmcli dev status
  2. 檢查 IP 組態設定： 
    ip addr show
nmcli con show ens33
  3. 測試本機連線： 
    ping -c 4 127.0.0.1  # 本機迴環介面 (Loopback)
ping -c 4 $(ip route | grep default | awk '{print $3}')  # 預設閘道
  4. 測試外部網路連線： 
    ping -c 4 8.8.8.8  # Google DNS
  5. 測試 DNS 名稱解析： 
    ping -c 4 google.com
nslookup google.com
  6. 檢查路由路徑： 
    ip route show
tracepath google.com
  7. 檢查系統服務日誌： 
    journalctl -u NetworkManager -n 50

📝 練習題

第 1 題：使用 nmcli 設定靜態 IP 的正確指令為何？

  • A) nmcli con mod ens33 ipv4.method manual ipv4.addresses 192.168.1.100/24
  • B) ip addr add 192.168.1.100/24 dev ens33
  • C) ifconfig ens33 192.168.1.100 netmask 255.255.255.0
  • D) B 與 C 皆可
解答：A)
在 RHEL 9 中，nmcli 是建立永久網路設定的標準方式。設定靜態 IP 時必須將 ipv4.method 設為 "manual"。指令 B 與 C 僅為暫時性設定（重開機後會失效）。 修改完成後別忘了執行 nmcli con up ens33 以套用變更。

第 2 題：如何永久設定系統的主機名稱？

  • A) hostname server1.example.com
  • B) hostnamectl set-hostname server1.example.com
  • C) echo "server1" > /etc/hostname
  • D) B 與 C 皆可
解答：D) B 與 C 皆可
hostnamectl set-hostname 是最推薦的方法（會同步更新相關設定檔並立即生效）。 直接編輯 /etc/hostname 也能永久生效，但需要重新開機或重新載入 hostnamectl。 指令 A 僅會暫時變更主機名稱（重開機後失效）。

第 3 題：哪一個檔案包含 DNS 伺服器的設定？

  • A) /etc/resolv.conf
  • B) /etc/hosts
  • C) /etc/nsswitch.conf
  • D) /etc/sysconfig/network
解答：A) /etc/resolv.conf
/etc/resolv.conf 包含 nameserver 設定項目（在 RHEL 9 中由 NetworkManager 管理）。 /etc/hosts 用於靜態主機名稱與 IP 對應；/etc/nsswitch.conf 定義名稱解析的順序。 請勿手動編輯 /etc/resolv.conf，應改用 nmcli 進行設定。

第 4 題：哪個指令可以顯示目前作用中的網路連線？

  • A) nmcli connection show
  • B) nmcli con show --active
  • C) nmcli dev status
  • D) 以上皆是
解答：D) 以上皆是
這三個指令都能檢視作用中的連線或裝置狀態。nmcli con show 會列出所有連線（作用中的會以醒目顏色標示）； nmcli con show --active 只過濾出作用中的連線；nmcli dev status 則顯示網路裝置的狀態。 撰寫自動化腳本時可搭配 nmcli -t -f 使用。

第 5 題：如何在現有連線組態中新增第二組 DNS 伺服器？

  • A) nmcli con mod ens33 ipv4.dns 8.8.4.4
  • B) nmcli con mod ens33 +ipv4.dns 8.8.4.4
  • C) echo "nameserver 8.8.4.4" >> /etc/resolv.conf
  • D) nmcli con add dns 8.8.4.4
解答：B) nmcli con mod ens33 +ipv4.dns 8.8.4.4
使用 + 前綴會在現有值後方新增項目。若未加上 +，將會覆蓋並取代原本所有的 DNS 伺服器。 使用 - 則可移除指定的 DNS 伺服器。請勿手動修改 /etc/resolv.conf，因為 NetworkManager 會覆寫它。

第 6 題：進行網路疑難排解的第一個步驟為何？

  • A) Ping google.com
  • B) 使用 ip link show 檢查網路介面連線狀態
  • C) 重新啟動 NetworkManager
  • D) 檢查 /etc/resolv.conf
解答：B) 使用 ip link show 檢查網路介面連線狀態
應從底層開始檢查：先確認介面是否為 UP 狀態，接著檢查 IP 位址（ip addr），再測試預設閘道（ping），最後檢查 DNS 解析。 依循 OSI 模型由下而上的原則排查：實體層 → 資料連結層 → 網路層 → 應用層。 也可使用 nmcli dev status 快速掌握整體概況。
