管理網路安全性 (Firewalld)

精通使用 firewalld 進行防火牆組態設定。學習如何管理區域（Zones）、服務、連接埠與進階規則（Rich Rules） 以強化網路安全性，並掌握永久規則與執行時期規則的設定差異。

🎯 Firewalld 簡介

Firewalld 是 RHEL 9 預設的動態防火牆管理服務。它採用「區域（Zones）」的概念來定義不同的信任等級， 並且能夠在不中斷現有連線、不重新啟動服務的情況下動態套用防火牆規則。

Firewalld 核心元件

元件 說明
firewalld 動態防火牆背景守護程式（Daemon）
firewall-cmd 命令列管理工具
Zones（區域） 依信任等級劃分的規則容器
Services（服務） 預先定義好的連接埠與通訊協定組合

管理 Firewalld 服務

# 啟動 firewalld 服務
sudo systemctl start firewalld

# 設定開機自動啟動並立即啟動
sudo systemctl enable --now firewalld

# 檢查服務與防火牆狀態
sudo systemctl status firewalld
sudo firewall-cmd --state

# 重新載入防火牆（套用永久規則）
sudo firewall-cmd --reload

# 停止 firewalld（在正式環境中極度危險！）
sudo systemctl stop firewalld

執行時期（Runtime）規則 vs 永久（Permanent）規則

類型 說明 指令格式
執行時期（Runtime） 立即生效，但重新載入或重開機後即失效 firewall-cmd（不加選項）
永久（Permanent） 永久儲存至設定檔，需執行 reload 後才會生效 firewall-cmd --permanent
💡 提示：最佳實踐

務必確保規則同時套用於執行時期與永久設定，或先使用 --permanent 新增規則後再執行 --reload：
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --reload

🛡️ 防火牆區域 (Zones)

區域（Zones）用來定義不同網路連線的信任等級，每個網路介面都會被指派給一個區域。

預定義區域

區域名稱 信任等級 預設行為
drop 無 直接丟棄所有傳入封包，不給予任何回應
block 無 拒絕所有傳入連線（會回傳 ICMP 拒絕訊息）
public 低 預設區域，僅允許 SSH 與 cockpit
external 低 適用於啟用 IP 偽裝（NAT）的外部網路
work 中 信任工作場所中的同事電腦
home 中高 信任居家網路環境
internal 高 適用於內部區域網路
trusted 完全信任 允許所有網路流量通過

管理區域

# 列出所有可用區域
sudo firewall-cmd --get-zones

# 顯示目前的預設區域
sudo firewall-cmd --get-default-zone

# 設定預設區域
sudo firewall-cmd --set-default-zone=public

# 顯示目前作用中的區域（含指派的介面與來源）
sudo firewall-cmd --get-active-zones

# 顯示指定區域的所有設定
sudo firewall-cmd --zone=public --list-all

# 顯示所有區域的詳細設定
sudo firewall-cmd --list-all-zones

將網路介面指派至區域

# 變更網路介面所屬區域（僅執行時期有效）
sudo firewall-cmd --zone=work --change-interface=ens33

# 永久變更介面所屬區域
sudo firewall-cmd --permanent --zone=work --change-interface=ens33
sudo firewall-cmd --reload

# 或直接使用 nmcli 設定連線所屬區域
sudo nmcli con mod ens33 connection.zone work
sudo nmcli con up ens33

# 查詢特定介面目前所在的區域
sudo firewall-cmd --get-zone-of-interface=ens33

🔧 管理服務

服務（Services）是針對常見應用程式預先定義好的連接埠與通訊協定組合。

列出服務

# 列出所有支援的預定義服務
sudo firewall-cmd --get-services

# 列出預設區域中已允許的服務
sudo firewall-cmd --list-services

# 列出特定區域中已允許的服務
sudo firewall-cmd --zone=public --list-services

# 顯示特定服務的詳細定義（連接埠與協定）
sudo firewall-cmd --info-service=http
sudo firewall-cmd --info-service=ssh

新增與移除服務

# 新增服務（僅執行時期有效）
sudo firewall-cmd --add-service=http

# 新增服務（永久設定，需重新載入生效）
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --reload

# 將服務新增至特定區域
sudo firewall-cmd --zone=public --add-service=https

# 一次新增多個服務
sudo firewall-cmd --permanent --add-service={http,https,smtp}
sudo firewall-cmd --reload

# 移除服務
sudo firewall-cmd --remove-service=http
sudo firewall-cmd --permanent --remove-service=http
sudo firewall-cmd --reload

常見服務對照表

服務名稱 連接埠 通訊協定
ssh 22 TCP
http 80 TCP
https 443 TCP
nfs 2049 TCP
mysql 3306 TCP
smtp 25 TCP

操作步驟：開放 HTTP/HTTPS 網路流量

  1. 檢查目前允許的服務： 
    sudo firewall-cmd --list-services
  2. 永久新增 HTTP 與 HTTPS 服務： 
    sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-service=https
  3. 重新載入防火牆： 
    sudo firewall-cmd --reload
  4. 驗證設定結果： 
    sudo firewall-cmd --list-services
  5. 測試服務連線存取： 
    curl http://localhost
curl https://localhost

🔌 管理連接埠

對於自訂應用程式或非標準連接埠，可以直接針對個別連接埠進行開放或關閉管理。

新增與移除連接埠

# 新增連接埠（執行時期）
sudo firewall-cmd --add-port=8080/tcp

# 新增連接埠（永久設定）
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload

# 一次新增多個連接埠
sudo firewall-cmd --permanent --add-port={8080/tcp,8443/tcp,3000/tcp}
sudo firewall-cmd --reload

# 新增連續的連接埠範圍
sudo firewall-cmd --permanent --add-port=5000-5010/tcp
sudo firewall-cmd --reload

# 新增 UDP 連接埠
sudo firewall-cmd --permanent --add-port=53/udp
sudo firewall-cmd --reload

# 移除連接埠
sudo firewall-cmd --remove-port=8080/tcp
sudo firewall-cmd --permanent --remove-port=8080/tcp
sudo firewall-cmd --reload

列出已開放的連接埠

# 列出預設區域中開放的連接埠
sudo firewall-cmd --list-ports

# 列出指定區域中開放的連接埠
sudo firewall-cmd --zone=public --list-ports

# 顯示所有規則（包含服務與連接埠）
sudo firewall-cmd --list-all

管理方式比較：Port vs Service

方式 適用時機
服務（Service） 標準系統服務（http、ssh、nfs 等）—— 設定簡潔且易於識別管理
連接埠（Port） 自訂應用程式或非標準連接埠（8080、3000 等）

操作步驟：開放自訂應用程式連接埠

  1. 確認應用程式所需的連接埠（例如執行於 3000 埠的 Node.js）： 
    ss -tulpn | grep 3000
  2. 永久新增該連接埠規則： 
    sudo firewall-cmd --permanent --add-port=3000/tcp
  3. 重新載入防火牆： 
    sudo firewall-cmd --reload
  4. 驗證連接埠已開放： 
    sudo firewall-cmd --list-ports
  5. 從其他機器進行連線測試： 
    telnet server-ip 3000
# 或
curl http://server-ip:3000

📜 進階規則 (Rich Rules)

Rich Rules（進階規則）提供更精細的防火牆控制能力，包含來源 IP 過濾、日誌記錄（Logging）、連線速率限制與複雜條件設定。

Rich Rule 語法

# 基本格式：
rule family="ipv4" source address="IP/MASK" [service|port] [accept|reject|drop]

# 範例：僅允許來自特定 IP 的 SSH 連線
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="192.168.1.100" service name="ssh" accept'

# 重新載入生效
sudo firewall-cmd --reload

Rich Rules 實用範例

# 允許來自特定子網路的 HTTP 連線
sudo firewall-cmd --permanent --add-rich-rule='
  rule family="ipv4"
  source address="192.168.1.0/24"
  service name="http"
  accept'

# 封鎖特定來源 IP
sudo firewall-cmd --permanent --add-rich-rule='
  rule family="ipv4"
  source address="10.0.0.50"
  reject'

# 允許特定 IP 存取連接埠並記錄日誌
sudo firewall-cmd --permanent --add-rich-rule='
  rule family="ipv4"
  source address="192.168.1.10"
  port port="3306" protocol="tcp"
  log prefix="MySQL Access: " level="info"
  accept'

# 限制 SSH 連線速率（防止暴力破解）
sudo firewall-cmd --permanent --add-rich-rule='
  rule service name="ssh"
  limit value="5/m"
  accept'

# 連接埠轉發（Port Forwarding）
sudo firewall-cmd --permanent --add-rich-rule='
  rule family="ipv4"
  forward-port port="8080" protocol="tcp" to-port="80"'

管理 Rich Rules

# 列出目前的 Rich Rules
sudo firewall-cmd --list-rich-rules

# 列出指定區域中的 Rich Rules
sudo firewall-cmd --zone=public --list-rich-rules

# 移除 Rich Rule
sudo firewall-cmd --permanent --remove-rich-rule='
  rule family="ipv4"
  source address="192.168.1.100"
  service name="ssh"
  accept'

# 變更完成後重新載入
sudo firewall-cmd --reload

來源 IP 區域過濾

# 將來源網段加入指定區域（例如信任特定網段）
sudo firewall-cmd --permanent --zone=trusted --add-source=192.168.1.0/24
sudo firewall-cmd --reload

# 移除來源網段
sudo firewall-cmd --permanent --zone=trusted --remove-source=192.168.1.0/24

# 列出該區域中已加入的來源位址
sudo firewall-cmd --zone=trusted --list-sources
📘 注意：Rich Rules 常見應用場景

• 僅允許來自特定 IP 或子網路存取特定服務
• 封鎖惡意來源 IP
• 記錄特定網路流量的日誌
• 限制連線速率（Rate limiting）
• 設定連接埠轉發（Port forwarding）
• 設定基於時間條件的進階規則

📝 練習題

第 1 題：如何讓防火牆規則永久生效？

  • A) 加上 --permanent 參數後執行 --reload
  • B) 規則預設即為永久生效
  • C) 執行 firewall-cmd --save
  • D) 重新啟動 firewalld 服務
解答：A) 加上 --permanent 參數後執行 --reload
先執行 sudo firewall-cmd --permanent --add-service=http，再執行 sudo firewall-cmd --reload。若未加上 --permanent，規則僅於執行時期生效 （在 reload 或重開機後就會消失）；執行 reload 則會將永久設定載入套用。

第 2 題：RHEL 9 的預設防火牆區域（Zone）為何？

  • A) trusted
  • B) home
  • C) public
  • D) work
解答：C) public
public 為預設區域，預設情況下僅開放 SSH 與 cockpit 服務。 可使用 firewall-cmd --get-default-zone 查看預設區域，或透過 firewall-cmd --set-default-zone=home 進行修改。

第 3 題：哪個指令可以永久開放 HTTP 與 HTTPS 服務？

  • A) firewall-cmd --add-service=http,https
  • B) firewall-cmd --permanent --add-service={http,https}
  • C) firewall-cmd --add-port=80,443/tcp
  • D) firewall-cmd --open http https
解答：B)
執行 sudo firewall-cmd --permanent --add-service={http,https} 後，再執行 sudo firewall-cmd --reload。大括號語法可一次指定多個服務。 對於標準應用程式，建議優先使用服務名稱而非連接埠號。

第 4 題：如何永久開放自訂連接埠 8080/tcp？

  • A) firewall-cmd --permanent --add-port=8080/tcp
  • B) firewall-cmd --permanent --add-service=8080
  • C) firewall-cmd --permanent --open-port=8080
  • D) firewall-cmd --port 8080 --allow
解答：A)
執行 sudo firewall-cmd --permanent --add-port=8080/tcp 後，再執行 sudo firewall-cmd --reload。開放連接埠時必須指定通訊協定（tcp 或 udp）。 自訂連接埠請使用 --add-port，預定義服務則使用 --add-service。

第 5 題：哪一個區域預設會允許「所有」網路流量通過？

  • A) public
  • B) home
  • C) trusted
  • D) internal
解答：C) trusted
trusted 區域會放行所有流量，請謹慎使用！可將受信任的 IP 指派至該區域： firewall-cmd --permanent --zone=trusted --add-source=192.168.1.10。 drop 區域最嚴格（阻擋一切），而 trusted 則是最寬鬆（允許一切）。

第 6 題：哪一項是僅允許 192.168.1.100 連線至 SSH 的正確 Rich Rule 語法？

  • A) --add-rich-rule='rule source address="192.168.1.100" service="ssh" accept'
  • B) --add-rich-rule='rule family="ipv4" source address="192.168.1.100" service name="ssh" accept'
  • C) --add-source=192.168.1.100 --add-service=ssh
  • D) B 與 C 皆可
解答：B)
正確語法為：sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="192.168.1.100" service name="ssh" accept'。必須完整指定 family 與 service name="..." 語法。選項 C 的作法會對整個區域套用設定，而非僅針對該 IP 限定 SSH 存取。
