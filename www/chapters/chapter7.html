排程未來任務

使用 cron、anacron、at 與 systemd 計時器（Timer）來自動化系統任務。 掌握定期維護、備份、監控以及一次性任務執行的排程管理技巧。

📋 本章目錄

  • 簡介
  • Cron 與 Crontab
  • Systemd 計時器
  • At 與 Batch 指令
  • Anacron
  • 練習題

🎯 簡介

任務排程是系統管理不可或缺的一環。Linux 提供了多種工具，讓系統能在指定時間或週期自動執行任務—— 從簡單的定期作業（如備份、日誌輪替）到複雜的維護排程皆可勝任。熟練這些工具能確保系統在無需人工介入的情況下平穩運作。

在本章中，你將掌握：

  • 使用 Cron 執行週期性排程任務
  • 將 Systemd 計時器作為 Cron 的現代化替代方案
  • 使用 At 執行一次性未來任務
  • 針對非 24 小時開機的系統使用 Anacron
  • 設定工作排程的使用者存取控制

排程工具比較

工具 類型 最適用情境
cron 週期性 固定時間間隔任務（每日備份、每小時檢查）
systemd timers 週期性 現代化系統環境，支援整合日誌與服務相依性
at 一次性 單次未來執行（例如凌晨 2 點重開機、週五產生報表）
anacron 週期性 桌上型電腦 / 筆電（非 24 小時持續開機的設備）
📘 注意

在 RHEL 9 上，新建立的任務越來越傾向優先使用 systemd 計時器而非 cron， 但 cron 依然在實務中被廣泛使用，也是 RHCSA 考試的重點之一。

⏰ Cron 與 Crontab

Cron 是傳統的 Unix 工作排程器，可在指定的時間與日期自動執行指令。 Cron 背景服務（crond）每分鐘都會檢查 crontab 檔案並執行符合時間條件的排程工作。

Crontab 語法

每筆 crontab 排程記錄包含六個欄位：

# ┌───────────── 分鐘 (0-59)
# │ ┌───────────── 小時 (0-23)
# │ │ ┌───────────── 日期 (1-31)
# │ │ │ ┌───────────── 月份 (1-12)
# │ │ │ │ ┌───────────── 星期 (0-6，週日=0)
# │ │ │ │ │
# │ │ │ │ │
# * * * * * 要執行的指令

特殊字元

字元 意義 範例
* 任意值（每個單位） * * * * * = 每分鐘執行一次
, 列舉多個指定值 0 9,17 * * * = 每天上午 9 點與下午 5 點
- 連續範圍 0 9-17 * * * = 上午 9 點到下午 5 點的每個整點
/ 間隔步進值 */15 * * * * = 每 15 分鐘執行一次

常見 Crontab 範例

# 每分鐘執行
* * * * * /path/to/command

# 每天凌晨 3:30 執行
30 3 * * * /usr/local/bin/backup.sh

# 每小時整點（第 0 分）執行
0 * * * * /usr/bin/check-status.sh

# 平日（週一至週五）下午 2:15 執行
15 14 * * 1-5 /usr/bin/report.sh

# 每月 1 日與 15 日午夜 00:00 執行
0 0 1,15 * * /usr/local/bin/billing.sh

# 每 15 分鐘執行一次
*/15 * * * * /usr/bin/monitor.sh

# 每週日晚上 11:45 執行
45 23 * * 0 /usr/local/bin/weekly-cleanup.sh

# 每 6 小時執行一次
0 */6 * * * /usr/bin/sync-data.sh

# 每年 1 月 1 日午夜執行
0 0 1 1 * /usr/local/bin/new-year-task.sh

# 週一至週五上午 9:00 執行
0 9 * * 1-5 /usr/local/bin/workday-start.sh

管理使用者 Crontab

# 編輯自己的 crontab
crontab -e

# 列出自己的 crontab 內容
crontab -l

# 移除自己的 crontab（直接刪除）
crontab -r

# 移除自己的 crontab（刪除前詢問確認）
crontab -r -i

# 編輯其他使用者的 crontab（需 root 權限）
sudo crontab -u username -e

# 列出其他使用者的 crontab
sudo crontab -u username -l

系統 Crontab

系統層級的 cron 排程工作分別儲存在以下位置：

# 系統主 crontab（包含指定執行使用者的欄位）
/etc/crontab

# /etc/crontab 內容範例：
SHELL=/bin/bash
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MAILTO=root
HOME=/

# 分 時 日 月 週 使用者 指令
0 2 * * * root /usr/local/bin/daily-maintenance.sh

# 腳本置放目錄（Drop-in directories）
/etc/cron.hourly/    # 每小時執行
/etc/cron.daily/     # 每天執行一次
/etc/cron.weekly/    # 每週執行一次
/etc/cron.monthly/   # 每月執行一次

# 額外的系統 cron 排程設定檔目錄
/etc/cron.d/         # 放置額外的 crontab 設定檔

# 範例：將腳本加入每日排程
sudo cp script.sh /etc/cron.daily/
sudo chmod +x /etc/cron.daily/script.sh

Cron 環境變數

可在 crontab 檔案頂端設定環境變數：

# 設定使用的 Shell
SHELL=/bin/bash

# 設定 PATH 搜尋路徑
PATH=/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin

# 將輸出結果寄信給指定使用者
MAILTO=admin@example.com

# 停用郵件通知
MAILTO=""

# 設定 HOME 目錄
HOME=/home/student

# 以下放置你的 cron 排程工作
0 2 * * * /usr/local/bin/backup.sh

重新導向 Cron 輸出

# 丟棄所有輸出（標準輸出與錯誤輸出）
0 2 * * * /usr/local/bin/quiet-task.sh > /dev/null 2>&1

# 將輸出附加寫入日誌檔
0 2 * * * /usr/local/bin/backup.sh >> /var/log/backup.log 2>&1

# 僅寄送錯誤輸出（標準輸出丟棄）
0 2 * * * /usr/local/bin/task.sh > /dev/null

# 將標準輸出與錯誤輸出分別寫入不同檔案
0 2 * * * /usr/local/bin/task.sh >> /var/log/task.log 2>> /var/log/task-error.log

操作步驟：建立每日備份 Cron 工作

  1. 建立備份腳本： 
    sudo vi /usr/local/bin/daily-backup.sh

#!/bin/bash
# Daily backup script
DATE=$(date +%Y%m%d)
tar -czf /backups/home-$DATE.tar.gz /home
find /backups -name "home-*.tar.gz" -mtime +7 -delete

# 賦予可執行權限
sudo chmod +x /usr/local/bin/daily-backup.sh
  2. 手動測試腳本是否正常運作： 
    sudo /usr/local/bin/daily-backup.sh
  3. 編輯 crontab： 
    sudo crontab -e
  4. 新增 cron 排程（每天凌晨 2 點執行）： 
    # 每天凌晨 2 點執行備份
0 2 * * * /usr/local/bin/daily-backup.sh >> /var/log/backup.log 2>&1
  5. 驗證 crontab 設定： 
    sudo crontab -l
  6. 確認 cron 服務正在運行： 
    sudo systemctl status crond

Cron 存取控制

控管哪些使用者可以使用 cron：

# 透過白名單或黑名單控管使用者權限
/etc/cron.allow    # 若檔案存在，僅列於其中的使用者可使用 cron
/etc/cron.deny     # 若檔案存在，列於其中的使用者禁止使用 cron

# 範例：僅允許 student 與 admin 使用 cron
echo "student" | sudo tee /etc/cron.allow
echo "admin" | sudo tee -a /etc/cron.allow

# 範例：禁止特定使用者使用 cron
echo "baduser" | sudo tee /etc/cron.deny

# 若兩個檔案皆不存在，預設僅有 root 可使用 cron（RHEL 預設）
# 若兩個檔案同時存在，以 cron.allow 優先
💡 提示：Cron 最佳實務
  • 在 cron 排程中務必使用絕對路徑
  • 加入 crontab 前請先手動測試腳本執行無誤
  • 適當地重新導向輸出或設定 MAILTO，避免產生大量通知郵件
  • 在 crontab 中加上清楚易懂的註解
  • 對於較複雜的排程需求，建議改用 systemd 計時器

⏲️ Systemd 計時器

Systemd 計時器（Timers）是取代 cron 的現代化排程機制。它能與 systemd 服務緊密整合， 提供更完整的日誌記錄、支援服務相依性，並具備更彈性的排程選項。

為什麼使用 Systemd 計時器？

  • 深度整合： 可直接搭配 systemd 服務單元與相依性設定運作
  • 日誌追蹤： 完整整合 journald 日誌系統，便於除錯與檢視紀錄
  • 高度彈性： 支援開機後觸發、相對於其他單元觸發，以及隨機延遲功能
  • 資源控管： 可套用 systemd 資源使用限制
  • 精準度高： 針對時間敏感的任務提供更佳的觸發精確度

計時器組成元件

一個 systemd 計時器需要兩個單元設定檔：

  1. 服務單元（Service unit, .service） - 定義「要執行什麼」
  2. 計時器單元（Timer unit, .timer） - 定義「何時執行」

建立 Systemd 計時器

範例：每日清理計時器

  1. 建立服務單元檔案： 
    sudo vi /etc/systemd/system/cleanup.service

[Unit]
Description=Daily Cleanup Task
Wants=cleanup.timer

[Service]
Type=oneshot
ExecStart=/usr/local/bin/cleanup.sh

[Install]
WantedBy=multi-user.target
  2. 建立計時器單元檔案： 
    sudo vi /etc/systemd/system/cleanup.timer

[Unit]
Description=Daily Cleanup Timer
Requires=cleanup.service

[Timer]
OnCalendar=daily
OnCalendar=*-*-* 02:00:00
Persistent=true

[Install]
WantedBy=timers.target
  3. 重新載入 systemd 設定： 
    sudo systemctl daemon-reload
  4. 啟用並立即啟動計時器： 
    sudo systemctl enable cleanup.timer
sudo systemctl start cleanup.timer
  5. 驗證計時器狀態： 
    sudo systemctl status cleanup.timer
sudo systemctl list-timers cleanup.timer

計時器排程語法

OnCalendar 支援多種時間格式：

# 簡易週期關鍵字
OnCalendar=hourly     # 每小時
OnCalendar=daily      # 每天午夜
OnCalendar=weekly     # 每週一午夜
OnCalendar=monthly    # 每月 1 日午夜
OnCalendar=yearly     # 每年 1 月 1 日午夜

# 指定特定時間
OnCalendar=*-*-* 02:30:00           # 每天凌晨 2:30
OnCalendar=Mon *-*-* 09:00:00       # 每週一上午 9:00
OnCalendar=Mon..Fri *-*-* 18:00:00  # 週一至週五下午 6:00

# 多個觸發時間
OnCalendar=*-*-* 06:00:00           # 早上 6:00
OnCalendar=*-*-* 18:00:00           # 晚上 6:00

# 每 15 分鐘執行一次
OnCalendar=*:0/15

# 測試行事曆時間表示式是否正確
systemd-analyze calendar "Mon..Fri *-*-* 09:00:00"

計時器選項

選項 說明
OnCalendar= 依真實行事曆時鐘時間排程
OnBootSec= 系統開機後經過的時間
OnActiveSec= 計時器啟動後經過的時間
OnUnitActiveSec= 對應服務上次執行後經過的時間
Persistent= 若關機錯過執行時間，於下次開機後立即補跑
AccuracySec= 計時器精確度容許窗口（預設為 1 分鐘）
RandomizedDelaySec= 執行前加上隨機延遲時間

管理計時器

# 列出所有啟用中的計時器
systemctl list-timers

# 列出所有計時器（包含未啟用者）
systemctl list-timers --all

# 檢查計時器狀態
systemctl status cleanup.timer

# 檢視計時器詳細屬性
systemctl show cleanup.timer

# 檢查計時器下次執行的時間
systemctl list-timers cleanup.timer

# 手動立即觸發對應的服務
sudo systemctl start cleanup.service

# 檢視服務執行日誌
sudo journalctl -u cleanup.service

# 檢視計時器日誌
sudo journalctl -u cleanup.timer

範例：每小時系統檢查

# /etc/systemd/system/syscheck.service
[Unit]
Description=Hourly System Health Check

[Service]
Type=oneshot
ExecStart=/usr/local/bin/check-system.sh
StandardOutput=journal

# /etc/systemd/system/syscheck.timer
[Unit]
Description=Run system check every hour

[Timer]
OnCalendar=hourly
OnBootSec=5min
AccuracySec=1s

[Install]
WantedBy=timers.target

# 啟用並立即啟動計時器
sudo systemctl daemon-reload
sudo systemctl enable --now syscheck.timer

📅 At 與 Batch 指令

at 指令用於排程在未來特定時間執行的一次性任務。 不同於 cron（週期性重複執行），at 工作在執行一次後就會從排程佇列中移除。

安裝 At

# 安裝 at 套件
sudo dnf install at

# 啟動並設定開機自動啟用 atd 服務
sudo systemctl enable --now atd

# 驗證服務狀態
sudo systemctl status atd

使用 At 排程工作

# 在指定時間執行工作
at 10:00 PM
> /usr/local/bin/backup.sh
> <Ctrl+D>

# 在明天上午 9 點執行工作
at 9am tomorrow
> echo "Daily report" | mail -s "Report" admin@example.com
> <Ctrl+D>

# 在指定日期與時間執行工作
at 2:30 PM December 25
> /usr/local/bin/christmas-task.sh
> <Ctrl+D>

# 在 30 分鐘後執行工作
at now + 30 minutes
> /usr/local/bin/quick-task.sh
> <Ctrl+D>

# 在 2 小時後執行工作
at now + 2 hours
> systemctl restart httpd
> <Ctrl+D>

# 在下週同時間或指定時間執行工作
at 10am next week
> /usr/local/bin/weekly-report.sh
> <Ctrl+D>

# 從檔案讀取要執行的工作內容
at 2am tomorrow -f /usr/local/bin/script.sh

# 使用 Here Document 排程工作
at now + 5 minutes <<EOF
echo "Task started at $(date)" >> /var/log/tasks.log
/usr/local/bin/my-task.sh
echo "Task completed at $(date)" >> /var/log/tasks.log
EOF

At 時間格式說明

格式 範例
HH:MM 14:30, 10:00 PM
midnight, noon, teatime noon tomorrow
now + 時間 now + 30 minutes
today, tomorrow 10am tomorrow
MMDDYY 122524（2024 年 12 月 25 日）

管理 At 工作

# 列出已排程的工作
atq
# 或
at -l

# 輸出範例：
# 1	Thu Nov 14 22:00:00 2025 a student
# 2	Fri Nov 15 09:00:00 2025 a student

# 檢視工作內容
at -c 1    # 顯示編號 1 的工作詳細內容

# 移除指定工作
atrm 1     # 移除編號 1 的工作
# 或
at -d 1

# 移除目前使用者的所有工作
atrm $(atq | cut -f1)

# 移除特定使用者的所有工作（需 root 權限）
sudo atrm $(atq -u username | cut -f1)

Batch 指令

與 at 類似，但僅在系統負載較低時才會執行：

# 當系統平均負載低於 1.5（預設值）時才執行
batch
> /usr/local/bin/resource-intensive-task.sh
> <Ctrl+D>

# batch 工作同樣會出現在 atq 佇列中
atq

At 存取控制

# 控管哪些使用者可以使用 at
/etc/at.allow    # 若檔案存在，僅列於其中的使用者可使用 at
/etc/at.deny     # 若檔案存在，列於其中的使用者禁止使用 at

# 範例：允許特定使用者使用 at
echo "student" | sudo tee /etc/at.allow
echo "admin" | sudo tee -a /etc/at.allow

# 若兩個檔案皆不存在，預設僅有 root 可使用 at

操作步驟：排程系統重新開機

  1. 排程在明天凌晨 2 點重新開機： 
    sudo at 2am tomorrow
at> systemctl reboot
at> <Ctrl+D>
job 3 at Fri Nov 15 02:00:00 2025
  2. 驗證已排程的工作： 
    sudo atq
  3. 檢視工作詳細內容： 
    sudo at -c 3
  4. 若需要取消排程： 
    sudo atrm 3

🔄 Anacron

Anacron 用於定期執行指令，但它不會假設系統一直處於開機狀態。 不同於 cron（關機期間錯過的排程會直接跳過），anacron 能確保錯過的任務在系統開機後補執行——非常適合桌上型電腦與筆記型電腦。

Anacron 與 Cron 比較

特性 Cron Anacron
最小執行間隔 1 分鐘 1 天
錯過的任務 直接略過 於下次開機時補執行
最適用環境 伺服器（24 小時運行） 桌上型電腦 / 筆電

Anacron 設定

主要設定檔為：/etc/anacrontab

# /etc/anacrontab 範例
SHELL=/bin/sh
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MAILTO=root
RANDOM_DELAY=45        # 最大隨機延遲分鐘數
START_HOURS_RANGE=3-22 # 僅於凌晨 3 點至晚上 10 點之間執行

# 週期    延遲    工作識別名稱     指令
1         5      cron.daily      nice run-parts /etc/cron.daily
7         25     cron.weekly     nice run-parts /etc/cron.weekly
@monthly  45     cron.monthly    nice run-parts /etc/cron.monthly

# 欄位格式說明：
# period     = 兩次執行之間的間隔天數
# delay      = 執行前需等待的延遲分鐘數
# identifier = 唯一的工作識別名稱
# command    = 要執行的指令

Anacron 運作原理

  1. Anacron 會檢查位於 /var/spool/anacron/ 的時間戳記檔案
  2. 若某項工作在指定週期內尚未執行過，便會將其排入執行
  3. 工作會先等待設定的延遲時間（delay），再開始執行
  4. 成功執行完成後，系統會更新對應的時間戳記檔案

管理 Anacron

# 手動執行 anacron（檢查所有工作）
sudo anacron

# 立即強制執行所有工作（忽略時間戳記）
sudo anacron -f

# 僅強制執行特定工作
sudo anacron -f cron.daily

# 測試模式（在前景測試而不實際在背景執行）
sudo anacron -d -n

# 僅更新時間戳記而不實際執行工作
sudo anacron -u

# 檢查時間戳記檔案
ls -l /var/spool/anacron/
📘 注意：Anacron 整合機制

在 RHEL 系統上，anacron 已與 cron 整合。cron.daily、cron.weekly 與 cron.monthly 目錄中的腳本實際上是由 anacron 負責管理，以確保即使系統曾經關機，這些維護工作仍會確實執行。

📝 練習題

第 1 題：這筆 crontab 設定代表何種執行時間？ 30 2 * * 1-5

  • A) 週末凌晨 2:30 執行
  • B) 平日（週一至週五）凌晨 2:30 執行
  • C) 凌晨 2 點至 5 點之間每 30 分鐘執行一次
  • D) 每月 30 日凌晨 2 點執行
解答：B) 平日（週一至週五）凌晨 2:30 執行
Crontab 欄位格式為：分鐘(30) 小時(2) 日(*) 月(*) 星期(1-5 = 週一至週五)。 因此此排程會在週一到週五的凌晨 2:30 執行。

第 2 題：如何排程一個在 4 小時後執行一次性的任務？

  • A) 使用 crontab -e 新增工作
  • B) at now + 4 hours
  • C) systemctl start task.timer
  • D) anacron -t 4h
解答：B) at now + 4 hours
at 指令專用於一次性的未來任務執行。用法：輸入 at now + 4 hours， 接著輸入要執行的指令，最後按下 Ctrl+D 完成排程。cron 則是用於週期性重複任務。

第 3 題：哪個檔案用來控管哪些使用者可以建立 cron 排程工作？

  • A) /etc/cron.access
  • B) /etc/cron.allow 或 /etc/cron.deny
  • C) /etc/crontab
  • D) ~/.cron.conf
解答：B) /etc/cron.allow 或 /etc/cron.deny
若 /etc/cron.allow 存在，僅清單中的使用者可使用 cron；若 /etc/cron.deny 存在， 則清單中的使用者無法使用 cron；若兩者皆不存在，僅 root 可使用 cron。

第 4 題：哪個指令可以列出所有等待執行的 at 工作？

  • A) at -l 或 atq
  • B) crontab -l
  • C) systemctl list-timers
  • D) at --list
解答：A) at -l 或 atq
at -l 與 atq 皆可用來列出已排程的 at 工作；若要移除工作請使用 atrm 工作編號。 crontab -l 列出的是 cron 排程，而非 at 工作。

第 5 題：相較於 cron，systemd 計時器有什麼主要優勢？

  • A) 語法比較簡短
  • B) 能與 journald 日誌系統及 systemd 服務深度整合
  • C) 可以設定更高的執行頻率
  • D) 不需要系統管理員權限即可管理系統任務
解答：B) 能與 journald 日誌系統及 systemd 服務深度整合
Systemd 計時器會將日誌整合至 journald、支援服務相依性管理、提供更彈性的排程選項（如 OnBootSec、Persistent 等）， 是 RHEL 9 上建議採用的現代化排程方式。
